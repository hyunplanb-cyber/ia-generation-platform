# 뷰티샵 예약 플랫폼 — 완성 화면

`_판매팩/뷰티샵_프리미엄/` 의 파일 세 개를 그대로 읽어 만든 정적 사이트입니다.

| 넣은 파일 | 무엇을 정했나 |
|---|---|
| `07_AI빌드_스펙팩.json` | 화면 136개의 구성·기능·화면 이동 |
| `디자인프리셋/가이드_01_코럴선셋.json` | 색 · 글꼴 · 모서리 · 간격 · 컴포넌트 규칙 |
| `디자인프리셋/레이아웃_A_사진중심형.json` | 화면 뼈대 (히어로 · 목록 · 내비 · 상세) |

빌드 도구·프레임워크·외부 CDN 없이 HTML·CSS·바닐라 JS만 씁니다.

## 바로 보기

- 전체 화면 목록: `index.html` (더블클릭)
- 고객 홈: `pages/HO0101.html` · 매장 홈: `pages/PT0101.html`
- 로컬 서버로 보기(권장):

```bash
node build/serve.mjs
```

→ http://localhost:4173 (포트를 바꾸려면 `PORT=4175 node build/serve.mjs`)

- **기본 화면**(`…01`)은 스펙팩의 화면 프롬프트를 그대로 구현했습니다.
- **상태·세부 화면**(`…02` 이상)은 스펙팩 지침대로 *상위 화면의 레이아웃·컴포넌트·톤을 유지한 채 해당 상태만 바뀐 모습*으로 만들었습니다.
  (예: `RE0405` 결제 처리 중 = 결제 화면 + 진행 오버레이, `SE0104` = 매장 목록 + 스켈레톤)
- 상태 화면 위쪽에는 어떤 상태인지 알려주는 노란 띠가 있고, 모든 화면 우하단 **화면 정보** 버튼을 누르면
  pageId · 화면명 · 기능정의 · 연결 화면을 볼 수 있습니다.
- 고객 화면과 매장(사장님) 화면은 헤더가 다릅니다. 매장 화면은 로고 옆에 `매장` 배지가 붙습니다.

## 가이드 프리셋 01 — 코럴 선셋

`assets/css/base.css` 의 `:root` 에 프리셋 값을 토큰으로 그대로 넣었습니다.

- 색: primary `#F0654F` / hover `#D9503B` / accent `#F59E0B` / bg `#FFF6F3` / surface `#FFFFFF` / text `#33221E` / muted `#7A6560` / border `#F2E2DD` / success `#0F7A52` / warning `#B45309` / danger `#C0392B`
- 글꼴: Pretendard (폴백 Paperlogy) · 페이지 제목 36/800 · 섹션 24/700 · 카드 18/700 · 본문 15/500 · 보조 14/400 · 표 헤더 13/700
- 모서리: 카드 16 / 버튼·입력 12 / 배지 알약 · 간격 4px 배수(카드 내부 24, 섹션 40)
- 그림자: `0 2px 8px rgba(51,34,30,.07)` — 카드와 떠 있는 요소에만
- 컴포넌트: 주요 버튼 높이 44·굵기 700 / 보조 버튼은 primary 10% 배경에 테두리 없음 / 입력 높이 44·배경 `#FFF9F7`·포커스 시 primary 2px / 표 헤더는 배경색 채움·행 높이 48 / 사이드바 활성 항목은 primary 10% + radius 12
- 강조 문구는 accent 형광펜(`.hl`), 지표 숫자는 40px/800 primary — 프리셋의 화면별 지침을 따랐습니다.

## 레이아웃 프리셋 A — 사진 중심형

| 자리 | 어떻게 했나 |
|---|---|
| 첫 화면 위쪽 | 검색바 없이 사진 모자이크(큰 1장 + 작은 4장). 문구와 검색바는 사진 **아래**에 겹치지 않게 |
| 목록 화면 | 매거진형 2열. 큰 이미지 위에 매장명·태그를 얹고 설명은 두 줄로 자름 |
| 내비게이션 | 상단 가로 GNB + 그 아래 시술 카테고리 줄 (2단 헤더) |
| 상세 화면 | 상단 전체 폭 갤러리 → 아래 정보. 예약 버튼은 하단 고정 바 |

> **스펙팩과 레이아웃이 부딪힌 곳** — 스펙팩 `HO0101` 프롬프트는 "히어로에 통합 검색바"를,
> 레이아웃 A는 "히어로에 검색바 없이 사진 모자이크"를 지시합니다.
> 레이아웃 프리셋이 *"뼈대는 이 규칙을 우선해줘"* 라고 못 박고 있어 **뼈대는 A를 따르고**,
> 스펙팩이 요구한 지역·시술 통합 검색 기능은 사진 아래 첫 자리에 두어 둘 다 만족시켰습니다.
> 매장 목록(`SE0101`)도 같은 이유로 좌측 필터 사이드바(스펙팩) + 매거진 2열 카드(레이아웃 A)로 합쳤습니다.
>
> **색이 부딪힌 곳** — 스펙팩의 `designConcept` 과 몇몇 프롬프트는 "딥 플럼(`#7A3B5D`)으로 강조"를 지시하지만,
> 색·글꼴은 가이드 프리셋을 따르는 것이 프리셋 체계의 전제이므로 **강조색은 모두 코럴(`#F0654F`)로 통일**했습니다.
> (D-day 배지, 적립금 숫자, 대시보드 지표 등 "강조하라"고 한 자리는 그대로 강조하되 색만 프리셋 값으로 바꿨습니다.)
> 가이드 02·03으로 바꾸면 같은 자리가 그 프리셋 색으로 바뀝니다.

## 사진 자리 규칙

스펙팩 `imagePlaceholder` 규칙을 그대로 지켰습니다. 실제 사진을 넣기 전까지 이 상태를 유지하세요.

- 테마 색으로 칠하지 않고 **옅은 파스텔 한 톤 + 1px 테두리**(`#EEF2F7` 계열 5종 / 테두리 `#E3E8F0` / 글자 `#8B94A6`)
- 자리 안에 **무엇이 들어갈 사진인지와 권장 크기**를 적음 — `이미지 영역 (매장 대표 · 권장 1200×900)`
- **적어 둔 크기의 비율을 실제로 지킴** — `aspect-ratio` 로 고정하고, `build/qa.html` 이 전 화면에서 이를 검사합니다
- 프로필·썸네일처럼 크기가 고정된 자리는 `flex:none` + 명시 width/height 로, 가로로 나란히 놓아도 늘어나지 않습니다

실제 사진으로 바꿀 때는 `build/ui.mjs` 의 `ph()` · `phFix()` 두 함수만 고치면 전 화면에 반영됩니다.

## 파일 구조

```
뷰티샵_예약_완성화면/
├─ index.html              전체 화면 목록 + 프리셋 색상표
├─ pages/                  화면 136개 (HO0101.html … AU0501.html)
├─ assets/
│  ├─ css/base.css         디자인 토큰 + 전체 컴포넌트
│  └─ js/app.js            탭·아코디언·칩·별점·슬롯·토스트·모달·카운트다운
├─ 스펙팩/                  넣은 원본 3개 (스펙팩 · 가이드 01 · 레이아웃 A)
└─ build/
   ├─ generate.mjs         스펙팩을 읽어 136개 HTML 생성
   ├─ data.mjs             샘플 데이터(매장·디자이너·시술·예약·리뷰·정산 등)
   ├─ ui.mjs               공통 컴포넌트와 페이지 셸(2단 헤더·푸터)
   ├─ pages-*.mjs          메뉴별 화면 빌더 (기본 화면 49개 + 상태 분기)
   ├─ serve.mjs            로컬 미리보기 서버
   ├─ qa.html              전체 화면 자동 점검(가로 스크롤·끊어진 링크·사진 비율)
   └─ pageids.json         qa.html 이 읽는 화면 목록
```

## 다시 생성하기

화면 내용을 고치려면 `build/pages-*.mjs` 를 고친 뒤:

```bash
node build/generate.mjs
```

`pages/` 아래 136개 파일과 `index.html` 이 다시 만들어집니다.
디자인만 바꿀 때는 `assets/css/base.css` 만 고치면 되고 재생성이 필요 없습니다.

프리셋을 다른 조합으로 바꿔보려면 `스펙팩/` 안의 가이드·레이아웃 JSON을 다른 벌로 바꾸고
`base.css` 의 `:root` 토큰과 뼈대 규칙을 그 값으로 맞추면 됩니다.

## 자동 점검

```bash
node build/serve.mjs
```

를 띄운 뒤 http://localhost:4173/build/qa.html 을 엽니다.
136개 화면을 1280 / 768 / 390px 폭에서 차례로 열어 가로 스크롤, 끊어진 링크,
`undefined` 문자열, **사진 자리 비율 어긋남**을 찾아 표로 보여줍니다. (약 3분)

## 참고 사항

- 반응형: 1024px 이하에서 사이드·2단 레이아웃이 접히고, 720px 이하에서 매거진 2열이 1열로 바뀝니다.
  매장 상세·시술 상세·예약 단계는 하단 고정 액션 바가 항상 보입니다.
- 폼 전송·결제·저장은 동작하지 않고 안내 토스트만 띄웁니다(검토용 프로토타입).
- 로그인·결제·지도·알림·사진 업로드·예약 충돌 처리는 바깥 서비스를 불러야 하는 기능이라
  화면만 있고 실제로 동작하지 않습니다. 개발자에게 넘길 항목은 판매팩 `README.txt` 에 정리돼 있습니다.
- 데이터는 모두 가상입니다. 회사·연락처·주소·계좌 정보는 예시값입니다.
