# 검수 결과는 «팩 하나씩» 흘려보낸다

2026-08-19 에 사장님이 정하신 규칙이다.

## 왜 바꾸나

전에는 **다 모아서 한꺼번에** 넘겼다. 그래서 이렇게 됐다.

- 뷰티샵 한 칸이 「사장님 판단이 필요」해서 막히면 **나머지 27칸도 같이 멈췄다**
- 사장님이 답을 주셔도 **다음 주 화요일**에나 반영됐다

**한 칸이 막힌다고 다른 칸이 못 나갈 까닭이 없다.**

## 새 규칙 — 팩 하나 끝날 때마다 갈래를 정한다

검수 루틴은 팩(업종_등급) 하나를 다 보고 나면 **그 자리에서** 셋 중 하나로 보낸다.

| 그 팩에서 | 어디로 | 언제 손님에게 가나 |
| --- | --- | --- |
| **고친 것이 있다** | `검수/대기/<팩이름>.json` 을 만든다 | 다음 마무리 회차가 **그 팩만** 다시 구워 zip 교체 |
| **고칠 것이 없었다** | **아무것도 안 남긴다** | 그대로 (바뀐 게 없다) |
| **근거가 없어 못 고친다** | `검수/사장님판단.md` 에 한 칸 더한다 | 사장님이 정해 주신 뒤 |

⭐ **셋은 팩마다 따로 정해진다.** 같은 업종이라도 디럭스는 고쳐 보내고 프리미엄은 판단 대기일 수 있다.

## 대기 파일 모양

`검수/대기/뷰티샵_프리미엄.json`

```json
{
  "팩": "뷰티샵_프리미엄",
  "업종키": "beauty",
  "상품키": "beauty-premium",
  "루틴": "pack-qa-spec-a",
  "올린때": "2026-08-19T01:12:00+09:00",
  "고친것": [
    "매장 카드에 「전체 1,204곳 가운데 12곳만 보여 주는 견본입니다」 한 줄 넣음",
    "9/13 을 토요일로 적은 것을 일요일로 고침 (12건)"
  ],
  "다시구울것": ["문서", "zip"]
}
```

- **`업종키`** — `build-template.mts` 가 쓰는 이름: `lms` `beauty` `travel` `matching` `groupbuy` `rental` `interior` `petcare` `used`
- **`상품키`** — `package-template.mts` 가 쓰는 이름: `<업종키>-<등급>` (`standard` `plus` `deluxe` `premium`)
  보기: `beauty-premium` · `lms-deluxe`
- **`다시구울것`** — 문서(01~08·프리셋)만 고쳤으면 `["문서","zip"]`,
  완성화면만 고쳤으면 `["zip"]` (완성화면은 팩 안이 원본이라 다시 구울 게 없다)

## 마무리 회차가 하는 일

`검수/대기/` 를 훑어 **거기 있는 팩만** 처리한다.

```bash
# 팩 하나씩. 하나가 실패해도 나머지는 계속한다
npx tsx build-template.mts <업종키>              # "문서" 가 있을 때만
npx tsx build-template-deep.mts <업종키>         # 프리미엄·플러스면
npx tsx package-template.mts <상품키> --zip      # 그 칸만 zip 을 다시 묶는다
npx tsx check-zip.mts                            # FAIL 0 이어야 한다
```

- 한 팩이 **`check-zip` FAIL** 이면 **그 팩만** 멈추고 대기 파일을 남겨 둔다.
  나머지는 그대로 나간다
- 잘 끝난 팩은 **대기 파일을 지운다.** 지우지 않으면 다음에 또 굽는다
- ⛔ **`npm run pack` 으로 판매팩을 통째로 굽지 않는다.** 대기에 없는 팩까지 건드린다

## 사장님 판단이 필요한 것은 «루틴을 기다리지 않는다»

⛔ **다음 주 루틴이 읽어서 고치는 것이 아니다.** 그러면 일주일이 늦는다.

1. 마무리 회차가 아침 보고에 **판단 기다리는 목록**을 그대로 올린다
2. 사장님이 보시고 **다른 채팅에서 바로 지시**하신다
3. 그 채팅에서 고친 뒤 **`검수/대기/<팩이름>.json` 을 만든다**
4. 다음 마무리 회차가 그 팩만 구워 내보낸다

**그래서 판단이 필요한 팩은 하루쯤 늦게 나갈 뿐, 다른 팩은 안 막힌다.**

`검수/사장님판단.md` 는 **사장님이 보시는 목록**이지, 루틴이 답을 기다리는 곳이 아니다.

## 지켜야 할 것

| | |
| --- | --- |
| **대기 파일은 팩 하나에 하나** | 같은 팩을 두 루틴이 고쳤으면 `고친것` 을 합친다 |
| **고칠 것이 없으면 만들지 않는다** | 빈 파일이 쌓이면 마무리가 헛일한다 |
| **마무리가 지운다** | 검수 루틴은 남의 대기 파일을 지우지 않는다 |
| **락을 본다** | `검수/_마무리중.lock` 이 있으면 굽는 중이다. 대기 파일만 만들고 팩은 안 건드린다 |
