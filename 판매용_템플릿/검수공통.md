## 1. 도는 차례 — 기계 먼저, 그다음 눌러 보기

사람 눈에 기대지 않는다. 기계가 셀 수 있는 것은 기계가 먼저 센다.

### 1단계 — 정적 검사 (몇 초)

```bash
node _작업/팩검사.mjs <팩이름>        # 한 팩만
node _작업/팩검사.mjs                 # 전부
```

끊어진 링크 · 없는 그림 · 외톨이 쪽 · **요일이 달력과 맞는지** ·
프리셋 이름이 실제 색과 맞는지 · 두 등급이 같은 레이아웃인지를 센다.

⛔ **요일을 눈으로 세지 마라.** 2026-08-19 에 49건이 그렇게 숨어 있었다 —
2025년 달력으로 요일을 적고 날짜만 2026년으로 쓴 자리다.

```bash
node _작업/레이아웃검사.mjs <팩이름>          # 한 팩만 (한 쪽에 15초쯤)
node _작업/레이아웃검사.mjs <팩이름> --폭 390   # 폰 폭으로 한 번 더
```

**팩의 «모든 쪽»을 실제로 그려** 다섯 가지를 잰다 (2026-08-20 에 만들었다):

| 무엇 | 왜 |
| --- | --- |
| 가로 넘침 | 칸보다 넓은 내용이 옆 칸을 덮는다 (`min-width:0` 빠짐) |
| 탭 줄에 딸려 온 세로 스크롤바 | `overflow-x` 만 적으면 y 가 auto 로 딸려 온다 |
| 푸터가 바닥에 안 붙음 | 짧은 쪽에서 아래가 텅 빈다. 「덜 만든 화면」으로 읽힌다 |
| 글자 겹침 | 서로 포개져 못 읽는다 (LMS ST0401 이 그랬다) |
| **CSS 점이 옆 글자를 덮음** | 세로 타임라인용 점(`::before`)을 가로 줄에 쓰면 앞 글자를 문다 |

⛔ **`check-레이아웃.mts` 와 다르다.** 그쪽은 «대표 다섯 장»만 본다.
   레이아웃이 깨지는 자리는 **짧은 화면**(빈 목록·완료·오류)에 몰려 있는데,
   손으로 도는 동선에서도 대표 다섯 장에서도 그 화면들이 자꾸 빠졌다.
   14팩 1,357쪽에 처음 돌렸을 때 59쪽이 나왔다.

⚠ **마지막 항목은 의사요소라 「글자 겹침」으로는 못 잡는다.** DOM 에 없어서 사각형을 못 견준다.

### 2단계 — 만들어 둔 검사기

```bash
npx tsx check-presets.mts             # 글과 코드가 싸우면 여기서 멈춘다
npx tsx check-design.mts
npx tsx check-pack.mts
npx tsx check-사진.mts
npx tsx check-레이아웃.mts            # ⭐ 대표 다섯 장을 실제로 그려 겹침·넘침을 잰다
npx tsx check-반응.mts <팩이름>        # ⭐ 눌러도 아무 일 없는 것을 센다 (디럭스·프리미엄)
npx tsx check-눈으로.mts <팩이름>      # ⭐ 옮겨 다니며 잰다 — 폭·간격·푸터·흔들림·뒤로가기·늘어난 부품
```

- **`check-레이아웃`** — 다른 검사기는 «글자»를 보지 «그려진 자리»를 안 본다.
  2026-08-11 에 그 틈으로 사진이 페이지를 덮은 것이 그대로 나갔다.
  캡처가 `판매용_템플릿/_마케팅/검수/<날짜>/<팩>/` 에 남으니 **그것도 열어 본다.**
- **`check-반응`** — 매칭 프리미엄의 알림 종 146개, 인테리어의 달력 56칸이
  죽은 채로 다른 검사기를 다 통과했다. FAIL 0 이어야 한다.
- **`check-눈으로`** — 2026-08-20 에 붙었다(검수항목 **H1~H15**). 나머지 검사기는 다
  «한 장을 세워 놓고» 잰다. 그래서 이런 것을 아무도 못 봤다 —
  「이 화면만 폭이 다르다」·「탭을 눌렀더니 화면이 밀렸다」·「푸터가 버튼에 맞붙었다」.
  **옮겨 다니고 끝까지 굴려야** 보이는 것들이다.
  ⚠ **창 높이를 900 으로 잰다.** 2400 으로 재면 어느 화면이든 자리가 남아
  `margin-top:auto` 푸터가 저절로 아래로 밀린다 — 첫 판이 그래서 MY0101 을 못 봤다.
  ⚠ 한 팩만 볼 때는 `--전부` 를 준다. 대표 14장으로는 사장님이 짚으신 자리가 빠질 수 있다.

⛔ **`check-zip날짜` 를 빼면 고친 것이 아무 데도 안 간다.**
2026-08-20 에 실제로 겪었다 — 포인트 색·늘어난 배지·타원 버튼·눌리지 않던 가짜 버튼 702장을

손님이 내려받는 것은 폴더가 아니라 **zip** 이다. 팩을 고쳤으면 반드시 다시 굽는다:

```bash

```

⚠ **`npm run pack` 은 zip 을 안 굽는다.** 이걸 몰라서 「zip 다시 구웠다」고
두 번 잘못 보고한 적이 있다(검수항목 B9).

### 3단계 — 브라우저로 «사람처럼» 눌러 본다

**1·2단계가 0이 된 뒤에 한다.** 기계가 잡을 것을 손으로 찾지 않는다.

```bash
# .claude/launch.json 의 「팩전체」 — node _작업/팩서버.mjs 4200
```
`http://localhost:4200/<팩이름>/완성화면/` 에서 시작한다. **끝에 `/` 를 빼면 CSS 가 안 붙는다.**

⭐ **주소창에 쳐 넣지 말고 화면 안의 링크를 눌러 다닌다.**
주소로 건너뛰면 화면이 서로 이어지는지가 안 보인다.

**묶음마다 대표 화면**을 열고, 위 ①②③ 을 본다. 아래는 **실제로 나온 자리들**이다.

| 자주 나오는 자리 | 어떻게 확인하나 |
| --- | --- |
| 거르는 단추가 **켜짐 표시만 바뀌고 목록은 그대로** | 눌러서 보이는 개수가 실제로 줄어야 한다 |
| 같은 무리 단추가 **동시에 켜짐** | 「디자인」과 「전체 보기」가 같이 켜지면 안 된다 |
| 걸러서 2개가 남았는데 **쪽 번호는 1~5 그대로** | 조건이 바뀌면 1쪽으로 돌아가야 한다 |
| 카드 위 찜 하트가 **사진에 덮여** 안 눌림 | `document.elementFromPoint(x,y)` 로 그 자리 맨 위를 본다 |
| 앞 화면에서 고른 값(할부·수량·옵션)이 **안 넘어감** | 골라 놓고 다음 화면에서 확인한다 |
| 같은 값이 화면마다 다름 | 진도가 한 곳은 67%, 다른 곳은 40% |
| 「이번 주」·「D-3」 이 **실제 날짜와 안 맞음** | 오늘 기준으로 다시 센다 |
| 비로그인 화면인데 **헤더는 로그인 상태** | 로그인/회원가입 단추가 있어야 한다 |
| 탭을 눌렀는데 **내용이 화면 밖**이라 안 바뀐 것처럼 보임 | 탭 줄이 화면에 보이게 옮긴다 |
| 한 번으로 끝나는 단추(쿠폰 받기)가 **몇 번이고 눌림** | 누른 뒤 글자가 바뀌어야 한다 |

## 2. 고칠 때

### ⭐ 숫자 하나를 고치면 그 숫자로 계산되는 값을 «전부» 따라간다

2026-08-19 에 차시 수를 30에서 18로 고치면서 진도·남은 차시를 안 고쳤다.
같은 강의가 화면마다 67% 와 40% 로 갈렸다. **반쪽만 고치면 안 고친 것보다 나쁘다.**

차시를 바꿀 때 딸린 것: **총 재생 시간 · N/M · 진도 % · 남은 것 · 장별 완료 수.**

### ⭐ 한쪽을 고쳤으면 «다른 등급»도 본다

스탠다드와 디럭스는 핵심 파일이 같고, 플러스와 프리미엄도 같다.
한쪽만 고치면 나머지가 옛것으로 남는다.

### ⭐ 뿌리까지 올라간다

화면만 고치고 끝내지 마라. 같은 것이 아래에도 적혀 있는지 본다.

| 어디 | 무엇 |
| --- | --- |
| `template-data-<업종>.ts` | 스펙팩의 뿌리. 여기가 안 고쳐지면 **손님 화면도 똑같이 죽는다** |
| `lib/design-presets.ts` | 모든 팩이 따르는 규칙. 여기에 넣으면 다음 팩부터 안 생긴다 |
| `lib/export/spec-pack.ts` | 손님이 AI 에 넣는 스펙팩 |

스펙팩 뿌리를 고쳤으면 **CSV 에 「스펙팩 고침」이라고 적는다** — 마무리 회차가 다시 굽는다.

### ⭐ 공통 CSS·JS 를 고칠 때는 «짜임이 다른 화면»을 본다

2026-08-19 에 푸터를 바닥에 붙이려고 넣은 한 줄이
사이드바형 팩(`.app` 이 grid 2열)의 홈을 통째로 무너뜨렸다.
에디토리얼형에서는 멀쩡했다. **한 팩에서 되는 것이 다른 팩에서 안 된다.**

고쳤으면 **짜임이 다른 팩도 한 장씩 열어 본다.**

## 3. 절대 지킬 것

| | |
| --- | --- |
| **남의 몫을 건드리지 않는다** | 같은 시각에 다른 루틴이 그것을 보고 있다. 서로 덮어쓴다 |
| **`npm run pack` 을 돌리지 않는다** | 팩을 통째로 다시 굽는다. **마무리 회차만** 한다 |
| **zip 을 굽지 않는다 · 구글 시트에 올리지 않는다** | 마무리 회차 몫이다 |
| **`build-all.mts` 를 함부로 돌리지 않는다** | ⛔ 뷰티·여행·매칭·공동구매는 완성화면을 `_작업/` 에서 **덮어쓴다.** 고친 화면이 날아간다 |
| **우리 사이트 코드를 건드리지 않는다** | `app/` · `components/` 는 읽기만. 찾으면 고치지 말고 적는다 |
| **완성화면을 지우지 않는다** | 사람이 만든 것이다. 고치는 것은 되고 지우는 것은 안 된다 |
| **못 고친 것을 고쳤다고 하지 않는다** | 「어느 파일 · 몇 째 줄 · 무엇을 무엇으로」까지 적는다 |
| **git push · 배포를 하지 않는다** | 커밋까지만 |
| **물어보지 않는다** | 사장님은 주무신다. 막히면 그 줄을 「못고침」으로 적고 다음으로 간다 |

## 4. «만드는 중»인 팩은 절대 보지 않는다

팩 하나를 만드는 데 두 회차가 걸리는데 검수는 매주 돈다.
만들다 만 팩을 보면 FAIL 이 쏟아지고 포장이 막힌다.

| 자리 | |
| --- | --- |
| `판매용_템플릿/_판매팩/` | **네가 보는 곳.** 다 된 것만 있다 |
| `판매용_템플릿/_만드는중/` | **열지 마라** |

`_만드는중/` 은 세지도 말고 흠으로 적지도 마라.
보고에 「만드는 중인 업종이 있습니다 — <이름>」 한 줄만 적는다.

## 4-1. ⭐ 일 시작 전에 «검수 판단 목록»을 먼저 읽는다

`검수/판단대기.json` 을 읽는다. 사장님이 화면(`/admin/qa`)에서 처리해 두신 것이 있다.

| 상태 | 무슨 뜻인가 | 네가 할 일 |
| --- | --- | --- |
| **`수정완료`** | **사장님이 다른 채팅에서 이미 고치셨다** | ⭐ **네 검수 항목에 넣어 «제대로 고쳐졌는지» 본다.** 넣었으면 그 칸을 목록에서 **지운다** |
| `패스` | 안 고쳐도 되는 것으로 정하셨다 | **그대로 둔다.** 다시 올리지 마라 |
| `기다림` | 아직 안 보셨다 | **손대지 않는다.** 그 건은 건너뛴다 |

⛔ **사장님 답을 «기다렸다 고치는» 것이 아니다.**
사장님이 이미 고치셨고, 너는 그것을 **검수**한다. 순서를 거꾸로 알면 일이 겹친다.

### 네가 근거가 없어 못 고치는 것을 만나면

`검수/판단대기.json` 의 `건` 에 한 칸 더한다. 화면이 그대로 보여 준다.

```json
{
  "id": "2026-08-19_뷰티샵_필터칩",
  "올린때": "2026-08-19T01:12:00+09:00",
  "루틴": "pack-qa-spec-a",
  "팩": "뷰티샵_디럭스, 뷰티샵_프리미엄",
  "제목": "한 줄로",
  "무엇": "무엇이 문제인가",
  "왜못고쳤나": "왜 근거가 없나",
  "여쭙는것": "무엇을 정해 주셔야 하나 — 고르실 수 있게 두세 갈래로",
  "근거파일": "판매용_템플릿/_판매팩/…",
  "상태": "기다림"
}
```

⛔ **정말 근거가 없을 때만 올린다.**
2026-08-19 에 「12개 매장 어디에도 편의 정보가 없다」고 올렸는데, **실은 카드에 있었다** —
「주차 가능」과 「주차가능」의 띄어쓰기 차이를 못 넘은 것이었다.
**올리기 전에 «다른 이름으로 적혀 있지는 않은지» 한 번 더 찾아본다.**

## 4-2. ⛔ 마무리가 도는 동안에는 손대지 않는다

`검수/_마무리중.lock` 파일이 **있으면** `pack-qa-finish` 가 지금 28칸을 다시 굽고 zip 을 묶는 중이다.

- 그때는 **`판매용_템플릿/_판매팩/` 과 `packs/` 를 건드리지 않는다.**
  굽는 중에 고치면 덮어쓰거나, 반쪽만 든 zip 이 손님에게 나간다
- 락이 있는데 네가 고칠 것이 있으면 **CSV 에 적고 넘어간다.** 다음 회차가 본다
- 락은 마무리가 끝나면서 스스로 지운다. **네가 지우지 마라**

## 4-3. ⭐ 팩 하나 끝날 때마다 «그 자리에서» 갈래를 정한다

⛔ **다 모아서 한꺼번에 넘기지 마라.** 한 칸이 막히면 나머지도 같이 멈춘다.
2026-08-19 에 뷰티샵 한 칸 때문에 27칸이 함께 묶일 뻔했다.

팩(업종_등급) 하나를 다 보고 나면 **바로** 셋 중 하나로 보낸다.

| 그 팩에서 | 어디로 | 언제 손님에게 가나 |
| --- | --- | --- |
| **고친 것이 있다** | `검수/대기/<팩이름>.json` 을 만든다 | 마무리 회차가 **그 팩만** 다시 구워 zip 교체 |
| **고칠 것이 없었다** | **아무것도 안 남긴다** | (바뀐 게 없다) |
| **근거가 없어 못 고친다** | `검수/판단대기.json` 에 한 칸 (4-1 참고) | 사장님이 처리하신 뒤 |

대기 파일:

```json
{
  "팩": "뷰티샵_프리미엄",
  "업종키": "beauty",
  "상품키": "beauty-premium",
  "루틴": "pack-qa-spec-a",
  "올린때": "2026-08-19T01:12:00+09:00",
  "고친것": ["무엇을 어떻게 고쳤는지 한 줄씩"],
  "다시구울것": ["문서", "zip"]
}
```

- **업종키** — `lms` `beauty` `travel` `matching` `groupbuy` `rental` `interior`
- **상품키** — `<업종키>-<등급>` (`standard` `plus` `deluxe` `premium`) 보기: `beauty-premium`
- **다시구울것** — 문서(01~08·프리셋)를 고쳤으면 `["문서","zip"]`,
  완성화면만 고쳤으면 `["zip"]` (완성화면은 팩 안이 원본이라 다시 구울 게 없다)
- 같은 팩을 두 루틴이 고쳤으면 **`고친것` 을 합친다.** 파일은 팩 하나에 하나

### ⛔ 끝내기 전에 «내가 고친 팩과 대기 파일이 맞는지» 스스로 센다

**대기 파일을 안 만들면 그 고침은 손님에게 영영 안 간다.**
마무리 회차는 `검수/대기/` 만 보고 굽는다. 거기 없는 팩은 **고쳤어도 옛 zip 그대로 나간다.**

> 2026-08-19 에 실제로 그랬다. 네 루틴이 팩 10칸을 고쳐 놓고 대기 파일은 3칸만 남겼다.
> 나머지 7칸(인테리어 4·장비렌탈 2·매칭 1)은 고친 것이 zip 에 안 실릴 뻔했다.
> CSV 에는 「고침」이라고 잘 적혀 있었다 — **적는 것과 내보내는 것은 다른 일이다.**

그래서 CSV 를 다 쓴 뒤, 보고를 쓰기 **전에** 이것을 돌린다.

```bash
node _작업/대기점검.mjs
```

**빠진 팩이 나오면 보고를 쓰지 말고 먼저 대기 파일을 만든다.**


## 5. 결과를 남기는 자리

| 파일 | 무엇 |
| --- | --- |
| `검수/<날짜>_<루틴>.csv` | **내 몫의 결과.** 마무리 회차가 합친다 |
| `검수기록.csv` | 누적본. **마무리 회차만** 덧붙인다 |
| `검수항목.md` | 항목 목록. ✅(기계가 잰다) · ⬜(기계로 되는데 아직) · 👁(눌러 봐야) |
| **`검수/대기/<팩>.json`** | **고친 팩.** 마무리가 그것만 굽고 지운다 |
| **`검수/판단대기.json`** | **근거가 없어 못 고친 것.** 사장님이 `/admin/qa` 에서 보신다 |


CSV 줄: `날짜,루틴,팩,항목,무엇,근거파일,고침여부`

**고침여부는 넷 중 하나다. 함부로 늘리지 마라 — 마무리 회차가 이 값으로 포장할지 정한다.**

| 값 | 뜻 | 포장을 막나 |
| --- | --- | --- |
| `고침` | 내가 고쳤다 | 안 막는다 |
| `해당없음` | 볼 것이 없었다 · 확인만 했다 | 안 막는다 |
| **`마무리에넘김`** | **내가 하면 다른 루틴과 부딪히는 일.** 마무리 회차가 포장하며 처리한다 | **안 막는다** |
| `못고침` | **정말 못 고쳤다.** 막혔거나, 우리 사이트 코드라 손대면 안 되거나 | ⛔ **막는다** |

⛔ **2026-08-19 에 여기서 걸렸다.** 판매팩 스펙팩이 옛것인 것을
「못고침(마무리 회차가 다시 굽는다)」으로 적었더니, 마무리가 그 「못고침」을 보고 포장을 멈췄다.
**마무리에 넘긴 일이 마무리를 막았다.** 넘기는 것은 `마무리에넘김` 으로 적는다.

괄호로 까닭을 덧붙이는 것은 좋다 — `마무리에넘김(28칸 스펙팩 다시 구울 것)`.

### ⛔ CSV 를 쓴 뒤 «모양이 맞는지» 기계로 잰다

```bash
node _작업/검수표검사.mjs
```

머리줄·칸 수(7)·고침여부 값을 재고, **「고침」인데 팩에 등급이 없으면** 짚어 준다
(`LMS` ✗ → `LMS_디럭스` ○). 등급이 없으면 대기 파일을 못 만들어 그 고침이 안 나간다.

> **2026-08-19 에 `pack-qa-spec-a` 가 8칸짜리 옛 모양으로 썼다.**
> 지시서는 「줄 모양은 검수공통 5절」이라고 제대로 가리키고 있었다. 그런데 옆 폴더의
> 옛 파일(`2026-08-18_A.csv`)이 8칸이라 **그것을 본보기로 삼았다.**
> 그 바람에 마무리가 마지막 칸을 「고침여부」로 읽어 spec-a 의 고침 3칸을 못 봤다.
>
> ⭐ **규칙이 글에 있고 옆의 예시가 규칙을 배신하면, 만드는 쪽은 예시를 따른다.**
> 그래서 글을 더 세게 쓰는 대신 기계가 재게 했다.

⛔ **옆에 있는 옛 CSV 를 본보기로 삼지 마라.** 모양은 이 문서 5절만 본다.


## 6. 보고

한국어로, 개발 용어를 풀어서. 사장님은 웹기획자이고 개발자가 아니다.

- **숫자로** 적는다 — 「눌러 본 화면 N개 · 안 눌리는 단추 0개 · 안 걸러지는 필터 0개 ·
  뒤로가기 어긋남 0개 · 화면끼리 안 맞는 숫자 0개 · **고친 것 N건** · 못 고친 것 N건」
- 숫자를 못 적으면 **아직 확인한 것이 아니다.**
- 못 고친 것은 **왜 못 고쳤는지**까지 적는다.
