## 회차 폴더에 있어야 하는 것

⭐ **회차 폴더는 손으로 안 만들어도 된다 — `틀그리기.mjs` 가 만들어 준다.**
없는 이름을 주면 «릴스영상/» 아래에 만들고 「⭐ 회차 폴더가 없어 새로 만들었습니다」와
「이 폴더에 «마스터.mp4»와 «자막.txt» 를 넣으세요」까지 말해 준다.

```
5. 프로젝트 생성영상/
├─ 마스터.mp4      ← 컷 편집을 끝낸 영상 (내가 만든다)   ⚠ 손으로 넣는다
├─ 자막.srt        ← 내가 만든다 (시각이 있는 것)        ⚠ 손으로 넣는다
│  또는 자막.txt    ← 한 줄에 한 칸. 시각 없이 차례로 놓인다
└─ 캡션.md         ← 내가 만든다
```

돌리는 차례:

```
① node 틀그리기.mjs "5. 프로젝트 생성영상" --제목 "첫 줄|둘째 줄"   ← 폴더 + 틀 + 제목 .ass
      (폴더가 없으면 여기서 만들어진다. --제목없이 로 제목 없이 굽는 길도 있다)

② ⚠ 그 폴더에 «마스터.mp4» 와 «자막.txt»(또는 자막.srt) 를 넣는다   ← 손으로 하는 단계
      이걸 건너뛰면 ③ 이 「대본이 없습니다」로 멈춘다

③ node 자막굽기.mjs  "5. 프로젝트 생성영상"                        ← 자막.srt/txt → .ass 두 벌
④ node 영상만들기.mjs "5. 프로젝트 생성영상"                       ← 굽는다
```

⛔ **회차 폴더 이름에 작은따옴표(`'`)를 쓰지 마라.** ffmpeg 의 필터 파서가 `'` 를 삼켜
(「현님's」 → 「현님s」) 파일을 못 찾는다. 셋 다 «맨 먼저» 이 사실을 말하고 멈춘다.
쉼표 · 한글 · 공백 · 「02. 」의 점은 다 괜찮다.

돌리면 나오는 것:

```
├─ 16_9.png        3840 x 2160  가로 틀   (틀그리기.mjs)
├─ 9_16.png        2160 x 3840  세로 틀   ( 〃 )
├─ 제목_9_16.ass   제목 글자              ( 〃 )   ⭐ 2026-09-04 저녁에 생김
├─ 제목_16_9.ass                          ( 〃 )
├─ 자막_9_16.ass   2160 x 3840 용         (자막굽기.mjs)
├─ 자막_16_9.ass   3840 x 2160 용         ( 〃 )
├─ 마스코트.txt    이 편이 쓴 마스코트 영상 (영상만들기.mjs)   ⭐  〃
├─ 최종_16x9.mp4   3840 x 2160   유튜브 롱폼 · 홈페이지 임베드
└─ 최종_9x16.mp4   2160 x 3840   쇼츠 · 릴스
```

⭐ 자막을 우리가 굽는다 — **캡컷에서 얹지 않아도 된다.**

⭐ **제목 띠는 «움직이는 마스코트 영상»이다** (2026-09-04 저녁).
`_이미지/마스코트/영상/*.mp4` 에서 편마다 하나를 골라 그 편 내내 쓴다.
고른 것은 `<회차>/마스코트.txt` 에 적어 두어 **세로판·가로판을 따로 구워도 같은 것이 나온다.**

```

```

빠져나갈 문 몇 개 더 (2026-09-04 밤에 생겼다):

```
node 틀그리기.mjs  "회차" --제목없이        ← 제목 글자 없이 (옛 제목_*.ass 도 지운다)
node 틀그리기.mjs  "회차" --제목 "세로 첫 줄|둘째 줄" --가로제목 "가로 첫 줄|둘째|셋째"
     ⭐ 가로판 제목 칸은 폭이 1024 뿐이라 같은 글이 접혀 줄이 는다.
        집 대본(`_작업/대본_*.json`)의 «세로제목 / 가로제목» 과 같은 뜻이다.

node 영상만들기.mjs "회차" --한수            ← 구간을 안 나누고 옛날처럼 한 수로 굳힌다
node 영상만들기.mjs "회차" --분할선 1144     ← 2분할 분할선을 손으로 못 박는다
node 영상만들기.mjs "회차" --분할무시        ← 2분할로 안 보고 통째로 앉힌다 (코드창 PiP 없음)
```

## ⭐ 구간마다 짜임이 갈린다 (2026-09-04 밤)

**녹화본은 영상 내내 2분할이 아니다.** 대개 ① 코드창 전체화면 → ② 2분할 → ③ 브라우저 전체화면
으로 흐른다. 옛 방식은 분할선을 «한 수»로 굳혀 ③ 구간에서도 왼쪽을 잘라 PiP 에 넣었고,
그래서 **코드창 자리에 브라우저 조각이 확대돼** 들어갔다. 현님이 잡아내신 흠이다.

지금은 `_구간.mjs` 가 구간을 재서 **구간마다 짜임을 갈아 끼운다.**

| 구간 종류 | 영상 칸 | 코드창 PiP |
|---|---|---|
| 2분할 | 분할선 «오른쪽»만 | **얹는다** |
| 코드창 전체화면 | 통째로 채움 | **안 얹는다** |
| 브라우저 전체화면 | 통째로 채움 | **안 얹는다** |

- 2분할 안에서 분할선이 40px 넘게 바뀌면 **거기서 또 자른다** — 「한 수로는 못 자른다」가 사라졌다
- 세로판(9:16)만 달라진다. 가로판(16:9)은 원본이 통째로 들어가므로 구간과 무관하다
- `--한수` · `--분할선` · `--분할무시` 중 하나라도 주면 구간을 안 나눈다.
  그때는 옛 검사가 살아나 분할선이 흔들리면 멈춘다
- ⚠ 브라우저 전체화면 구간은 «가운데»를 잘라 채우고 2분할 구간은 «오른쪽»을 잘라 채우므로,
  구간이 바뀔 때 화면이 옆으로 한 번 건너뛴다. 녹화에서 실제로 창이 바뀐 것이라 어쩔 수 없다

⭐ **가장 깨끗한 길은 녹화할 때 창 너비를 끝까지 고정하는 것**이다. 구간이 하나가 되어 나눌 것도 없다.

## ⭐ 브라우저 탭줄·주소창은 잘라낸다 (2026-09-04 밤)

릴스에 **로컬 경로(`D:/_가이드용_2/…/HO-01.html`)가 그대로 나가면 안 된다.**
`영상만들기.mjs` 가 위에서부터 «어두운 띠가 끝나고 밝은 페이지가 시작하는 줄»을 재서 잘라낸다.
실측 — LMS 218px · 공구 194px · 뷰티샵 219px · 인테리어 193px.

- 여러 점을 재서 **가운뎃값**을 쓴다. 벌어짐이 40px 을 넘으면 **안 자르고 그렇다고 말한다**
  (무료샘플이 110·253 으로 흔들렸다). 조용히 엉뚱한 데를 자르는 것이 제일 나쁘다
- **세로판만**이다. 가로판은 원본이 «배율 1.000» 으로 들어가는데 위를 자르면 그 1.000 이 깨지고
  왼쪽 코드창 위도 같이 잘린다
- **코드창 전체화면 구간에는 안 자른다** — 거기엔 브라우저 크롬이 없다
- ⚠ 치르는 값: 세로가 218px 줄어 배율이 **1.528 → 1.699** 로 오르고 가로 남는 몫이 **84.2% → 75.8%** 가 된다.
  그대로 두시려면 `--크롬남김`

자세한 것은 `새틀_명세.md` 의 「구간마다 짜임을 갈아 끼운다」·「브라우저 크롬을 잘라낸다」.

## 촬영 규격

### 1280 × 960 · 4:3

- **창 폭 1280을 지킨다** — 1024 아래로 가면 모바일 레이아웃으로 바뀐다
- 비율은 **4:3** — 두 틀의 영상 자리(1.28 : 1 과 1.35 : 1)의 딱 가운데라, 양쪽 모두 잘림·빈틈이 2% 안쪽이다

이 영상은 "이런 화면들이 나왔다"를 보여주는 것이지 화면 속 글씨를 읽히는 게 아니다.
설명은 자막이 한다. 그러니 해상도를 더 올릴 이유가 없다.

| 넣는 곳 | 4:3 원본이 들어가면 |
|---|---|
| 16:9 자리 | 좌우 1.9%씩 잘림 |
| 9:16 자리 | 좌우 0.25%씩 빔 |

**세로는 두 자리 모두 꽉 차서 위아래는 하나도 안 잘린다.**

## 속도감 — 기준은 여행편이고, 숫자로 맞춘다

`4. 여행사이트 144개화면/여행_컷편집_마스터.mp4`(92.6초)가 기준이다.
「빨라 보이지 않는다」는 말이 나오면 **감으로 고치지 말고 재서 맞춘다.**

### 재는 법

```bash
ffmpeg -v info -i 대상.mp4 -vf "scale=320:-1,format=gray,tblend=all_mode=difference,signalstats,metadata=print" -an -f null - 2>&1
```

프레임과 프레임 사이가 얼마나 달라졌는지(YAVG)가 나온다. 세 가지를 본다:

| 재는 것 | 뜻 | 기준(여행편) |
|---|---|---|
| YAVG > 30 인 프레임 | **진짜 장면 전환** | 1.60초에 한 번 |
| YAVG 3~30 인 프레임 비율 | **컷 안에서 화면이 흐르는 정도** | 14% |
| 상위 10% 변화량 | 전체적인 활기 | 6.46 |

**틀 여백은 늘 정지라 값을 희석시킨다. 영상 칸만 잘라서 재야 한다** (`crop=1080:774:0:400` 식).

### 두 번 틀린 것

**① 배속만 올리는 것 — 안 통한다.** 2배속으로 올려도 「빨라진 것 같지 않다」는 말을 들었다.
멈춰 있는 화면은 두 배로 빨려도 멈춰 있다. 재 보니 장면 전환이 1.02초에 한 번으로 기준(1.60초)보다
오히려 잦은데도 느리게 느껴졌다. 모자란 건 **컷 안의 움직임**(7% vs 14%)이었다.

**② 생성 구간을 8배속으로 까는 것 — 우리 소재엔 안 맞는다.**
기준 영상이 그렇게 한다길래 따라 했다가 오히려 나빠졌다(상위10% 1.61 → 0.44).
**우리 녹화본의 생성 구간은 어두운 터미널에 글자만 올라오는 화면**이라 아무리 당겨도 픽셀이 안 움직인다.
고배속은 화면이 실제로 크게 바뀌는 소재에서만 쓴다.

### 그래서 지금 쓰는 방법

**자막 한 칸(2.5초)을 컷 세 개(각 0.83초)로 쪼갠다.** 컷마다 소스의 다른 자리로 건너뛴다.
어디로 건너뛸지는 **움직임을 재서 고른다** — 소스를 훑어 변화량이 큰 창부터 집는다(`pick.mjs`).

```bash
# 소스에서 움직이는 구간 찾기 (관심 구간만, fps=4 로 훑으면 몇 초면 끝난다)
ffmpeg -v info -ss 590 -t 290 -i 원본.mp4 -vf "fps=4,scale=160:-1,format=gray,tblend=all_mode=difference,signalstats,metadata=print" -an -f null -
```

배속은 **장면 성격에 맞춘다** — 읽어야 하는 화면(목록·금액) 2~3배, 눌러 보는 화면 3~4배.

이렇게 해서 영상1이 **장면 전환 1.79초에 한 번**(기준 1.60)까지 왔다.
컷 안 움직임은 6%로 기준(14%)에 못 미치는데, **완성 사이트를 눌러 보는 영상은 원래 정적**이라
소재의 한계다. 로그가 쏟아지거나 스크롤이 긴 녹화본을 쓸 땐 더 올라간다(영상2는 9%).

### 자막이 어긋나는 문제 — 구조로 막았다

배속과 컷을 건드리면 보통 자막이 밀린다. 우리는 **자막을 틀 PNG에 구워 넣고 그 위에 영상을 얹기 때문에
자막이 영상과 물리적으로 한 덩어리다.** 컷을 아무리 잘라도 자막은 제자리에 있는다.

> ⛔ **2026-09-04 — 새 틀(2분할 녹화본)에서는 이 방식을 못 쓴다.**
> 새 자막 자리(46%)가 **영상 자리 한복판**이라 틀에 구우면 `overlay` 가 덮어 한 글자도 안 보인다.
> 그리고 정지 PNG 로는 한 글자씩 채우는 움직임을 못 만든다.
> 대신 `.ass` 로 **최종 크기에서 곧장** 굽는다 — `node 자막굽기.mjs "회차"`.
> 밀림은 여전히 안 생긴다: `.ass` 의 시각은 **컷 편집이 끝난 마스터.mp4 기준**이고 굽는 사슬 안에서 얹힌다.
> 이 「틀에 굽기」 규칙은 **주간 카드형 콘텐츠(`_작업/영상굽기.mjs`)에는 그대로 살아 있다.**

숫자로도 딱 떨어진다 — 컷 0.8333초 × 30fps = **25프레임**, 세 컷이면 **75프레임 = 정확히 2.5초**.
자막 한 칸이 프레임 수로 정수라 반올림 오차가 쌓이지 않는다.
**컷 수를 바꿀 땐 2.5초를 나눠떨어지게 잡아야 한다**(3컷 0.833 / 5컷 0.5 ○, 4컷 0.625 ○, 7컷 ✗).

## 컷 편집 흐름 — 이 순서를 지킨다

기준은 여행편(`4. 여행사이트 144개화면/여행_컷편집_마스터.mp4`, 92초)이다.
**완성본부터 보여주지 않는다. 녹화 맨 앞, AI팩을 넣는 장면부터 시작한다.**

| 토막 | 무엇을 | 비중 |
|---|---|---|
| 넣는다 | 파일 끌어다 놓기 → 프롬프트 한 줄 → 전송 | ~9% |
| 클로드 분석 | 스펙팩 읽는 로그, 도구 실행 개수 | ~9% |
| 기다린다 | **거의 안 움직이는 화면을 타이머 값만 바꿔 가며 컷컷** (5분·20분·30분) | ~6% |
| 나온다 | 생성 파일 개수·줄 수, 미리보기 주소, 누르기 | ~6% |
| **화면생성** | **AI가 화면을 찍어내는 구간을 10배속으로.** 40초 원본 → 4초 출력, 6컷 | ~20% |
| 클릭해 보는 | 완성 사이트 — 고객 화면 → 매장 화면 → 예외 화면 → 정산 | ~35% |
| 시그니처 | 아래 고정 3줄 | ~14% |

- 빌드 대기 구간은 화면이 정지해 있는 게 정상이다. **바뀌는 건 타이머뿐이고, 그 숫자가 이야기를 끌고 간다.**
- **정지 구간이 길어지면 영상이 죽는다.** 화면이 실제로 바뀌는 구간을 골라 10배속으로 깔아 역동성을 만든다.
  움직임이 큰 창은 프레임 차이로 찾는다 (`motion.mjs` 방식 — 20초 창 평균 변화량 상위 구간).
- 등속 컷은 장면 전환 지점 안쪽에만 넣는다 — 한 컷 안에서 페이지가 바뀌면 안 된다.
- 감정이 실리는 자막은 두 군데만. 나머지는 담담하게 숫자만 말한다.
- 자막은 컷마다 한 줄씩, 촘촘하게. 2.0~2.9초가 기본이다.

### 시그니처 — 마지막 세 줄은 이걸로 고정한다

```
편한 건 좋지만, 부족한 건 싫어서 AI팩을 직접 만들었어요.
만들어진 화면 OOO개, 제가 한 건 파일 O개 넣고 기다리기
AI팩이 궁금하시다면, 캡션과 프로필 링크를 확인해 주세요.
```

숫자만 회차에 맞게 바꾼다. 자막은 2.5초에 하나씩 넘긴다.

#### 마지막 한 줄은 글자 그대로 고정이다

```
AI팩이 궁금하시다면,
캡션과 프로필 링크를 확인해 주세요.
```

**토씨 하나 바꾸지 않는다.** 매 영상 같은 자리에서 같은 말이 나와야 사람이 기억한다.
「궁금하면」·「프로필 링크 확인해 주세요」처럼 조금씩 달라진 판이 섞여 있었는데 위 문장으로 통일했다.

**색도 고정이다 — 이 줄만 바탕을 채운다.**

```html
AI팩이 궁금하시다면,|<span class="cta">캡션과 프로필 링크를 확인해 주세요.</span>
```

| | 값 |
|---|---|
| 바탕 | `--orange` `#E4762C` |
| 글자 | `#FCF3E2` |
| 모서리 | 10px(세로) · 12px(가로) |

본문 자막이 이미 오렌지 글자(`.o`)와 틸 글자(`.t`)를 쓰고 있어서
**글자색만 바꿔서는 안 튄다.** 그래서 여기만 바탕을 채워 갈라 놓는다.
영상에서 유일하게 「눌러 달라」고 말하는 자리라 이 대접을 받을 만하다.

`.cta` 는 `영상틀_916.html`·`영상틀_169.html` 두 틀에 다 들어 있다.
가로 틀은 자막이 영상 안이라 글자에 굵은 테두리를 두르는데, 이 줄만 테두리를 끈다(안 그러면 지저분하다).

## 자막(SRT) 규칙

- **BOM + CRLF**로 저장해야 캡컷에서 한글이 안 깨진다 (캡컷에 넘길 때만 — `.ass` 는 BOM 없이 UTF-8)
- 초당 6.5자 이하
- 자막 사이 공백은 최대 0.3초
- ⭐ **한 줄은 한글 13자** (공백 섞이면 16자). 넘으면 `|` 로 끊는다 — `자막굽기.mjs` 가 미리 알려 준다
