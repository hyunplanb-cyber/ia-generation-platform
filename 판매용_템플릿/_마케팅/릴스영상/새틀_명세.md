### 제목 띠에 마스코트 영상을 어떻게 앉히나 — 「폭 꽉, 세로만」

```
배율 = 2160 / 원본W                          # 1280 → 배율 1.6875
창h  = min(원본H, 610 / 배율)                # 띠 높이를 원본 화소로 환산
cy   = 짝수( round( (머리·원본H − 0.03·창h) × 배율 ) )
scale=2160:1216 → crop=2160:610:0:cy
```
「머리 꼭대기를 띠 위끝에서 창 높이의 3% 아래에 둔다」 = **여백 18px** (540 일 때는 16px 이었다).

### 되풀이 — ⛔ `-stream_loop -1` «만»으로는 부족하다

되풀이 이음매(마지막 프레임 → 첫 프레임 밝기 절대차)는 **영상마다 다르다.**

| 영상 | 이음매 | 평범 최대 | 배수 |
|---|---|---|---|
| 해변가 | **6.99** | 1.38 | **5.1배** |
| 설명중 | 3.92 | 0.77 | 5.1배 |
| 아침테라스 | 3.77 | 0.63 | 6.0배 |
| 강가 | 3.37 | 0.45 | 7.5배 |
| 화상회의 | 2.92 | 0.64 | 4.6배 |
| 온천 | **1.43** | 0.62 | 2.3배 ← 가이드가 쓴 것. 그래서 «안 튄다»는 착각을 준다 |

→ **왕복본(앞→뒤→앞)을 미리 만들어 `릴스영상/_마스코트왕복/` 에 캐시하고 `-stream_loop -1`.**

   `fps=30` 은 반드시 `concat` «앞»에 둔다. 왕복본은 `-an` 으로 만든다(§소리 사고 참고).

#### 무엇을 어떻게 잘라 넣나

촬영본은 **왼쪽이 클로드, 오른쪽이 브라우저**인 2분할이다. 왼쪽 칸을 잘라 이 자리에 넣는다.

```
경계x   = 촬영본에서 «어두운 왼칸 → 밝은 오른칸»이 바뀌는 자리 (녹화본마다 다르다)
크롭h   = round( 경계x / (2002/904) )      # 2.2146 — 목표 상자 비율
크롭y   = 글이 실제로 움직이는 띠 (아래 참고)
crop=경계x:크롭h:0:크롭y  →  scale=2002:904
```

⛔ **경계 x 를 박아 두지 마라 — 녹화본마다 크기가 다르다.**
뷰티샵 프리미엄은 3156×2160 에 경계 **x=1080** 이었다(왼 1080 · 오른 2076). 다른 것은 다른 값이다.

**크롭 y 는 «글이 움직이는 곳»으로 잡는다.** 뷰티샵을 1/2초 간격 120장으로 재 보니
움직임이 y 320~1920 에 퍼져 있고 y 480~960 이 가장 컸다.
488px 창을 가장 잘 놓는 자리는 **y 416~904** 였다. 위쪽 0~320 은 거의 안 움직인다(머리말·탭).

## 어느 마스코트 영상을 쓰나

### ⛔ 공유 상태를 «읽기만» 한다

`_이미지/마스코트/영상/_편별.json` · `_최근.json` 은 **쓰지 않는다.**
`_작업/영상굽기.mjs`(쓰기)와 `영상인트로.mjs` 168줄(커버 누끼 짝짓기 · 읽기)이 공유하는
주간 파이프라인 상태다. 릴스 편 이름을 써 넣으면 주간 커버가 그 줄을 그대로 믿는다.

| 파일 | 무엇 |
|---|---|
| `릴스영상/_마스코트자리.json` | 영상 11개 × 네 숫자(x0 x1 머리 얼굴) + 띠쓰나 |
| `릴스영상/_마스코트_최근.json` | 릴스끼리 안 겹치게. 기억은 **후보수−1 = 8개**만 |
| `릴스영상/<회차>/마스코트.txt` | 파일 이름 한 줄. **세로·가로를 따로 구워도 같은 것이 나오게** |
| `릴스영상/_마스코트왕복/<이름>.mp4` | 왕복본 캐시 (영상당 2~5MB, 0.8초) |

### 고르는 차례 — 3단이다. 2단을 빼면 무작위가 된다

```
① --마스코트 온천.mp4   손지정 → <회차>/마스코트.txt 에 적고 끝
② <회차>/마스코트.txt 가 있으면 그것                       ← 다시 구워도 같게
③ 새로 뽑기
     후보 = 자리표 띠쓰나:true  AND  (캐릭터왼끝 − 제목잉크오른끝 ≥ 60px)
     1단  후보 − 릴스최근 − 주간최근      둘 다 안 쓴 것
     2단  후보 − 릴스최근                릴스에서 안 쓴 것          ⛔ 빼면 안 된다
     3단  후보 전체                      한 바퀴 다 돌았다
```
⛔ **2단이 반드시 있어야 한다.** 주간 `_최근.json` 에는 10개가 들어 있다. 그것을 1단과 같은 무게로 빼면
우리 후보 9개가 통째로 지워지고 **순수 무작위**가 된다(실제로 밟았다 — 강가가 세 편 내리 나왔다).
릴스 제 최근이 «딱딱한 규칙», 주간 최근은 그 안에서의 «취향»이다.

⛔ **후보가 0개면 멈춘다.** `--띠없이` 를 주면 어두운 띠로 굽는다(빠져나갈 문 하나).

### 자리표의 네 숫자 — 사람이 한 번 채운다

`머리` 는 편 전체에서 «가장 높이 올라간» 순간의 값이어야 한다(캐릭터가 숨쉬며 오르내린다).

⚠ **자동검출을 시도했다가 버렸다.** 움직임에너지는 야근·쇼파수다에서 뒤집히고(캐릭터가 오히려 저변동),
색 검출은 벽·모래·나무를 얼굴로 잡는다. 11개 중 2개가 틀리면 «얼굴 반쪽»이 나간다.
→ 대신 **확인 그림 도구**를 둔다: `node 마스코트자리.mjs` 가 11개 띠를 제목까지 얹어 한 장으로 붙여 준다.

## 촬영본을 어떻게 앉히나

2분할 녹화본은 **왼쪽 = 클로드 코드 창 · 오른쪽 = 브라우저**다. 분할선은 파일마다 다르다.

| 파일 | 원본 | 분할선 | 코드창 | 브라우저 |
|---|---|---|---|---|
| 공구_디럭스 | 2514×2160 | x 1016 | 1016 | 1498 |
| 인테리어_프리미엄 | 2588×2160 | x 949 | 949 | 1639 |
| 매칭_디럭스 | 2804×2160 | x 1133 | 1133 | 1671 |
| LMS_디럭스 | 2816×2160 | x 1144 → 962 ⚠ | 1144 → 962 | 1672 → 1854 |
| 무료샘플 | 3012×2160 | x 1042 | 1042 | 1970 |
| 뷰티샵_프리미엄 | 3156×2160 | x 1078 | 1078 | 2078 |
| 여행_144개화면 | 3840×2160 | **없음** | — | 전체 |

**분할선은 코드가 스스로 찾는다** — 열 평균 밝기의 최대 상승점 한 줄이면 잡힌다.
못 찾으면 «2분할이 아니다» 로 보고 PiP 없이 브라우저만 앉힌다.

### ⛔ 분할선이 «한 파일 안에서» 바뀔 수 있다 (2026-09-04 밤에 밟았다)

위 표는 파일마다 한 수를 적어 두었지만, **그건 한 점만 재서 나온 값이다.**
`9. 새틀시험/마스터.mp4`(LMS_디럭스 컷편집본, 12.03초)를 0.5초 간격으로 다 재 보니

| 구간 | 분할선 | 상승 |
|---|---|---|
| t 0.0 ~ 5.0초 | x **1144** | 176~184 |
| t 5.5 ~ 9.5초 | x **962** | 176~179 |
| t 10.0초 ~ 끝 | 없음 (한 화면) | 4~6 |

녹화 도중에 코드창 너비가 182px 바뀐 것이다. 옛 코드는 넉 점(25·40·55·70%)만 재서
**가운뎃값 1144 하나로 굳혔고**, 흔들림 검사(폭의 8% = 225px)에도 안 걸려 한 마디도 안 했다.
그 결과 뒤 절반은 브라우저 왼쪽 182px 이 날아가고, PiP 안에 브라우저가 182px 들어왔다
(**「PiP 는 코드창을 가로로 한 픽셀도 안 자른다」가 반대쪽으로 깨졌다**).

## ⭐ 구간마다 짜임을 갈아 끼운다 (2026-09-04 밤 · 현님 지적으로 생김)

현님: 「이 중간에 검은화면이 다른 걸로 바뀌는데 이런건 알맞게 컷이 불가능한가?」

**한 수로 굳히는 것 자체가 틀렸다.** 녹화본은 영상 내내 2분할이 아니다. 대개 이렇게 흐른다.

```
① 클로드 코드 전체화면  →  ② 2분할  →  ③ 브라우저 전체화면
```

③ 구간에서도 왼쪽을 잘라 PiP 에 넣으니 **코드창 자리에 «브라우저 조각»이 확대돼** 들어갔다.
현님이 보신 것이 그것이다.

실측 (`2. 완성화면_LMS_디럭스_1분.mp4` · 62.3초)

| 구간 | 길이 | 종류 |
|---|---|---|
| 0.2 ~ 7.2초 | 7.5초 (12%) | 코드창 전체화면 |
| 7.7 ~ 23.0초 | 15.5초 (25%) | 2분할 `x=1138` |
| 23.5 ~ 27.2초 | 3.8초 (7%) | 2분할 `x=962` ← 여기서 터미널 폭을 줄였다 |
| 27.7 ~ 62.2초 | 35.0초 (56%) | 브라우저 전체화면 |

### 어떻게 하나 — 잘라서 따로 앉히고 다시 이어 붙인다

`_구간.mjs` 가 0.25~0.5초마다 «열 평균 밝기»로 판정해 구간으로 묶는다.
왼쪽이 어둡고(코드창) 오른쪽이 밝으면(브라우저) 2분할이다. 2분할 안에서도
**분할선이 40px 넘게 바뀌면 거기서 또 자른다** — 그래서 「한 수로는 못 자른다」가 사라졌다.

```
[1:v]split=3[g0][g1][g2]
[g0]trim=0:5.3,setpts=PTS-STARTPTS,format=yuv444p,split=2[m0][k0]      ← 2분할
[m0]crop=1678:2160:1138:0,scale=2160:3300:increase,crop=2160:3300[mm0]
[k0]crop=1138:854:0:1306,scale=1360:1020[kk0]
[mm0][kk0]overlay=400:1330:format=auto,setsar=1[p0]
[g2]trim=9.6:12.0,setpts=PTS-STARTPTS,format=yuv444p,scale=…,crop=…,setsar=1[p2]  ← PiP 없음
[p0][p1][p2]concat=n=3:v=1:a=0[main]
```

| 구간 종류 | 영상 칸 | 코드창 PiP |
|---|---|---|
| **2분할** | 분할선 «오른쪽»만 (코드창은 한 픽셀도 안 잘린다) | **얹는다** |
| 코드창 전체화면 | 통째로 채움 | **안 얹는다** |
| 브라우저 전체화면 | 통째로 채움 | **안 얹는다** |

- ⚠ **`enable=` 로 시간을 재는 길은 안 썼다.** 그러면 모든 사슬이 모든 프레임을 돈다.
  `trim` 은 제 구간 프레임만 지나가므로 한 프레임이 **한 번만** 되크기된다.
- ⚠ `concat` 은 크기·SAR·화소형식이 같아야 한다 → 조각마다 `format=yuv444p,setsar=1`.
  **444 로 두는 까닭**은 4:2:0 간축을 맨 마지막 한 번으로 미루기 위해서다.
- ⚠ 아주 짧은 구간(2점 미만)은 앞 구간에 흡수한다 — 컷마다 짜임이 바뀌면 산만하다.
- **세로판(9:16)만 달라진다.** 가로판(16:9)은 원본이 통째로 들어가므로 구간과 무관하다.

실측 — 프레임 수와 길이가 한 장도 안 어긋난다(361프레임 · 12.033초, 구간 나누기 전과 같다).

## 굽는 사슬 — 옛 것과 무엇이 다른가

```
입력 차례:  0 = 틀 PNG   1 = 마스터.mp4   2 = 마스코트 왕복본   3 = 음악
            ⛔ 번호를 «변수로» 뺀다. 박아 쓰면 안 된다 (§소리 사고)

[0:v]null[bg]                                          ← 틀이 이미 최종 크기. scale 이 없다
[2:v]fps=30,scale=2160:1216:lanczos,crop=2160:540:0:<cy>,setsar=1[band]   ← ⭐ 마스코트 영상
[bg][band]overlay=0:0:format=auto[b0]
[1:v]split=2[a][b]
[a]crop=<브라우저칸>,scale=<칸크기>:increase:lanczos,crop=<칸크기>[main]
[b]crop=<코드창 아래쪽>,scale=<PiP크기>:lanczos[pip]
[b0][main]overlay=<칸자리>:format=auto[t]               ← [bg] 가 아니라 [b0]
[t][pip]overlay=<PiP자리>:format=auto[c]
[c]ass=<제목.ass>:fontsdir=<_폰트/Paperlogy>[p]          ← ⭐ 띠 뒤 · 자막 앞
[p]ass=<자막.ass>:fontsdir=<_폰트/Paperlogy>[s]          ← overlay 뒤 · yuv420p 앞
[s]format=yuv420p[out]
```
출력에 `-t 길이 -r 30 -fps_mode cfr -pix_fmt yuv420p`.

**띠를 여기에 두는 이유 셋** (순서마다 다르다)

1. **`format=yuv420p` 앞** — 4:2:0 간축이 일어나는 자리다. 뒤에 얹으면 마스코트 윤곽이 두 번 뭉갠다
2. **제목 글자 앞** — 띠 영상은 배경이다. 뒤에 얹으면 글자를 덮는다
3. **`[bg][main]` 앞** — 자리가 안 겹치니 그림 결과는 같지만, crop 이 1~2px 어긋나 삐져나와도
   뒤따르는 불투명 overlay 가 덮어 준다. 반대 순서면 삐져나온 띠가 브라우저 위에 남는다

`setsar=1` — 1112×834 · 960×960 을 늘릴 때 SAR 이 딸려 와 overlay 가 어긋나는 것을 막는다.

### ⛔ 소리 사고 — `[2:a]` 를 박아 쓰면 «오류 없이» 틀린다

옛 코드는 음악을 `[2:a]` 로 박아 썼다. 마스코트가 3번째 입력으로 끼어들면
**ffmpeg 은 한 마디도 안 낸다** — 마스코트 mp4 는 11개 전부 `aac/44100/2ch` 이라 `[2:a]` 가 «해결되어»
배경음악 대신 마스코트 소리가 0.12 볼륨으로 섞인다.
→ 입력 번호를 변수로 빼고, **왕복본은 `-an` 으로 만든다**(그러면 실수해도 조용히 넘어가지 않고 죽는다).

`영상만들기.mjs` 에서 고친 것 여덟

| 곳 | 옛것 | 새것 | 왜 |
|---|---|---|---|
| 마지막 `scale` | `[c]scale=출력W:출력H` | **없앰** | 2배 늘림의 자리. 이것 하나가 화소의 3/4 을 버렸다 |
| 자리 찾기 | 네모 «하나» | **둘**(브라우저 46 · PiP 64) | 코드창을 따로 앉히려면 자리가 둘이어야 한다 |
| 자리 판정 색 | `R>=35` | **`R>=8`** + 정확색 우선 | 견본 넷이 `rgb(16,16,16)` 이라 전부 죽고 있었다 |
| 판정 해상도 | 폭 800 으로 줄여서 | **원본 폭 그대로** | 오른쪽·아래에 2px(최종 4px) 검은 실선이 남았다 |
| 틀 입력 | `-loop 1` | **`-loop 1 -framerate 30`** | 30fps 가 25 로 솎였다 되채워졌다. 여섯 장에 한 장이 복사본이었다 |
| overlay | (기본 yuv420) | **`:format=auto`** | 색 간축이 1080 폭에서 벌어졌다 |
| 되크기 | (없음) | **`flags=lanczos`** | 글자 위주 화면에서 남는 정보 +3.6% |
| 소리 | `amix=inputs=2` | **`:normalize=0`** | 말소리가 −6dB 로 깎이고 있었다 |
| 굽기 | `preset medium crf 19` | **`preset slow crf 17 aq-mode=3`** | 글자·가는 선이 먼저 뭉갠다 |

09-03 판 머리말에 「**틀의 배경은 회차마다 업종에 맞는 사진으로 바뀐다**」가 있었다.
띠가 «움직이는 마스코트 영상»이 되면서 그 줄이 통째로 사라졌는데, **사라진 자리에
「이제 안 쓴다」가 안 적혀 있었다.** 그래서 여기에 못 박는다.

| | 09-03 판 | **지금** |
|---|---|---|
| 틀 배경 | 회차마다 업종에 맞는 사진 | **`0x1A1512` 한 가지.** 사진이 없다 |
| 넣는 법 | `node 틀그리기.mjs "회차" --사진 배경.jpg` | **`--사진` 이 없어졌다** (써도 「없어졌습니다」라고 알려 준다). 남은 것은 `--제목` 뿐 |
| 제목 띠 | 사진 위에 글자 | **마스코트 mp4** 를 코드가 골라 얹는다 |

**왜 뺐나** — 띠가 영상이 되면서 사진이 놓일 자리가 사라졌다. 남는 자리를 세어 보면

| 판 | 덮이는 것 | 사진이 보일 수 있는 자리 |
|---|---|---|
| 9_16 | 띠(마스코트 영상) y 0~539 + 브라우저 칸 y 540~3839 | **0 화소.** 화면이 통째로 덮인다 |
| 16_9 | 영상 칸 x 0~2815 + 마스코트 창 x 2816~3839 y 540~2159 | **글자칸 1024×540 하나뿐** — 그런데 그 위에 제목 3줄(잉크 y 185~511)이 앉는다 |

세로판은 아예 안 보이고, 가로판은 «제목 뒤 1024×540» 한 조각만 남는다.
회차마다 업종 사진을 고르고 어둡기를 맞추는 품에 견주면 남는 게 없다.
그래서 「어두운 사진을 고르시라」는 안내도 함께 폐지했다(`_작업흐름.md` 「틀 만들 때 지킬 것」).

⚠ 되살리고 싶으시면 사진이 아니라 **마스코트 영상을 늘리는 쪽**이 맞다 —
`_이미지/마스코트/영상/` 에 mp4 를 넣고 `_마스코트자리.json` 에 한 줄 적으면 후보가 는다.

## 현님이 그리셔야 하는 것 — **없다** (2026-09-04 저녁에 다시 씀)

옛 명세는 여기에 넷을 적어 두었다. **넷 다 코드가 한다.**

| 옛 명세 | 지금 |
|---|---|
| ~~① 업종 사진 제목 띠 (정지 사진으로 시작해도 된다)~~ | ⛔ **틀렸다.** 띠는 정지 사진도 마스코트 PNG 도 아니다. `_이미지/마스코트/영상/*.mp4` 를 코드가 골라 얹는다 → 바로 위 「업종 사진은 이제 안 쓴다」 |
| ~~② 마스코트를 좌표에 맞춰 앉히기~~ | ⛔ **현님이 그리실 것이 아니다.** 영상이라 그릴 수가 없다. `_규격.mjs` 가 좌표를 안다 |
| ~~③ 제목 글자를 틀 그림에 굽는다~~ | ⛔ **PNG 에 구우면 띠 영상이 덮어 지운다.** `제목_*.ass` 로 굽는다 |
| ~~④ 16:9 의 오른쪽 제목 칸~~ | **글자칸 540 + 마스코트 창 1620** 으로 나뉘었다. 둘 다 코드가 채운다 |

`틀그리기.mjs` 가 만드는 틀 PNG 에는 **어두운 네모 둘밖에 없다.**

```
9_16.png   바탕 0x1A1512  +  브라우저 칸 rgb(46,46,46)  +  코드창 PiP rgb(64,64,64)
16_9.png   바탕 0x1A1512  +  영상 칸 rgb(46,46,46)
```

현님이 손대실 수 있는 것은 **브라우저 칸과 PiP 의 자리**뿐이다(코드가 색으로 찾으니까).
띠 자리는 칠하지도, 표시색을 넣지도 마세요 — 코드가 좌표를 알고 영상으로 덮습니다.

### 새 마스코트 영상을 넣으셨을 때

```bash
node 마스코트자리.mjs                     # 확인 그림 → _마스코트자리_확인.png
# 그림을 보고 _마스코트자리.json 에 한 줄 (W H x0 x1 머리 얼굴 띠쓰나)
```

### 이 안이 포기한 것 — 정직하게

1. **쇼파수다·야근은 릴스에서 안 쓴다.** 11개 중 9개만 돈다. 되살리려면 다시 찍어야 한다
2. **가이드보다 띠가 70px 짧다.** 캐릭터가 허리 위에서 끊긴다. 불만 ③ 을 지키려고 낸 값이다
3. **가로판 창은 원본 가로의 35.6% 만 쓰고 ×2.25 로 늘린다.** 3D 클레이라 아티팩트는 없고,
   1080p 배포에서는 ×1.13 이라 사실상 등배다
4. **왕복본 캐시가 새로 생긴다.** 영상당 2~5MB × 9 ≈ 30MB. 마스코트 mp4 를 바꾸면 mtime 으로 저절로 다시 만든다
5. **제목은 9:16 두 줄 · 16:9 세 줄이 상한이다.** 넘으면 멈춘다. 자동으로 작게 줄이지 않는다
6. **자리표를 사람이 한 번 채워야 한다.** 자동검출을 시도했다가 버린 결과다
