# 지킴이를 «창 없이» 돌리는 세 가지 길

| 길 | 언제 도나 | 부담 | 쓸 때 |
|---|---|---|---|
| ⭐ **검수기에서 켜기** | 검수 화면을 **열어 둔 동안만** | 없음 | **평소** |
| 창에 띄우기 | 그 창을 켜 둔 동안 | 창 하나 | 오래 돌릴 때 |
| 작업 스케줄러 | 컴퓨터가 켜져 있는 내내 | 하루 288번 헛돔 | 자리를 비울 때 |

## ⭐ 1. 검수기에서 켜기 (평소엔 이걸로)

1. 이 컴퓨터에서 `npm run dev`
2. `http://localhost:3000/admin/sns` 를 연다
3. **「지킴이 켜기」** 를 누른다 — 30초마다 한 바퀴 돈다
4. **탭을 닫으면 그것으로 끝.** 끄는 걸 잊어도 남는 게 없다

⚠ **배포된 곳(caffeinecolor.com·폰)에서는 단추가 안 먹는다.** 녹화본도 ffmpeg 도
  그 컴퓨터에 없기 때문이다. 그때는 「여기서는 못 돌립니다」라고 적힌다 —
  눌리는데 아무 일도 안 일어나는 것이 제일 나쁘다.

## 2. 창에 띄우기

```bash
npx tsx "판매용_템플릿/_마케팅/_작업/sns지킴이.mts" --지킴이
```

## 3. 작업 스케줄러 (자리를 오래 비울 때만)

`watcher-once.cmd` 를 몇 분마다 실행하게 등록한다. 「한 바퀴 돌고 끝」이라
창이 없어도 되고 컴퓨터를 껐다 켜도 다음 시각에 다시 돈다. 기록은 `watcher.log`.

⛔ **영상은 주에 한두 번인데 5분마다 돌리면 하루 288번이 헛돈다.** 평소엔 1번을 쓴다.

## 4. 구글 드라이브에 «빠진 사본» 채우기 (2026-08-25)

```bash
npx tsx "판매용_템플릿/_마케팅/_작업/sns지킴이.mts" --드라이브채우기
```

**왜 필요한가.** 지킴이는 유튜브에 올린 «사본»을 드라이브에도 넣는다. 그런데
드라이브 복사가 실패해도 **일부러 안 죽는다** — 유튜브에는 이미 올라갔으니
되돌리면 같은 영상을 두 번 올리게 되기 때문이다. 그래서 상태는 「등록완료」로
넘어가고, **다시 채울 기회가 영영 없었다.**

실제로 2026-08-25 에 그랬다. 구글 드라이브 앱이 꺼져 있어 `G:` 가 안 붙었고,
영상9(「내 사이트에는 몇 개의 화면이 필요할까요」)만 드라이브에 안 들어갔다.
사장님이 손으로 찾아내셨다.

**이제 두 가지가 달라졌다.**

1. 드라이브 복사가 빠지면 **검수기 화면(`/admin/sns`)에 남는다** — 「구글 드라이브에
   사본이 안 들어갔습니다」. 창에만 찍히고 사라지지 않는다.
2. 위 명령으로 **빠진 것만** 채운다. 이미 있는 것은 건드리지 않는다.

⚠ **저절로 돌지 않는다 — 일부러 불러야 한다.** 드라이브의 파일 이름은 «그때의 제목»으로
굳는데, 나중에 검수기에서 제목을 고치면 이름이 어긋난다. 이름만 보고 채우면 같은 영상이
**두 벌** 쌓인다. 실제로 4주차 펫유치원이 그 짝이다:

| 어디 | 이름 |
|---|---|
| 드라이브 | AI팩으로 만드니 146개 화면 **목록이 나왔어요** |
| 검수기 | AI팩으로 만드니 146개 화면**이 만들어 졌어요** |

그래서 채우기 전에 **그 폴더에 이미 있는 영상을 다 찍어 보여 준다.** 두 벌인지 눈으로
보고 정한다. `--시늉` 을 같이 주면 무엇을 넣을지만 찍고 아무것도 안 한다.

## ⛔ 「할 일이 없습니다」인데 «실패»로 적히고 있었다 (2026-08-25 고침)

지킴이가 한 바퀴 돌고 나갈 때 **나간 값이 127** 이었다. 하는 일은 다 하고
「할 일이 없습니다」까지 찍고 나서 죽는 것이라 **창에서 볼 때는 멀쩡해 보였다.**
그런데 작업 스케줄러와 루틴은 «나간 값»만 본다 — 헛도는 날마다 «실패»로 적히고 있었다.

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c
```

뿌리는 자식 프로세스(`유튜브있나.mjs`)를 부르고 **바로** 나가는 것이었다.
나가는 길을 `나가기()` 한 군데로 모으고 한 숨 쉬었다 나가게 했다. 세 번 재서 0 을 확인했다.

⚠ **「창에서 멀쩡해 보인다」는 증거가 아니다.** 나간 값을 따로 재야 한다:

```bash
npx tsx "판매용_템플릿/_마케팅/_작업/sns지킴이.mts" --시늉 > /dev/null 2>&1; echo $?
```

## 옮기면서 걸렸던 것 — 다시 겪지 않게

`npx` 를 거치면 창 밖에서 세 번 넘어진다.

1. `spawnSync npx ENOENT` — 창에서는 셸이 `npx.cmd` 를 찾아 주지만 스케줄러엔 셸이 없다
2. `shell: true` 로 고쳤더니 **폴더 이름 「02. 웹기획자」의 빈칸**에서 경로가 잘렸다
3. `npx.cmd` 를 직접 부르니 `EINVAL` — **Node 24 는 보안상 `.cmd` 직접 실행을 막는다**

→ 셋 다 npx 를 거쳐서 난 것이라 **아예 안 거친다.**

```
node --import tsx <스크립트>
```

`node` 는 진짜 실행파일이라 셸도 `.cmd` 도 필요 없다.
`.cmd` 파일 안에는 **한글을 쓰지 않는다** — cmd.exe 가 다른 코드페이지로 읽어 깨진다.
그래서 한글 경로는 `package.json` 의 `sns-watch` 에 두고 `.cmd` 는 영문만 담는다.

## 켜 두면 «어디를 오가도» 안 꺼진다

스위치는 목록 화면이 아니라 **레이아웃**에 붙어 있다. 그래서 목록 ↔ 수정 화면을
오가도 부품이 안 사라지고 30초 시계도 안 멈춘다.

- 켬/끔은 **브라우저가 기억한다.** 새로고침하거나 창을 다시 열어도 켜진 채로 온다
- **도는 중에 창을 닫으려 하면 붙잡는다** — 유튜브에 세로·가로 둘을 올리는 도중에
  끊기면 하나만 올라간다

⛔ 2026-08-18 에 스위치를 목록 화면에만 붙였다가 사장님이 바로 찾아내셨다 —
  「수정화면에 들어가면 지킴이가 꺼지는거 같아」. 검수는 «목록에서 보고 → 들어가서
  고치고 → 나오고»를 되풀이하는 일이라, 제일 많이 오가는 자리에서 꺼지고 있었다.
