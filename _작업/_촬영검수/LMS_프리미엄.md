## 공통 1. 탭·필터 줄에 세로 스크롤바가 생긴다

 **퍼진 곳: 14개 팩 · 74곳**

```css
.tabs      { overflow-x: auto }   /* ⛔ x 만 열면 세로축이 auto 로 딸려 온다 */
.tabs-pill { overflow-x: auto }
```

테두리 1px 때문에 내용이 1px 넘쳐 세로 스크롤바가 뜬다. 탭 옆에 ⬍ 가 보이던 것이 이것이다.

⛔ **뿌리는 우리 생성기의 자기모순이었다.** `lib/design-presets.ts` 가
   규칙에는 「두 축을 다 적는다 — `overflow: auto hidden`」라고 써 두고,
   바로 아래 예시에는 `.table-wrap { overflow-x: auto; }` 를 두었다.
   **AI 는 규칙 문장보다 예시를 베낀다.** 그래서 만들어진 팩이 전부 틀렸다.

→ 고침: 생성기 예시를 `overflow: auto hidden` 으로 바로잡고, 14개 팩 74곳을 바꿨다.

## 공통 2. 푸터가 화면 바닥에 안 붙는다

 **퍼진 곳: 14개 팩 전부**

짧은 화면(결제 동의·완료·빈 목록·오류)에서 푸터가 화면 가운데 떠 있었다.
CO0403 에서 **아래 172px 이 텅 비었다.** 손님은 「덜 만들어진 화면」으로 읽는다.

까다로운 점 — 푸터가 `body` 직계가 아니라 **main 안**에 있다:

```
body > .app-ed > main.edmain > .ft
```

그래서 세 단계를 다 세로 flex 로 잡고, 푸터를 품은 main 의 아래 여백(64px)을 없앴다.
→ 172px → 64px → **0px** 로 두 번에 걸쳐 잡았다. 잰 값으로 확인했다.

## 공통 3. 그리드 칸의 자식이 칸 밖으로 삐져나온다

 **퍼진 곳: 14개 팩 (min-width:0 을 3~17곳 추가)**

그리드·플렉스 자식의 `min-width` 기본값이 `auto` 라, 칸을 340px 로 정해도

## 공통 4. 결제 흐름에 «읽기 폭»이 잘못 걸려 있었다

→ CO04·CO05·CO06(결제·완료·영수증·실패) 아홉 쪽의 `read`·`wrap-narrow` 를 `wrap` 으로 바꿨다.

## ⚠ 내가 만든 회귀 — 고치다 하나 깨뜨렸다

푸터를 바닥에 붙이려고 래퍼를 세로 flex 로 바꿨더니, 그 안의 `main` 이 flex 자식이 되어

→ `width:100%` 를 줘서 되돌렸다. **재서 확인했다 — 812 → 1,440px.**

⭐ 배운 것: **레이아웃 뿌리(display)를 바꾸면 그 아래가 다 흔들린다.**
  고친 화면만 보지 말고 **폭·높이를 다시 재서** 확인해야 한다.

# ✅ 화면목록 깨짐 — 서버를 고쳐서 끝냈다

## 무엇이 일어났나

주소 끝에 빗금이 없으면 브라우저가 마지막 칸을 «파일 이름»으로 본다:

```
/LMS_프리미엄/완성화면   +  assets/css/base.css
→ /LMS_프리미엄/assets/css/base.css            ⛔ 한 칸 위 · 404 · 민얼굴

/LMS_프리미엄/완성화면/  +  assets/css/base.css
→ /LMS_프리미엄/완성화면/assets/css/base.css   ✅
```

## 팩은 멀쩡했다

| 확인한 것 | 결과 |
|---|---|
| 화면 안 링크 `href="../index.html"` | **맞다** — pages/ 에서 한 칸 위를 정확히 가리킨다 |
| 팩에 든 `build/serve.mjs` | `/` → `/index.html` 내부 처리 ✅ |
| README (file:// 로 열기) | 안전 ✅ |
| BOM·깨진 글자 | 14팩 모두 없음 ✅ |

⛔ 문제는 내가 검수용으로 띄운 `npx serve` 였다. `/…/완성화면/index.html` 을
  `/…/완성화면` 으로 **빗금을 «떼면서»** 되돌렸다. 표준 정적 서버는 그 반대로,
  **폴더인데 빗금이 없으면 빗금을 «붙여서»** 되돌려야 한다.

## 고친 것 — `_작업/팩서버.mjs`

```js
if ((await stat(실제)).isDirectory()) {
  if (!길.endsWith("/")) {                                   // 빗금이 없으면
    res.writeHead(301, { location: encodeURI(길) + "/" });   // 붙여서 되돌린다
    return res.end();
  }
  실제 = join(실제, "index.html");
}
```

→ 이제 «빗금 없는 주소» 그대로 넣어도 제대로 뜬다. **확인했다.**

⚠ 나는 처음에 「되돌리지 않게」 만들었는데 **그게 거꾸로였다.**
  되돌리기를 없애면 브라우저가 상대 경로를 잘못 푸는 것은 그대로다.
  서버가 빗금을 붙여 줘야 한다.

```bash
node _작업/팩서버.mjs 4200
```

그런데 **`[hidden]` 은 브라우저 기본값이라 작성자 스타일에 진다.**


### 이게 왜 무서운가

«눌러서 개수를 세어야» 나온다. 내가 첫 바퀴에서 못 잡은 것이 정확히 이 때문이다.

→ 12개 팩에 `[hidden]{display:none !important}` 를 넣었다.
→ 생성기 규칙에도 넣고, **검수 시나리오 7-2 에 「안 줄어들면 열에 아홉은 이것」**으로 원인을 적었다.
→ 눌러서 확인했다 — 「수강 완료 2」에서 목록이 **5개 → 2개**로 줄었다.

사장님이 보신 «CSS 가 하나도 안 붙은 화면목록»은 **내 검수 환경 탓**이었다.

⭐ **검수할 때 주소 규칙** — 반드시 끝에 빗금을 붙인다:

```

http://localhost:4200/<팩>/완성화면/pages/<ID>
```

민얼굴로 뜨면 팩이 깨진 게 아니라 **주소가 잘못된 것**이다.

한 줄이면 끝난다. 그래서 **숫자는 바뀌는데 목록만 그대로**인 화면이 된다.

### 이게 왜 무서운가

**눈으로 보면 절대 안 잡힌다.** 화면을 넘겨 가며 보면 목록이 5개인 게 정상으로 보인다.
«눌러서 개수를 세어야» 나온다. 내가 첫 바퀴에서 못 잡은 것이 정확히 이 때문이다.

→ 12개 팩에 `[hidden]{display:none !important}` 를 넣었다.
→ 생성기 규칙에도 넣고, **검수 시나리오 7-2 에 「안 줄어들면 열에 아홉은 이것」**으로 원인을 적었다.
→ 눌러서 확인했다 — 「수강 완료 2」에서 목록이 **5개 → 2개**로 줄었다.

---
 는 단일 요소를 주므로 `.forEach` 에서 TypeError 가 나 **그 줄부터 죽었다.**
결제 수단을 골라도 아래 단추가 안 바뀌었다.

⭐ **`String.replace` 로 코드를 고칠 때는 `.split().join()` 을 쓴다** — $·# ⛔ 팩만 —·$1 이 특수 표기다.
  이건 이번 세션에서 역슬래시가 먹히던 것과 같은 갈래다.

---
## 공통 7. 한 문장이 두 조각으로 갈려 뒤죽박죽 읽힌다 — ST0401

```css
.list-plain>li{ … display:flex; gap:var(--gap-group)}   /* ⛔ */
```

문장 안에 `<b>` 가 섞이면 **앞뒤 텍스트가 각각 flex 칸**이 되어 gap 만큼 벌어진다.
「미접속 일수만 크게 잡으면 **이미 다 들은 분**도 걸립니다」가
「미접속 일수만 크게  이미 다 들은  도 / 잡으면  분  걸립니다」로 읽혔다.

→ 그냥 문장은 block 으로 두고, **값을 오른쪽에 붙이는 줄에만** `.kv` 로 flex 를 준다.

# ⛔ 팩만 — LMS 숫자·문구 맞추기 (다 잡았다)

## 차시 수 — 30 이 아니라 **18** 이었다

CL0301·ST0301 에 **실제로 그려진 커리큘럼**을 세어 보니 18차시였다:

| 장 | 차시 |
|---|---|
| 1장 데이터를 보는 눈 | 4 |
| 2장 함수로 계산 자동화 | 5 |
| 3장 피벗 테이블 실전 | 5 |
| 4장 보고서로 만들기 | 4 |
| **합** | **18차시 · 295분(4시간 55분)** |

「30차시 · 12시간」은 **지어낸 숫자**였다. 그려진 것이 사실이다.
→ 16쪽의 30차시 → 18차시, 7쪽의 12시간 → 4시간 55분, 진도 40% → **67%**(12/18).
→ CO0302 커리큘럼 탭은 4챕터 × 3차시(=12)로 **덜 그려져** 있어, 18차시를 그대로 옮겨 다시 지었다.

## 나머지 — 값 하나로 통일

| 무엇 | 어떻게 |
|---|---|
| 주문번호 | CO0502 를 완료 화면과 같은 `ORD-20260807-004182` 로 |
| 과제 마감 | 2장 9/10 → **7/27**(이미 지남) · GR0301 채점을 3장 마감 8/10 에 맞춤 |
| 수료 가능 | ST0101 38 → **96** (96+32=128 로 GR0401 이 안에서 맞다) |
| 진도율 | CL0801 96% → **80%** (내 강의실 48/60차시와 같게) |
| 질문 수 | CL0703 「전체 12개」 → **5개** |
| 알림 인원 | ST0501 12명 → **4명** (진도 미달 4명으로 골랐으므로) |
| 쿠폰 이름 | 「신규 가입 20%」 → **「첫 수강 20% 할인」** 으로 통일 |
| 개설 미리보기 값 | 79,200 → **79,000** (판매 화면과 같게) |
| 탭 구성 | CL0102 「만료 1」 → **「전체 5」** |
| 자리표시자 | `N/M차시` → 「연결 5/8차시」 · `N명에게` → 「4명에게」 |
| 「전체인데 12개」 | GR0501 처럼 **「전체 N 가운데 12개만 보여 주는 견본입니다」**를 밝힘 |

## 저절로 풀린 둘

- **AU0301 모순 오류 동시 표시** — 두 오류 모두 `hidden` 이 붙어 있었다. 공통 5([`[hidden]`])가 잡았다.
- **HO0204 잔디 5줄** — CSS 가 `grid-template-rows:repeat(7,12px)` 로 7줄이 맞다. **내가 작은 그림에서 잘못 세었다.**

# ⛔ 팩만 — LMS 만 고치면 되는 것

## 팩 1. 강의 재생 레이아웃이 깨진다 — CL0301 외 (2쪽·4곳)

커리큘럼 사이드바가 영상 위로 겹쳐 있었다. 인라인 스타일이 원인:

```html
<div style="max-height:62vh; overflow-y:auto; margin:calc(var(--card-pad)*-1)">
```

부모 `.card-bd.flush` 는 이미 `padding:0` 인데 **음수 마진을 또 걸었다.**
상쇄할 여백이 없으니 좌우로 24px 씩, 총 48px 이 넓어진다 — 잰 값 338.4 + 48 = **386.4px** 이었다.
거기에 `overflow-y` 만 열어 가로축까지 딸려 왔다.

→ 음수 마진을 빼고 `overflow: hidden auto` 로 바꿨다.
→ 고친 뒤 다시 재니 **칸 밖으로 나간 자식 0개**, 가로 넘침 없음.

⭐ 이 «flush + 음수 마진» 조합 자체는 **공통 규칙**으로 금지에 넣었다.

## ⛔ 고쳐야 할 것

### 1. 같은 강의인데 차시 수가 다르다 — CO0301 ↔ CO0302

| 화면 | 적힌 것 |
|---|---|
| CO0301 강의 상세 | 총 차시 **30차시** · 총 재생 시간 12시간 |
| CO0301 제목 아래 | 박지훈 · **30차시** · 총 12시간 |
| CO0302 커리큘럼 탭 | 전체 **12차시** · 12시간 · 4챕터 |
| CO0302 챕터별 | (3차시) × 4챕터 = **12차시** |

커리큘럼을 펼치면 12차시인데 상세에는 30차시라고 적혀 있다.
손님이 결제 전에 보는 숫자라 그냥 넘길 수 없다.

⭐ **30차시가 맞다 — CL0301 에서 확정됐다.** 30차시는 CO0301·CO0305·CO0306 세 화면에 같이 나오고,
   총 재생 12시간을 30으로 나누면 24분/차시로 그럴듯하다. 12차시면 1시간/차시인데
   CO0305 미리보기의 1차시가 **8:12** 이라 안 맞는다.
   → **커리큘럼 탭(4챕터 × 3차시)이 덜 그려진 쪽**이다.

   ✅ **확정** — CL0301 강의 재생의 커리큘럼 사이드바가 「12/30차시」이고
      1장 4/4 · 2장 5/5 · 3장 3/5 … 로 이어진다. 3장까지만 14차시다.
      **고칠 곳은 CO0302 한 곳**이다.

### 2. 「조건이 없다」면서 「12개」만 보여 준다 — CO0101

한 화면에 이 두 줄이 같이 있다:

- 「1,280개 강의 가운데 지금 조건에 맞는 것은 **12개**예요」
- 「걸린 조건이 **없어요**. 전체를 보고 있습니다」

조건이 없으면 1,280개여야 한다. 견본 데이터가 12개인 것은 알겠는데,
**두 문장이 한 화면에서 서로를 부정한다.**

⚠ 관련해서 숫자 계통이 화면마다 다르다 — CO0102 「전체 12개 중」,
  CO0104 「이 조건이면 14개」, CO0202 「이것만 풀면 2·31·46·18개」.

### 3. 학습 습관 잔디가 5줄이다 — HO0204

「최근 3개월」이라는데 칸이 **13열 × 5행**이다. 요일로 세면 7행이어야 한다.
5행인 까닭이 화면에 안 적혀 있다(주중만 세는 것이라면 그렇게 적어야 한다).


### 4. 조사가 「을(를)」로 나온다 — CO0403

> ⚠ 환불 규정 동의 **을(를)** 아직 채우지 않았어요

항목 이름을 넣어 문장을 만드는 자리인데 조사를 안 고르고 「을(를)」로 뒀다.
받침을 보고 «를» 로 붙여야 한다. 손님에게 바로 보이는 글이다.

### 5. 쿠폰 이름이 화면마다 다르다 — CO0401 ↔ CO0402

| 화면 | 쿠폰 이름 |
|---|---|
| CO0401 결제 | **첫 수강 20% 할인** (79,000 → 15,800 할인) |
| CO0402 쿠폰 목록 | **신규 가입 20% 할인** (~2026-08-31, 사용 가능) |

같은 쿠폰으로 보이는데 이름이 둘이다. 손님은 다른 쿠폰인 줄 안다.


### 6. 같은 주문인데 주문번호가 다르다 — CO0501 ↔ CO0502

| 화면 | 주문번호 |
|---|---|
| CO0501 수강 신청 완료 | **ORD-20260807-004182** |
| CO0502 영수증 (완료 화면에서 「영수증 보기」로 들어감) | **20260809-004821** |

접두사(ORD-)도, 날짜(0807 ↔ 0809)도, 뒷번호(004182 ↔ 004821)도 다르다.
바로 이어지는 두 화면이라 손님이 나란히 본다.

⭐ 금액은 맞다 — 132,000 − 53,000(상시) − 15,800(쿠폰) = **63,200** ✓ 두 화면 모두 같다.

### 7. 조사가 「(으)로」로 나온다 — CO0601

> 단추: **신용카드 (으)로 다시 시도**

4번(CO0403 「을(를)」)과 같은 계통이다. 결제 수단 이름을 넣어 단추 글을 만드는데
받침을 안 보고 「(으)로」를 그대로 뒀다. **조사 붙이는 자리를 한 번에 훑어야 한다.**

⚠ CO0603 에도 비슷한 것이 있다 — 「엑셀로 시작하는 실무 데이터 분석 **은** 2026년…」
  처럼 강조 뒤에 조사가 띄어져 붙는다.


### 8. ⛔⛔ 거르는 단추가 목록을 안 줄인다 — CL0101

「수강 중 **3**」 탭이 골라져 있고 「지금 **3개** 강의를 보고 있어요」라고 적혀 있는데,
**목록에는 5개가 다 보인다** — 수강 중 3개(엑셀·영어회화·피그마)에
수강 완료 2개(SQL·재테크)까지 그대로 있다.

이건 우리가 검수 시나리오 7-2 에 「거르는 단추는 «목록이 실제로 줄어야» 합니다」로
못박아 둔 바로 그것이다. **팩 안에서 그 규칙이 깨져 있다.**

### 9. 같은 화면인데 탭 구성이 다르다 — CL0101 ↔ CL0102

| 화면 | 탭 |
|---|---|
| CL0101 | 수강 중 3 · 수강 완료 2 · **전체 5** |
| CL0102 | 수강 중 3 · 수강 완료 2 · **만료 1** |

3+2 = 5 이므로 「전체 5」가 맞다. 「만료 1」이면 전체가 6이어야 하는데 그런 강의가 없다.
같은 내 강의실인데 세 번째 탭이 화면마다 다르다.


### 10. 「마감된 과제」인데 마감일이 미래다 — CL0601

- 화면 위: 「제출 기간이 종료된 과제예요 · 마감 **2026년 9월 10일** 23:59」
- 같은 화면 아래: 「다음 기회 — 3장 과제가 **8월 10일**에 마감됩니다」
- CL0501(3장 과제): 마감 **2026년 8월 10일** · 남은 시간 3일 8시간
- TC0101: 「오늘은 **2026년 8월 7일**이에요」

2장 과제 마감이 9월 10일이면 **아직 안 왔는데 종료됐다**고 한다.
게다가 뒤에 오는 3장 과제(8/10)보다 늦다. **8월 이전 날짜여야 한다.**

### 11. 같은 강의 진도율이 다르다 — CL0101 ↔ CL0801

| 화면 | 하루 20분 비즈니스 영어 회화 |
|---|---|
| CL0101 내 강의실 | 48/60차시 · **80%** |
| CL0801 수료증 발급 | 진도율 80% 이상 — 지금 **96%** |

96%면 60차시 중 57.6차시다. 48차시가 아니다.

### 12. 질문 수가 다르다 — CL0701 ↔ CL0703

- CL0701 질문 게시판: 「전체 **5**」
- CL0703 미답변만 보기: 「필터를 풀면 전체 **12개**를 보실 수 있습니다」

### 13. 자리표시자 「N/M」이 그대로 나온다 — CU0401

화면 맨 아래:

> 연결하면 위 요약의 **N/M차시**가 함께 올라갑니다

숫자를 넣어야 할 자리에 `N/M` 이 그대로 있다. 같은 화면 위쪽은 「연결 **5/8**차시」로
제대로 채워져 있으니, 이 한 줄만 빠뜨린 것이다.

### 14. 40% 할인 값이 화면마다 다르다 — CU0201 ↔ 나머지

| 화면 | 값 |
|---|---|
| CU0201 강의 개설 미리보기 카드 | **79,200원** (132,000 의 정확히 60%) |
| CO0301·CO0102·CO0401·CO0502 | **79,000원** |

132,000 × 0.6 = 79,200 이라 CU0201 이 «계산상» 맞고,
79,000 은 132,000 − 53,000(상시 할인)이라 «영수증상» 맞다.
어느 쪽이든 **한 값으로 맞춰야 한다** — 손님이 개설 화면과 판매 화면을 같이 본다.

⚠ 가볍게: CU0101 에서 「기획자를 위한 SQL 첫걸음」이 **검수 대기**인데 수강생이 **246명**이다.
  CL0101·CL0102 에서는 이미 수료까지 한 강의다. 재검수 중이라면 그렇게 보이게 해야 한다.

### 15. ⛔ 글자가 서로 겹쳐 읽을 수 없다 — ST0401

오른쪽 「기준을 어떻게 잡을까요」 상자의 셋째 줄:

> · 미접속 일수만 크게   **이미 다 들은**  도
> 잡으면                          **분**        **걸립니다**

왼쪽 설명과 오른쪽 값이 두 칸으로 갈리면서 글자가 뒤섞였다.
원문은 「미접속 일수만 크게 잡으면 이미 다 들은 분도 걸립니다」로 보인다.
**한 문장을 두 칸짜리 표에 넣어서 생긴 일이다.** 이 줄만 한 칸으로 빼야 한다.

### 16. 「전체」인데 128명 중 12명만 보인다 — ST0101

- 지표: 「전체 수강생 **128명**」
- 탭: **전체** 가 골라져 있음
- 목록 위: 「지금 **12명**을 보고 있어요」

2번(CO0101)과 같은 모양이다. **거르기를 안 걸었는데 목록이 줄어 있다.**

### 17. 받는 사람 수가 앞뒤로 안 맞는다 — ST0401 → ST0501 → ST0503

| 화면 | 사람 수 |
|---|---|
| ST0401 진도 미달자 | 이 기준에 걸린 사람 **4명** (목록도 4명 ✓) |
| ST0501 알림 발송 | 「**12명**에게 보냅니다」 · 배지는 「진도 미달 조건으로 고름」 |
| ST0503 발송 결과 | 보낸 사람 **23명** (도착 14 + 실패 9 ✓) |

진도 미달로 골랐다면서 4 → 12 → 23 으로 늘어난다.

⚠ 가볍게: ST0201 은 화면 맨 위 큰 제목이 위로 잘린 채 뜬다. 스크롤 자리 문제일 수 있으니
  촬영본에서 다시 확인한다.

### 18. 같은 과제인데 마감일이 다르다 — CL0501 ↔ GR0301

「3장 과제 — 부서별 실적 대시보드」 하나인데:

| 화면 | 마감 |
|---|---|
| CL0501 과제 제출 | 2026-08-10 23:59 (남은 시간 3일 8시간) |
| GR0301 채점 상세 | 2026-08-05 23:59 (제출 08-06 09:02 → 지각) |

10번(CL0601)과 같은 계통이다. **과제 마감일을 한 군데서 정해 쓰지 않고 있다.**

### 19. 수료 가능 인원이 다르다 — ST0101 ↔ GR0401

| 화면 | 수료 가능 | 진도 미달 |
|---|---|---|
| ST0101 수강생 목록 | **38명** | 32명 |
| GR0401 수료 기준 설정 | **96명** (전체 128 중 75%) | 32명 |

미달 32명은 같은데 수료 가능이 38 ↔ 96 이다. 96 + 32 = 128 이라 GR0401 은 안에서 맞고,
ST0101 은 38 + 32 = 70 으로 128 에 한참 못 미친다.

### 20. 조사 「을(를)」이 로그인에도 있다 — AU0101

> ⚠ 이메일 · 비밀번호 **을(를)** 아직 채우지 않았어요

CO0403 과 **똑같은 문구**다. 4번·7번과 묶어 한 번에 고친다.
→ 조사 자리 세 곳: **CO0403(을/를) · CO0601((으)로) · AU0101(을/를)**

### 21. 서로 어긋나는 오류가 한꺼번에 뜬다 — AU0301

휴대폰 인증 화면에 이 둘이 «같이» 떠 있다:

> ⚠ 인증번호가 맞지 않아요. 다시 확인해 주세요
> ⚠ 시간이 지났어요. 인증번호를 다시 받아 주세요

게다가 위에는 「남은 시간 **2:57**」이 아직 돌고 있다. 시간이 안 지났는데 지났다고 한다.
견본이라 두 문구를 다 보이려 한 것 같은데, **손님 눈에는 앞뒤가 안 맞는 화면**이다.
둘 중 하나만 뜨게 하거나, 「이 화면은 두 경우를 겹쳐 보여 줍니다」라고 적어야 한다.

## ⭐ 고치는 방향이 이미 팩 안에 있다 — GR0501

GR0501 수료 처리 화면 맨 아래에 이렇게 적혀 있다:

> 명단은 전체 128명 가운데 **12명만 보여 주는 견본입니다**

**2번(CO0101)·16번(ST0101)이 딱 이 한 줄이 없어서 생긴 일이다.**
견본 데이터가 적은 것은 흠이 아니다. 흠은 «전체를 보고 있다»고 말해 놓고 12개만 보여 주는 것이다.
GR0501 처럼 적으면 두 건이 한 번에 풀린다.
