# ⛔ 고친 것 — 열두 갈래

## 1. 단계표의 인원 구간이 «한 칸씩» 밀려 있었다 — 20쪽

**퍼진 곳: 디럭스 4쪽 · 프리미엄 16쪽**

상세 화면에서 이렇게 나왔다:

```
247명 참여 중 · 목표 300명

  50명~   ✓ 달성      32,000원
 150명~   ✓ 달성      28,000원
 250명~   지금 이 단계  24,900원   ← 247명인데 250명 단계에 서 있다
 400명~   아직        21,900원

다음 단계까지 3명 남았어요. 250명이 되면 24,900원 → 21,900원이 됩니다.
                                    ↑ 표에서는 250명이 24,900원인데
```

**한 화면 안에서 세 문장이 서로 다른 말을 했다.**

⭐ **팩이 스스로 답을 세 군데에 적어 두고 있었다.**

| 어디 | 무엇이라 적혀 있나 |
| --- | --- |
| 결제(JO-02) | 「250명이 모이면 **3,000원** 더 싸집니다」 → 24,900 − 3,000 = **21,900** |
| 상세(DE-01) | 「3명 남았어요. **250명**이 되면 24,900 → 21,900」 (247명) |
| 다음단계 도달(DE0105) | 「**250명을 넘겼습니다** … 21,900원이 적용됐습니다」 (250명) |

→ 250명 = 21,900원 단계다. 그러면 24,900원 단계의 문턱은 **247 이하**여야 한다.
→ 구간을 `50 / 150 / **200** / **250**` 으로 내렸다. **글 한 줄도 안 고치고 위 세 문장이 전부 맞는다.**

⛔ 값(24,900·21,900)이나 인원(247)을 고치지 않았다. 24,900원은 홈 히어로·목록·상세에
**38곳**, 247명은 **34곳**에 박혀 있다. 틀린 것은 «구간 이름» 넷뿐이었다.

⚠ 건드리지 않은 표 셋 — DE-03·DE0301(다른 상품의 3구간)과 HS0202(진행자가 «만드는» 5구간 화면,
0명이라 50명~ 이 켜진 것이 맞다).

## 2. 타임라인 점이 «두 겹»으로 찍혔다 — 147곳

**퍼진 곳: 디럭스 32곳 · 프리미엄 115곳 (공동구매 두 팩만)**

```css
.tl-item::before{ … width:14px;height:14px;border-radius:50%; … }   /* CSS 가 동그라미를 그린다 */
```
```html
<div class="tl-item"><span class="ok">✓</span> …                     <!-- 그런데 글자로 또 그렸다 -->
```

**게다가 `done`/`wait` 클래스를 162곳 중 하나도 안 붙였다.** 그래서 완료·지금·아직이
전부 같은 빈 동그라미였다 — 어디까지 왔는지 점만 봐서는 알 수 없었다.

→ 글자 마커를 빼고 상태를 클래스로 옮겼다: `✓`→`done` · `●`→(기본, 지금) · `○`→`wait`.
→ **다른 다섯 업종은 처음부터 이렇게 하고 있었다.** 공동구매만 어긋나 있었다.

## 7. 참여자 줄의 점이 앞 글자를 물었다 — DE-01·DE0101·DE0105·DE0106

「지금 참여하고 있어요」는 **가로로** 흐르는 줄(`.ticker`)인데 그 안에 **세로** 타임라인 항목
(`.tl-item`)을 썼다. `.tl-item::before{left:-21px}` 는 세로 타임라인의 왼쪽 여백에 점을 찍으라는
뜻이라, 가로로 늘어놓으면 그 −21px 이 **앞 항목의 글자 위**로 간다.

```
전 : ○ 김*연님이 5kg 1개 참○ 이*훈님이 10kg 1개 참○ 박*지님이 …     ← 「여」가 점에 먹혔다
후 : ○ 김*연님이 5kg 1개 참여   ○ 이*훈님이 10kg 1개 참여   ○ …
```

⚠ **여백만 줘서는 안 고쳐진다.** `padding-left:21px` 를 줘도 점은 여전히 테두리 «밖»(−21px)에
있다. 점 자리 자체를 안으로 들여야 한다 — `.ticker .tl-item::before{left:0}`.
한 번 헛디디고 재 보고 나서야 알았다.

⭐ **2번(마커 두 겹)을 고치기 전에는 이게 안 보였다.** 점이 두 개라 「점 두 개인 디자인」처럼
보였는데, 글자 마커를 걷어내니 CSS 점이 옆 글자를 물고 있는 것이 드러났다.

→ `레이아웃검사.mjs` 에 **⑤ CSS 점이 글자를 덮음** 검사를 넣었다.
   ④ 글자 겹침으로는 못 잡는다 — 의사요소는 DOM 에 없어서 사각형을 견줄 수가 없다.

## 13. 눌러도 목록이 안 줄어들던 것 — 거르기 엔진을 붙였다

공동구매 두 팩은 탭 33/33 · 칩 48/48 이 «밑줄만» 옮기고 아무것도 거르지 않았다.
LMS 프리미엄의 거르기 엔진을 옮겨 붙이고, 카드마다 꼬리표를 달았다.

| 화면 | 무엇이 도나 |
| --- | --- |
| `HO-02`·`HO0201~0204` 공구 목록 | 카테고리 탭 9 · 칩 3 · 검색 · 정렬 4가지 · 「N개 보임」 · 「더 보기」 |
| `HO-03`·`HO0301~0303` 마감 임박 | 칩 3 (오늘 마감 · 1시간 내 · 한 명만 더) |
| `MY-01`·`MY0101~0102` 내 공구함 | 탭 5 (진행 중 · 성사 · 불발 · 배송·완료 · 전체) |

**꼬리표는 카드에 이미 적힌 것에서만 뽑았다.** 「⏱ 21분 남음」에서 남은 분을,
달성률 막대에서 %를, 배지에서 할인율을 읽었다. 지어낸 값은 없다.

⭐ **무료배송은 «보이게» 했다.** 안 보이는 조건으로 목록이 줄면 손님은 왜 줄었는지 모른다.
   꼬리표를 단 카드에는 「무료배송」 배지를 함께 붙였다.

**눌러 본 결과** — 전체 8개 → 뷰티 1개 → 마감 임박 5개 → +무료배송 3개 → 초기화 8개.
「마감 임박순」으로 놓으면 21분 → 42분 → 1시간 36분 순으로 실제로 다시 늘어선다.

⚠ **세 번 걸렸다. 셋 다 나 때문이다:**

| 무엇 | 왜 |
| --- | --- |
| 칩을 눌러도 0개 | 꼬리표를 띄어쓰기로 쪼개는데 값에 공백을 넣었다 — `st:마감 임박` 이 `st:마감` 과 `임박` 으로 갈렸다 |
| 「더 보기」가 안 감춰짐 | `String.replace` 의 «바꿀 글»에서 `$$` 는 달러 하나로 줄어든다. `$$(…)` 가 `$(…)` 가 되어 forEach 가 없어졌다 |
| 칩 둘을 걸면 «둘 중 하나» | 셋 다 같은 갈래(`st`)라 OR 이었다. 갈래를 따로 주니 «둘 다»(AND)가 됐다 |

⛔ **조건이 걸리면 「더 보기」를 감춘다.** 견본 여덟 개만 들고 있으면서
   「뷰티 120개 남음」이라고 하면 손님이 속는다.

## 14. 옵션 웃돈을 매출에 넣었다 — 14쪽 58곳

`SE-03` 표가 자기 합계와 3,063,600원 어긋나 있었다. 까닭은 매출·결제액이 전부
「인원 × 기본가」로만 계산돼 있었기 때문이다. **참여자가 실제로 낸 돈이 진행자의 매출이다** —
6개입을 82,800원에 산 74명의 돈이 빠질 까닭이 없다. 팩도 표에는 82,800원을 적어 두었다.

| 무엇 | 전 | 후 | 어떻게 셌나 |
| --- | --- | --- | --- |
| 앰플 매출 | 20,120,400 | **23,184,000** | 412×41,400 + 74×82,800 |
| 앰플 수수료 | 1,005,020 | **1,159,200** | 매출 × 5% |
| 앰플 정산(요약/상세) | 18,991,180 / 18,890,806 | **21,900,600 / 21,800,226** | 수수료·환불·알림톡·쿠폰을 뺀 값 |
| 한라봉 결제액 | 6,150,300 | **7,426,300** | 189×24,900 + 58×46,900 |
| 한라봉 예상 수수료 | 307,515 | **371,315** | 결제액 × 5% |

⭐ **덤으로 하나 더 나왔다** — 「정산 예정 2,250만원」이 원래부터 어느 값과도 안 맞았다.

**값은 하나도 지어내지 않았다.** 전부 팩에 적힌 건수·단가에서 다시 셌고,
정산 표(매출−수수료−환불=순정산)와 차감 항목(다섯 줄의 합)이 맞는지 기계로 확인했다.

## 16. 장비렌탈 PD0201 — 겹친 게 아니라 «갈린» 것이었다

내 검사가 「32,000 ✕ 원 / 1일」을 겹쳤다고 했는데, 열어 보니 겹친 게 아니라
「32,000원 /」 + 「1일」로 **줄이 갈린** 것이었다. 값과 단위 사이를 끊으면
값이 「32,000원 /」로 읽힌다.

→ 화면: `.price .u{white-space:nowrap}` (뷰티샵·장비렌탈 네 팩)
→ 검사: `getBoundingClientRect`(합친 상자) 대신 `getClientRects`(줄 상자)로 견준다.
   여러 줄로 흐른 글은 «합친 상자»가 왼쪽 끝까지 늘어나 옆 글자를 덮은 것처럼 보인다.

## 17. 매칭 AU0302 — 인증번호 칸이 카드를 뚫고 나갔다

`.otp span` 은 46×56 으로 꾸며 두었는데 이 화면만 `<input class="otp-cell">` 을 썼다.
CSS 가 없으니 flex 칸 여섯 개가 각각 **170px** 로 늘어나 카드 밖으로 나가고
화면에 가로 스크롤바가 생겼다.

→ 마크업은 그대로 뒀다 — 오류 상태는 «다시 쳐 넣는» 자리라 input 이 맞다.
   `.otp .otp-cell` 에 같은 모양을 입혔다. 46×56 여섯 칸으로 돌아왔다.
