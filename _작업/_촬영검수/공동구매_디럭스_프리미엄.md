# ⛔ 고친 것 — 열두 갈래

## 1. 단계표의 인원 구간이 «한 칸씩» 밀려 있었다 — 20쪽

**퍼진 곳: 디럭스 4쪽 · 프리미엄 16쪽**

상세 화면에서 이렇게 나왔다:

```
247명 참여 중 · 목표 300명

  50명~   ✓ 달성      32,000원
 150명~   ✓ 달성      28,000원
 250명~   지금 이 단계  24,900원   ← 247명인데 250명 단계에 서 있다
 400명~   아직        21,900원

다음 단계까지 3명 남았어요. 250명이 되면 24,900원 → 21,900원이 됩니다.
                                    ↑ 표에서는 250명이 24,900원인데
```

**한 화면 안에서 세 문장이 서로 다른 말을 했다.**

⭐ **팩이 스스로 답을 세 군데에 적어 두고 있었다.**

| 어디 | 무엇이라 적혀 있나 |
| --- | --- |
| 결제(JO-02) | 「250명이 모이면 **3,000원** 더 싸집니다」 → 24,900 − 3,000 = **21,900** |
| 상세(DE-01) | 「3명 남았어요. **250명**이 되면 24,900 → 21,900」 (247명) |
| 다음단계 도달(DE0105) | 「**250명을 넘겼습니다** … 21,900원이 적용됐습니다」 (250명) |

→ 250명 = 21,900원 단계다. 그러면 24,900원 단계의 문턱은 **247 이하**여야 한다.
→ 구간을 `50 / 150 / **200** / **250**` 으로 내렸다. **글 한 줄도 안 고치고 위 세 문장이 전부 맞는다.**

⛔ 값(24,900·21,900)이나 인원(247)을 고치지 않았다. 24,900원은 홈 히어로·목록·상세에
**38곳**, 247명은 **34곳**에 박혀 있다. 틀린 것은 «구간 이름» 넷뿐이었다.

⚠ 건드리지 않은 표 셋 — DE-03·DE0301(다른 상품의 3구간)과 HS0202(진행자가 «만드는» 5구간 화면,
0명이라 50명~ 이 켜진 것이 맞다).

## 7. 참여자 줄의 점이 앞 글자를 물었다 — DE-01·DE0101·DE0105·DE0106

「지금 참여하고 있어요」는 **가로로** 흐르는 줄(`.ticker`)인데 그 안에 **세로** 타임라인 항목
(`.tl-item`)을 썼다. `.tl-item::before{left:-21px}` 는 세로 타임라인의 왼쪽 여백에 점을 찍으라는
뜻이라, 가로로 늘어놓으면 그 −21px 이 **앞 항목의 글자 위**로 간다.

```
전 : ○ 김*연님이 5kg 1개 참○ 이*훈님이 10kg 1개 참○ 박*지님이 …     ← 「여」가 점에 먹혔다
후 : ○ 김*연님이 5kg 1개 참여   ○ 이*훈님이 10kg 1개 참여   ○ …
```

⚠ **여백만 줘서는 안 고쳐진다.** `padding-left:21px` 를 줘도 점은 여전히 테두리 «밖»(−21px)에
있다. 점 자리 자체를 안으로 들여야 한다 — `.ticker .tl-item::before{left:0}`.
한 번 헛디디고 재 보고 나서야 알았다.

⭐ **2번(마커 두 겹)을 고치기 전에는 이게 안 보였다.** 점이 두 개라 「점 두 개인 디자인」처럼
보였는데, 글자 마커를 걷어내니 CSS 점이 옆 글자를 물고 있는 것이 드러났다.

→ `레이아웃검사.mjs` 에 **⑤ CSS 점이 글자를 덮음** 검사를 넣었다.
   ④ 글자 겹침으로는 못 잡는다 — 의사요소는 DOM 에 없어서 사각형을 견줄 수가 없다.

## 옵션 웃돈이 매출에 한 번도 안 들어갔다

`SE-03` 정산 상세의 「매출 구성」 표가 **자기 합계와 안 맞는다**:

```
기본 (3개입)      412건 × 41,400원 = 17,056,800원
추가 구성 (6개입)   74건 × 82,800원 =  6,127,200원
취소·환불          −3건            =   −124,200원
─────────────────────────────────────────────
행을 더하면                          23,059,800원
그런데 적힌 합계는                    19,996,200원   ← 3,063,600원 모자란다
```

까닭을 따라가 보니 **매출·결제액이 전부 «인원 × 기본가» 로만 계산돼 있다.**

| 어디 | 적힌 값 | 옵션까지 넣으면 | 차 |
| --- | --- | --- | --- |
| SE-03 앰플 매출 | 20,120,400원 (= 486 × 41,400) | 23,184,000원 | 3,063,600원 |
| HM-02 한라봉 총 결제액 | 6,150,300원 (= 247 × 24,900) | 7,426,300원 (10kg 58건 × +22,000) | 1,276,000원 |

**왜 안 고쳤나** — 답이 둘인데 둘 다 파장이 크다:

- **웃돈을 매출에 넣는다** → 매출·수수료·정산 예정액·대시보드 매출을 여러 화면에서 다시 계산해야 한다
- **웃돈을 빼고 표를 총 매출에 맞춘다** → 「추가 구성 74건」 행이 사라져 옵션별 매출을 못 보여 준다

**어느 쪽이 맞는지는 «옵션 웃돈을 진행자 매출로 볼 것인가»** 라는 장사 판단이라 제가 정할 일이 아닙니다.
정해 주시면 그대로 맞추겠습니다.

⚠ 다만 **SE-03 표가 자기 합계와 안 맞는 것**만은 어느 쪽으로 정하든 고쳐야 합니다.

## 눌러도 목록이 안 줄어든다 — **14개 팩 전체**

공동구매 목록의 카테고리 탭(뷰티·유아·육아…)을 눌러 보면 **밑줄만 옮겨 가고 목록은 한 글자도
안 바뀐다.** 칩도 켜졌다 꺼졌다 할 뿐 아무것도 거르지 않는다.

까닭은 LMS 때와 다르다. 그때는 엔진이 돌았는데 `[hidden]` 이 CSS 에 져서 안 보였다(한 줄로 고쳤다).
**여기는 엔진 자체가 없다.** `app.js` 의 `.tab` 처리는 `data-pane` 이 있을 때만 무언가를 바꾸는데,
목록의 탭에는 그것이 안 붙어 있다. 칩 처리는 `classList.toggle('on')` 한 줄이 전부다.

**공동구매만의 일이 아니다.** 14팩을 다 세어 봤다:

| 팩 | 안 도는 탭 | 안 도는 칩 | 걸린 쪽 |
| --- | --- | --- | --- |
| **공동구매 디럭스** | **33 / 33** | **48 / 48** | 16 |
| **공동구매 프리미엄** | 65 / 141 | **175 / 175** | 47 |
| 매칭 프리미엄 | 40 / 48 | 179 / 189 | 42 |
| 여행 프리미엄 | 68 / 194 | 93 / 112 | 31 |
| 뷰티샵 프리미엄 | 18 / 66 | 163 / 163 | 27 |
| 장비렌탈 프리미엄 | 16 / 62 | 98 / 104 | 23 |
| 인테리어 프리미엄 | 45 / 81 | 79 / 79 | 19 |
| LMS 프리미엄 | 28 / 123 | 35 / 108 | 20 |
| LMS 디럭스 | **0 / 53** | 13 / 47 | 2 |

**LMS 디럭스만 탭이 전부 돈다** — 8/19 검수 때 붙인 것이다.
LMS 프리미엄의 `app.js` 에는 쓸 만한 엔진이 이미 들어 있다
(`data-list` / `data-tags` / `data-fgroup` / `data-f` / `data-v` — 거르기·정렬·검색을 다 한다).

**할 일은 «엔진을 옮기는 것»이 아니라 «카드마다 꼬리표를 붙이는 것»이다.**
엔진은 복사하면 되고, 목록 카드에 `data-tags="cat:뷰티 st:임박"` 같은 표시를 달아야 한다.
공동구매 두 팩만 해도 63쪽이다. **검수에서 그 자리에 고칠 크기가 아니라 따로 잡아야 할 일**이라
오늘은 손대지 않고, 대신 **거짓말만 걷어냈다**(위 6번 — 걸지도 않은 조건을 걸었다고 하던 것).

> 검수 시나리오 7-2 「눌러도 아무 일 없는 것이 0개」가 바로 이 항목이다.
> 손님이 스펙팩을 받아 AI 에게 시키면 AI 는 이 검사를 하게 되어 있는데, **우리 팩이 못 지키고 있다.**

## 사진이 상품과 안 맞는다

한라봉 상세에 참기름병·빵·립스틱이 걸려 있다. 「예시 이미지 · 바꿔 넣으세요」 띠가 붙어 있어
일부러 그런 것으로 보이지만, **한 상품의 상세 석 장이 서로 다른 업종**인 것은 촬영에 좋지 않다.
`사진바꾸기.csv` 로 맞출 수 있는지 확인이 필요하다.
