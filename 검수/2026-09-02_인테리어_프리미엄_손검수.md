## B · 탭·칩 — 눌러도 아무 일이 없던 것

**뿌리 원인은 하나다.** 탭·칩이 «켜진 표시»만 바꾸고 내용은 그대로였다.
`check-반응` 은 `on` 클래스가 붙는 것도 «반응»으로 세기 때문에 구조적으로 못 잡는다.
그래서 손으로 눌러 봐야 나왔다.

고친 방식 — 화면마다 따로 코드를 쓰지 않고 **거르기 하나**를 만들어 `app.js` 에 넣었다.

```
칩·탭에   data-filter="이름"
담는 칸에 data-filter-in="이름"
줄마다    data-tag="값"
전체 칩에 data-filter-all
빈 자리에 data-filter-empty
셈하는 칸 data-filter-count="이름"
```

- **탭 75/75** 가 이제 실제로 칸을 바꾼다.
- **칩 58/69.** 남은 11개는 «고르는» 칩이라 거르는 것이 아니다
  (AU0401 관심분야·받을방법, HO0101 평수, OW0501 현장 이름).

### 데이터가 없는 자리는 «만들지 않았다»

없는 것을 지어내면 손님이 그대로 판다. 대신 **견본이라고 밝혔다.**

| OW0501 | 현장 칩이 여럿인데 청구 자료는 한 현장뿐 | 한 현장짜리라고 밝히는 글 |
| OW0101 · OW0601 · PR0101 | 주/월 탭인데 주별·월별 자료가 없다 | 견본 표시 |

## C · 굽는 코드에 안 넣어 날아간 것 — 두 번

**아침에 고친 HO0101 평수 칩이 오후에 사라졌다.** `pages/HO0101.html` 만 고쳐 뒀는데
`node build/generate.mjs` 가 207장을 새로 쓰면서 통째로 지웠다.
이 저장소가 이미 적어 둔 함정이다 — 「pages/*.html 만 고쳤으면 다음에 굽는 순간 사라진다」.
**그 글을 읽고도 같은 실수를 했다.** `check-헛선택자` 가 잡아 줬다.

되살리면서 `build/pages-ho.mjs` 에 넣었다. 함께 나온 것:

- `U.banner` 에 속성을 달 자리가 없어 `data-from-home` 이 조용히 버려지고 있었다.
  `pages-es.mjs` 는 넘기고 있었는데 `ui.mjs` 가 받지 않았다. `btn`·`chip` 처럼 `o.attr` 을 받게 했다.
- `data-proc-chip` 손잡이가 찌꺼기로 남아 있었다 — 내가 `data-filter="자재공정"` 으로 갈면서 버려 둔 것.

**두 번째로 날린 것 — 예시 사진 34곳.** 화면을 다시 구우니 `data-예시` 태그가 전부 사라졌다.
사진 42장은 폴더에 그대로 있는데 화면이 안 부른다 — 손님은 회색 네모만 본다.
`check-zip` 이 「예시 사진 42장이 들어 있는데 화면에서 쓰지 않습니다」로 잡았다.
`npx tsx 이미지-끼우기.mts 인테리어_프리미엄` 를 다시 돌려 되살렸다.

> ⚠ **`node build/generate.mjs` 를 돌린 뒤에는 `이미지-끼우기.mts` 를 반드시 다시 돌린다.**
> 굽기는 자리표만 만들고, 사진은 그 뒤에 얹는 것이다.

## D · 32칸이 «옛 검수 글»을 팔고 있었다

오늘 `lib/export/화면검수-글.ts` 에서 헛짚음 셋을 고쳤다(빵부스러기를 위 메뉴로 본 것 등).

본다. 검수 글은 아예 안 본다. 손으로 zip 을 열어 보다가 걸렸다.

**`check-zip.mts` 에 `굽힌글맞나()` 를 넣었다.** 07·11 에 담긴 검수 글을 지금 코드와
**통째로** 견준다. 한 줄만 달라도 잡는다.

> ⚠ 처음에는 «긴 줄 셋»만 뽑아 견주게 만들었다. 일부러 옛말을 심어 시험해 보니

## ⑫ 평당 단가 — 뿌리가 여기였다

같은 32평 전체 시공인데 화면마다 값이 달랐다.

| 어디 | 32평 | 평당 |
|---|---|---|
| ES0101 견적 마법사 | 2,400만~3,100만 | **75만** ⛔ |
| ES0201 · CT0101 · HO0301 머리말 | 3,240만~3,410만 | 101만 |
| HO0201 · HO0301 등급표 | — | **210~340만** ⛔ |

⛔ 210만원 × 32평 = **6억 7,200만원**이다. 바로 위 머리말이 3,240만원이라고 적어 둔
같은 화면에서다. 그리고 그 값이 **HO0201 과 HO0301 두 곳에 손으로** 적혀 있었다.

**`data.mjs` 에 `PRICING` 을 두고 한 곳에서만 정한다.** 새 숫자는 하나도 안 지었다 —
팩이 이미 가진 `FLAGSHIP`(32평 · 전체 시공 · 고급)에서 나눈다.

```
평당(고급) = FLAGSHIP.totalFirst / FLAGSHIP.area = 1,012,500원
등급배 = { 기본 1, 고급 1.22, 프리미엄 1.48 }   ← ES0201 이 이미 쓰던 것
→ 평당  기본 83만 · 고급 101만 · 프리미엄 123만
```

`PRICING` 은 **스스로 확인한다.** HO0101 의 평수 구간 넷이 이 셈을 품지 못하면
굽는 순간 멈춘다.

```
10평대 1,500~2,200만 ⊃ 15평 1,519~1,669만
20평대 2,400~3,500만 ⊃ 25평 2,531~2,781만
30평대 3,200~4,600만 ⊃ 32평 3,240~3,560만
40평대 4,300~6,200만 ⊃ 45평 4,556~5,006만
```

⚠ `app.js` 는 정적 파일이라 `data.mjs` 를 못 읽는다. 그래서 잣대를 **화면이 실어 보낸다**
(`data-min-base`·`data-scope-mult`·`data-grade-mult` …). 숫자를 app.js 에 또 적으면
반드시 갈라진다 — 오늘 갈라져 있던 것이 바로 그 꼴이다.

## ① ES0101 → ES0201 — 고른 것을 들고 간다

「견적 결과 보기」가 아무것도 안 들고 갔다. 이제 `?pyeong=&scope=&grade=&spaces=` 로 넘긴다.

⚠ 결과 화면의 숫자를 새로 적지 않았다. 이미 있던 `data-base`(기본 등급 기준)에
**조건 배수를 곱해 둘 뿐**이다. 그래서 마감 등급 탭도 그대로 맞물려 돈다.

눌러 확인 — 32평 · 부분 시공 · 프리미엄으로 넘기니 조건 칩 셋이 그대로 따라오고,
등급 탭이 「프리미엄」에 켜지고, 공사 기간도 25일로 바뀐다.

## ② ES0201 — 표 둘이 다른 총액을 쓰던 것

「돈 내는 차례」가 **확정 계약금액**(34,100,000)을 나눠 적고 있었다. 바로 위 항목표
합계는 32,400,000 이다. 게다가 등급을 바꾸면 합계는 움직이는데 이 표만 그대로였다.

⚠ 여기는 **견적**이지 계약이 아니다. 확정액을 나누는 것은 CT0101 의 몫이다.
이제 비율만 적어 두고 금액은 **지금 화면의 합계**로 셈한다. 마지막 회차가 나머지를
받아 **합이 반드시 합계와 같아진다**. 「실측 뒤 계약할 때 확정 금액으로 다시 나눕니다」를
화면에 적었다.

⚠ 조건을 곱하면 24,369,049원 같은 숫자가 나온다. 견적서에 쓸 숫자가 아니라
**만원 자리에서 끊는다**(총액 폭은 십만 자리).

## ③④⑤ VS 실측 예약

달력·시간대의 «켜짐»은 이미 제대로 돌고 있었다. **고른 것을 아무 데도 안 알렸을 뿐이다.**

- ③ 고른 날짜·시간을 `?d=&t=&est=` 로 넘긴다.
- ④ 「예약 요약」에 **날짜·시간 칸**을 넣었다. 예약에서 가장 중요한 둘이 없었다.
- ⑤ 「연결할 견적」이 «전체시공»으로 박혀 있던 것을, 견적에서 온 조건대로 고친다.
  ES0201 → VS0101 손잡이에 `data-carry` 를 붙여 조건이 한 걸음마다 새지 않게 했다.

⚠ 요일을 손으로 적지 않는다 — `Date` 로 뽑는다. 손으로 적으면 날짜와 갈라진다.

## ⑪ CS0201 — 사진이 엉뚱한 방 것이던 것

**탭과 판의 짝은 처음부터 맞았다.** 자리표 이름이 「비포·애프터」·「공간 사진」뿐이라
어느 방 자리인지 아무도 몰랐던 것이다 — 사진 끼우는 쪽도, **손님이 받는 사진바꾸기.csv 도.**

이름에 방을 넣었다. 손님이 받는 표가 이제 이렇게 말한다.

```
"CS0201","시공사례 상세","거실 사진 1","시술","800×800","인테리어 - 11.webp"
"CS0201","시공사례 상세","침실 사진 1","시술","800×800","인테리어 - 17.webp"
```

## ⑬ CT0201 — 할부가 되돌아오던 것

**손잡이는 멀쩡했다.** 눌러서 재 보니 3개월도 일시불도 제대로 셈한다.
진짜 흠은 **칸 차례가 「일시불 · 6개월 · 3개월」**로 뒤집혀 있던 것이다.
「일시불 · 3개월 · 6개월」로 바로잡았다.
