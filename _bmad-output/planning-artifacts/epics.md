# IA 자동생성 플랫폼 - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for IA 자동생성 플랫폼, decomposing the requirements from the PRD, UX Design spine (DESIGN.md/EXPERIENCE.md), and Architecture spine into implementable stories.

## Requirements Inventory

### Functional Requirements

FR-1: 사용자는 로그인 후 새 프로젝트를 생성할 수 있다. 프로젝트는 컨셉/설명, 전체 프로젝트 시작일·종료일을 포함한다.
FR-2: 사용자는 여러 개의 프로젝트를 계정 아래에 만들고 목록에서 관리(조회/수정/삭제)할 수 있다.
FR-3: 프로젝트의 전체 일정 수정 시 화면별 일정 재계산을 트리거하며, 사용자 확인 후 적용하고 수동 수정분은 덮어쓰지 않는다.
FR-4: 사용자는 프로젝트 내에서 메뉴를 여러 개 추가할 수 있다(메뉴명 한글/영문, 설명, 원하는 기능).
FR-5: 메뉴명 영문 표기로부터 메뉴코드를 자동 산출(앞 2글자, 대문자). 중복/1글자/예약어(PC·MO) 충돌 시 수동 입력 요구.
FR-6: 메뉴 목록은 순서변경/수정/삭제 가능. 메뉴 삭제 시 소속 화면은 격리 보관(하드 삭제 아님). 메뉴코드 변경 시 기존 페이지ID는 소급 변경하지 않음(신/구 혼재 경고).
FR-7: [실행: IA 생성] 클릭 시 메뉴별 화면 목록을 규칙기반 패턴 매칭으로 자동 생성(완료기준: 메뉴당 최소 1개 화면, 페이지ID 중복 0건, 5개 항목 기본값 채움).
FR-8: 재실행 시 수동 수정 화면은 보존, 신규 메뉴만 화면 추가 생성(전체 덮어쓰기 금지). 격리된 화면은 재실행 대상 제외.
FR-9: 페이지ID 규칙({디바이스코드}{메뉴코드}{일련번호}), 프로젝트 내 고유성, 디바이스 대응방식(반응형 단일/PC-MO 분리) 설정 및 사후 변경 시 소급 미변경 규칙.
FR-10: 페이지명 규칙(메뉴명+상태/행위), 자동생성값 수정 가능.
FR-11: 화면기능정의 — 버튼/액션별 이동 대상 페이지ID 매핑(드롭다운 선택), 깨진 링크 경고 배지 처리.
FR-12: AI프롬프트 — MVP부터 Claude API(`claude-haiku-4-5`) 실제 LLM 생성(`[2026-07-13 정정]`, 원래는 MVP 템플릿→Phase 2 LLM이었으나 원가 확인 후 앞당김). 전체 텍스트 편집 가능.
FR-13: 일정 — 전체일정 기준 화면별 자동분배(균등, MVP), 수동수정 보호, 겹침/역전 경고, 전체일정 단축 시 범위이탈 충돌 처리.
FR-14: 화면 리스트 전체를 엑셀(.xlsx)로 다운로드. 생성 중에는 다운로드 비활성화.
FR-15: 엑셀 포맷은 업계 관행(1~5 Depth, 디바이스별 병행표기)과 정합.
FR-16: 화면 리스트 외에 메뉴 목록/프로젝트 개요도 별도 시트로 내보냄.
FR-17: 플랫폼 자체에 GNB(상단 내비게이션)와 Footer 포함.
FR-18: 로그인/가입 필수, 프로젝트는 계정에 귀속. 계정 삭제 시 30일 유예 보관.
FR-19: 계정 시스템은 향후 결제/구독 연동 가능하도록 확장 가능하게 설계.
FR-20: 화면별 AI프롬프트에 👍/👎 피드백 기능(핵심가치 지표의 데이터 소스).

### NonFunctional Requirements

NFR-1 (보안): 비밀번호 해시 저장, 세션/토큰 관리, 본인 프로젝트만 접근 가능한 접근권한 제어.
NFR-2 (데이터 내구성): 수동 수정 데이터는 자동생성 로직 재실행으로 유실되지 않아야 함.
NFR-3 (성능): 100+ 화면 규모에서도 IA 생성/엑셀 다운로드가 수 초~수십 초 내 완료.
NFR-4 (호환성): 내보낸 엑셀이 Excel/Google Sheets에서 깨짐 없이 열림.
NFR-5 (언어): UI/산출물은 한국어 기본.
NFR-6 (확장성): 결제/LLM 연동이 추가돼도 기존 데이터 모델을 깨지 않는 구조.
NFR-7 (감사가능성): 화면 데이터의 자동생성/수동수정 여부를 필드 단위로 추적 가능.
NFR-8 (텍스트 길이 제한): 화면기능정의·AI프롬프트 필드는 엑셀 셀 한도(32,767자) 대비 최대 길이 제한.

### Additional Requirements

- **스택/스캐폴드(Epic 1 Story 1에 영향)**: Next.js 16(App Router)+TypeScript, Tailwind CSS 4+shadcn/ui, Drizzle ORM, Neon(서버리스 Postgres), Better Auth, SheetJS(반드시 cdn.sheetjs.com tarball로 설치, npm 공개 패키지 금지), Vercel 호스팅. `[2026-07-13 추가]` `@anthropic-ai/sdk`(Story 3.4 착수 시 설치, 모델 `claude-haiku-4-5`).
- **아키텍처 경계**: 헥사고날(포트/어댑터) 구조 — `ScreenGenerationEngine`/`PromptGenerator`/`ExcelExporter`/`Repository` 포트를 도메인 계층에 정의하고 어댑터로 구현. `domain/`↔`adapters/` 경계는 CI에서 dependency-cruiser(또는 eslint-plugin-boundaries) 규칙으로 강제.
- **데이터 모델(스키마 설계에 반영)**: User/Project/Menu/Screen/ButtonAction 엔티티. `screen.page_id`는 (project_id, page_id) 복합 유니크, `menu.menu_code`는 (project_id, menu_code) 복합 유니크. `screen.status`(active|quarantined), `screen.screen_role`(재실행 매칭키), 필드별 `*_source`(auto|manual), `schedule_locked`, `prompt_feedback`(up|down|null), `updated_at`(낙관적 동시성용). `button_action.target_screen_id`(UUID FK)+`target_page_id_snapshot`. `project.deleted_at`(계정삭제 유예 소프트삭제).
- **인가/보안 구현**: 모든 Application Service 진입점은 공통 래퍼 `withProjectAuth`를 통해서만 export. Next.js `middleware.ts`는 인가 판단에 사용하지 않음. 데이터 변경은 Server Action을 기본 경로로.
- **동시성 제어**: `updateScreenFields()` 커맨드가 `updated_at` 비교로 낙관적 동시성 충돌을 감지, 불일치 시 409 반환.
- **배포/환경**: Vercel(로컬→PR 프리뷰→프로덕션 3단계) + Neon 브랜치 DB(프리뷰 환경 대응).
- **연산/운영(구현은 아니어도 명시적으로 계획에 반영)**: 에러 트래킹/로깅은 MVP는 Vercel 기본 로그로 대응(Sentry 등은 추후 검토). 레이트리미팅/어뷰징 방지 정책은 Phase 2. 백업/보존 정책(Neon PITR) 기간 미정. 계정삭제 30일 유예 후 하드 삭제 배치 잡은 별도 구현 필요.
- **엑셀 내보내기 구현**: SheetJS 어댑터, 서버(Next.js Server Action/Route Handler)에서 스트리밍 생성, 대용량 프로젝트 상한 가드 필요(구체값 미정).

### UX Design Requirements

UX-DR1: 디자인 토큰 — 컬러 시스템(배경/표면/보더/텍스트, 브랜드 Primary Indigo `#5B4FE5`+on-soft 변형, 파스텔 워시 3종(민트/라벤더/옐로우), 시맨틱 상태색 4종(success/warning/danger/neutral, 각 -soft 배경 포함, WCAG AA 대비 확보))를 구현.
UX-DR2: 타이포그래피 토큰 — Pretendard 기반 display/display-sm/body/label + 코드성 데이터 전용 모노스페이스(JetBrains Mono) 롤 구현.
UX-DR3: 라운드/스페이싱 토큰 — sm/md/lg/full 라운드 스케일, 사이드바 폭(240px) 등 스페이싱 토큰 구현.
UX-DR4: 컴포넌트 — Button(primary), Status badge(4 variants, 색+텍스트라벨 병행), Page ID cell(모노스페이스+태그), Summary card(파스텔 순환배정), Sidebar nav item(active), Page ID selector(콤보박스), Advanced settings panel(아코디언), Feedback icon button(32px+ 히트영역) — 각 컴포넌트는 시각 스펙(DESIGN.md)과 행동 스펙(EXPERIENCE.md) 양쪽 구현 필요.
UX-DR5: 정보구조 9개 화면(로그인/가입, 대시보드, 프로젝트 설정, 메뉴 관리, 화면 리스트, 화면 상세 패널, 내보내기, 계정 설정, 마케팅 랜딩) 라우팅/레이아웃 구현. GNB(로고/대시보드/프로필)는 전역 고정, 프로젝트 내 서브내비(설정/메뉴관리/화면리스트).
UX-DR6: 화면 리스트 핵심 인터랙션 — 셀 선택(방향키)/편집(Enter·F2·더블클릭) 상태 구분, 편집중 Enter 저장+다음행 이동/Esc 취소, 행 선택→상세패널(Esc 닫기+포커스 트리거요소 복귀).
UX-DR7: 페이지ID 선택기 — WAI-ARIA Combobox 패턴(열기/방향키이동/Enter선택/Esc닫기, aria-live 결과개수 안내) 구현.
UX-DR8: 고급 설정 패널 — 네이티브 `<button>`+`aria-expanded` 토글, 세션 내 펼침상태 기억.
UX-DR9: 상태 처리 — 프로젝트 0개/메뉴 없음/메뉴코드 자동산출 실패/IA생성중/화면0개/깨진링크/범위이탈일정/일정역전/메뉴삭제격리/메뉴코드혼재/디바이스방식혼재/재생성무변경/상세패널(저장중·빈값·글자수초과)/로그인가입실패/세션만료/저장실패(aria-live assertive)/내보내기실패/계정삭제유예, 총 17개 이상 상태 패턴 구현.
UX-DR10: 접근성 — 표 전체 키보드 탐색/편집, 상태배지 색+텍스트 병행, 사이드패널/다이얼로그/팝오버 닫힘시 포커스 반환, 조밀한 행 내 인터랙티브 요소 최소 24×24px 히트영역.
UX-DR11: 반응형 — 데스크톱(≥1024px) 전체기능, md(768~1023px) 조회중심(상세패널 편집만 허용), <md 읽기전용.
UX-DR12: 재실행/전체일정재계산 확인 다이얼로그(닫힘 시 트리거 버튼으로 포커스 복귀), AI프롬프트 피드백 아이콘 버튼 상호작용.
UX-DR13: 마이크로카피 톤앤매너(Voice and Tone Do/Don't 가이드 — 전문가에겐 정확하게, 비전문가에겐 친절하게, 원인 명시적인 에러 문구) 전체 UI 텍스트에 반영.

## Epic List

### Epic 1: 계정 만들고 프로젝트 시작하기
로그인/가입 후 프로젝트(컨셉+전체일정)를 만들고, 여러 프로젝트를 목록에서 관리할 수 있다. 플랫폼 전체에서 쓰이는 상단 내비게이션/푸터도 이 안에서 함께 만든다 — 다른 모든 화면이 이 위에 얹히므로 첫 번째로 필요하다.
**FRs covered:** FR-1, FR-2, FR-3, FR-17, FR-18, FR-19

### Epic 2: 메뉴 구성하기
프로젝트 안에서 메뉴(메뉴명/설명/원하는 기능)를 추가·수정·삭제·순서변경할 수 있고, 메뉴코드가 자동으로 부여되며 충돌/변경 상황이 안전하게 처리된다. 아직 화면은 생성하지 않지만, 이 단계만으로도 "사이트 메뉴 구조를 정리해보는" 실질적 가치가 있다.
**FRs covered:** FR-4, FR-5, FR-6

### Epic 3: IA 자동생성과 화면 편집 (핵심 가치)
[실행: IA 생성] 버튼으로 메뉴별 화면 목록이 자동 생성되고, 각 화면의 페이지ID/페이지명/기능정의(버튼-이동 연결)/AI프롬프트/일정을 전부 직접 수정할 수 있다. 재실행해도 손댄 내용은 보존된다. 프롬프트에 만족도(👍/👎)도 남길 수 있다. 이 다섯 항목이 전부 같은 화면(같은 데이터)을 다루기 때문에 하나의 에픽으로 묶었다 — 쪼개면 같은 표를 여러 에픽이 반복해서 건드리게 된다.
**FRs covered:** FR-7, FR-8, FR-9, FR-10, FR-11, FR-12, FR-13, FR-20

### Epic 4: 엑셀로 내보내기

## Epic 2: 메뉴 구성하기

### Story 2.1: 메뉴 추가하기

As a 프로젝트를 준비 중인 사용자,

**Given** 메뉴가 하나도 없는 프로젝트

**Then** "첫 메뉴를 추가해 보세요" 안내가 보이고, [실행: IA 생성] 버튼은 비활성화되어 있다(UX-DR9).

**Given** 영문 메뉴명이 1글자뿐이거나("A"), 코드가 예약어("PC"/"MO")와 같아짐

**Then** 마찬가지로 자동 산출을 거부하고 수동 입력을 요구한다.

## Epic 3: IA 자동생성과 화면 편집 (핵심 가치)

[실행: IA 생성] 버튼으로 메뉴별 화면 목록이 자동 생성되고, 각 화면의 페이지ID/페이지명/기능정의/AI프롬프트/일정을 전부 직접 수정할 수 있다. 이 플랫폼의 핵심 가치가 만들어지는 곳이다.

### Story 3.1: [실행: IA 생성]으로 화면 목록 자동 만들기

As a 메뉴 구성을 마친 사용자,
I want [실행: IA 생성] 버튼 하나로 메뉴별 필요한 화면 목록이 자동으로 만들어지기를,
So that 화면을 하나하나 손으로 리스트업하지 않아도 된다.

**Acceptance Criteria:**

**Given** 메뉴가 1개 이상 등록된 프로젝트
**When** [실행: IA 생성]을 클릭하면
**Then** 진행 상황을 보여주는 모달이 뜨고, 완료되면 화면 리스트로 이동해 각 메뉴마다 최소 1개 이상의 화면이 생성되어 있다.
**And** "장바구니", "회원가입"처럼 알려진 패턴에 맞는 메뉴는 그에 맞는 화면 세트(예: 상품있음/없음 2종)가, 그렇지 않은 메뉴는 기본 화면 세트가 생성된다.
**And** 생성된 화면끼리 페이지ID가 겹치는 경우는 없다.
**And** 화면 100개 이상인 프로젝트에서도 생성이 수십 초 안에 끝난다(NFR-3).

**Given** IA 생성이 진행 중인 상태
**When** 화면을 벗어나거나 다시 클릭을 시도하면
**Then** 완료 전까지 엑셀 다운로드 버튼은 비활성화되어 있다.

### Story 3.2: 화면의 페이지ID·페이지명 확인하고 수정하기

As a 생성된 화면을 검토하는 사용자,
I want 각 화면의 페이지ID와 페이지명을 표에서 보고 직접 고치기를,
So that 우리 프로젝트 상황에 맞게 이름을 다듬을 수 있다.

**Acceptance Criteria:**

**Given** 화면 리스트
**When** 화면을 조회하면
**Then** 페이지ID는 "{디바이스코드}{메뉴코드}{4자리 번호}"(예: PCMR1000) 형식으로, 페이지명은 "메뉴명+상태/행위"(예: "장바구니 상품없음") 형식으로 자동 채워져 있다.

**Given** 특정 화면의 페이지ID를 다른 값으로 수정함
**When** 저장하면
**Then** 같은 프로젝트 안에서 중복되지 않는 한 저장되고, 이 화면은 "자동생성"이 아닌 "수정됨" 상태로 바뀐다.

**Given** 프로젝트의 디바이스 대응 방식(PC/모바일 분리 ↔ 반응형 하나로)을 화면 생성 이후에 바꿈
**When** 설정을 변경하면
**Then** 이미 만들어진 화면의 페이지ID는 그대로 유지되고, 이후 새로 만들어지는 화면부터 새 방식이 적용되며, 화면 목록 상단에 "방식이 혼재되어 있어요" 경고 배너가 뜬다.

### Story 3.3: 화면 기능정의 작성하고 버튼을 다른 화면과 연결하기

As a 화면을 구체화하는 사용자,
I want 화면 안의 기능과 버튼을 누르면 어디로 이동하는지 적기를,
So that AI 코딩 도구가 화면 간 이동까지 이해하고 만들 수 있다.

**Acceptance Criteria:**

**Given** 화면 상세 패널
**When** 기능정의를 작성하고 버튼 항목에 "이동 대상"을 추가하려 하면
**Then** 자유 텍스트가 아니라 같은 프로젝트 내 페이지ID를 검색해서 고르는 방식으로만 연결할 수 있다.
**And** 저장하면 이 화면의 기능정의 항목은 "자동생성"이 아닌 "수정됨" 상태로 바뀐다.

**Given** 어떤 화면 A의 버튼이 화면 B를 가리키고 있음
**When** 화면 B가 삭제되거나 소속 메뉴가 삭제되어 격리됨
**Then** 화면 A의 그 버튼 항목에 "깨진 링크" 배지가 표시되고, 자동으로 지워지거나 다른 곳으로 재연결되지 않는다(사용자가 직접 정리해야 함).

**Given** 화면 B의 페이지ID가 나중에 바뀜(삭제는 아님)
**When** 화면 A에서 그 참조를 다시 보면
**Then** "연결 대상 이름이 바뀌었어요"라는 경고가 뜬다(깨진 링크와는 다른, 별개의 안내).

**Given** 기능정의 입력칸
**When** 아주 긴 텍스트를 입력하면
**Then** 최대 길이(약 3만자)에 가까워지면 경고가 뜨고 한도를 넘는 입력은 막힌다(NFR-8).

### Story 3.4: AI프롬프트 확인하고 수정하기

As a 화면을 검토하는 사용자,
I want 각 화면에 자동으로 만들어진 AI 프롬프트를 읽고 필요하면 고치기를,
So that 이 프롬프트를 그대로 AI 코딩 도구에 붙여넣어도 괜찮은 수준으로 만들 수 있다.

`[2026-07-13 정정]` 이 스토리의 프롬프트 생성은 규칙기반 템플릿이 아니라 **Claude API(`claude-haiku-4-5`) 실제 호출**로 구현한다(Sprint Change Proposal 참조, `sprint-change-proposal-2026-07-13.md`). 페이지명·기능정의·소속 메뉴 설명뿐 아니라 같은 메뉴의 다른 화면·전체 사이트 컨셉까지 맥락으로 넘겨 더 자연스러운 문장을 생성한다.

**Acceptance Criteria:**

**Given** 화면 상세 패널
**When** 프롬프트 칸을 보면
**Then** 페이지명·기능정의·소속 메뉴 설명(및 같은 메뉴의 다른 화면·사이트 컨셉 맥락)을 반영해 Claude API가 생성한 문장이 이미 채워져 있다.

**Given** 자동으로 채워진 프롬프트
**When** 전체 내용을 직접 고치면
**Then** 수정한 내용대로 저장되고 이 항목은 "수정됨" 상태가 된다.

### Story 3.5: 화면별 일정 확인·수정하고, 전체 일정이 바뀌면 재계산 받기

As a 일정까지 관리하고 싶은 사용자,
I want 각 화면의 제작 일정이 전체 프로젝트 일정에 맞춰 자동으로 나뉘고, 필요하면 개별로 조정하기를,
So that 언제 어떤 화면을 만들지 계획을 세울 수 있다.

**Acceptance Criteria:**

**Given** 전체 일정이 정해진 프로젝트에서 화면이 생성됨
**When** 화면 리스트를 보면
**Then** 각 화면에 시작일·종료일이 균등하게 배분되어 있다.

**Given** 특정 화면의 일정을 손으로 수정함
**When** 저장하면
**Then** 이 화면의 일정은 "잠김" 상태가 되어, 이후 전체 일정을 다시 계산해도 이 화면은 건드리지 않는다(NFR-2).

**Given** 프로젝트의 전체 일정을 더 짧게 수정함(Epic 1의 Story 1.4에서 만든 기능)
**When** 저장을 시도하면
**Then** "수동으로 조정한 화면은 유지되고, 자동배분된 화면만 새로 계산됩니다"라는 확인을 거친 뒤 적용된다.
**And** 손으로 고정해둔 화면의 일정이 새로운 전체 일정 범위를 벗어나게 되면, 자동으로 자르지 않고 "범위 이탈" 상태로 표시해 목록 위쪽에 모아 보여준다.

**Given** 화면 두 개의 일정이 앞뒤가 뒤바뀜(먼저 끝나야 할 화면이 나중에 끝남)
**When** 화면 리스트를 보면
**Then** "일정 역전" 경고가 해당 화면들에 표시된다.

### Story 3.6: 재실행해도 내가 고친 내용은 지켜지기

As a 메뉴를 추가한 뒤 다시 [실행: IA 생성]을 누르는 사용자,
I want 이미 손으로 고친 화면은 그대로 남아있고, 새로 추가한 메뉴의 화면만 생기기를,
So that 다시 실행한다고 애써 고친 내용이 날아가는 걱정을 안 해도 된다.

**Acceptance Criteria:**

**Given** 화면 몇 개를 손으로 수정해둔 프로젝트
**When** 새 메뉴를 추가하고 [실행: IA 생성]을 다시 클릭하면
**Then** 이미 있던 화면(수정한 것 포함)은 그대로 유지되고, 새 메뉴에 대한 화면만 새로 추가된다.

**Given** 재실행 버튼을 누르기 직전
**When** 클릭하면
**Then** "기존에 직접 수정한 화면은 유지되고, 새로 추가된 메뉴에서만 화면이 생성됩니다"라는 확인 절차를 거친다.

**Given** 새로 추가된 메뉴가 없는 상태에서 재실행함
**When** 클릭하면
**Then** "새로 추가된 메뉴가 없어 변경사항이 없습니다"라는 안내만 뜨고 아무것도 바뀌지 않는다.

### Story 3.7: 메뉴가 삭제/변경되면 관련 화면이 안전하게 처리되는 것 확인하기

As a 메뉴 구조를 바꾸는 사용자,
I want 메뉴를 삭제하거나 이름을 바꿔도 이미 만들어진 화면과 그 화면을 참조하던 다른 화면이 안전하게 유지되기를,
So that 메뉴를 정리하다가 화면 데이터를 실수로 잃어버리지 않는다.

**Acceptance Criteria:**

**Given** 화면이 이미 만들어진 메뉴
**When** 이 메뉴를 삭제하면(Epic 2의 Story 2.4)
**Then** 소속 화면은 삭제되지 않고 "격리됨" 상태로 화면 리스트의 별도 필터에 모인다. 사용자가 나중에 재배정하거나 직접 삭제를 선택할 수 있다.

**Given** 격리된 화면을 다른 화면의 버튼이 가리키고 있었음
**When** 격리가 일어나면
**Then** 그 버튼 항목은 "깨진 링크"로 표시된다(Story 3.3과 동일 규칙).

**Given** 메뉴의 영문명을 바꿔 메뉴코드가 달라짐
**When** 저장하면
**Then** 이미 발급된 화면의 페이지ID는 그대로 유지되고, 새로 만들어지는 화면부터 새 코드가 적용되며, "이 메뉴에 신/구 코드가 섞여 있어요" 경고가 화면 목록에 표시된다.

### Story 3.8: AI프롬프트에 좋아요·싫어요 남기기

As a 자동생성된 프롬프트를 확인한 사용자,
I want 이 프롬프트가 쓸만한지 👍/👎로 평가하기를,
So that 서비스가 프롬프트 품질을 계속 개선해 나갈 수 있다.

**Acceptance Criteria:**

**Given** 화면 상세 패널의 AI프롬프트 영역
**When** 👍 또는 👎를 클릭하면
**Then** 평가가 저장되고 짧은 감사 메시지가 뜬다.

**Given** 이미 평가를 남긴 상태
**When** 같은 버튼을 다시 클릭하면
**Then** 평가가 취소된다.

## Epic 4: 엑셀로 내보내기

완성한 화면 리스트를 엑셀 파일로 다운로드할 수 있다. 이걸로 "다운받아서 AI 코딩 도구에 붙여넣는다"는 이 플랫폼의 핵심 약속이 처음부터 끝까지 완성된다.

### Story 4.1: 화면 리스트를 엑셀로 다운로드하기

As a 화면 리스트 작업을 마친 사용자,
I want 전체 화면 리스트를 엑셀 파일로 내려받기를,
So that 이 파일을 AI 코딩 도구나 팀원에게 그대로 전달할 수 있다.

**Acceptance Criteria:**

**Given** 화면이 1개 이상 생성된 프로젝트
**When** "엑셀 다운로드"를 클릭하면
**Then** 페이지ID·페이지명·화면기능정의·AI프롬프트·일정 전체 컬럼이 담긴 .xlsx 파일이 다운로드된다.

**Given** IA 생성이 아직 진행 중인 상태
**When** 다운로드를 시도하면
**Then** 버튼이 비활성화되어 있어 불완전한 상태의 파일이 받아지지 않는다(Story 3.1과 연계).

**Given** 다운로드가 실패함(서버 오류 등)
**When** 실패가 감지되면
**Then** "다운로드에 실패했어요. 다시 시도해 주세요." 안내가 뜨고 화면 데이터에는 영향이 없다.

### Story 4.2: 엑셀 포맷을 기존 기획 문서 형식에 맞게 다듬기

As a 실무에서 IA 문서를 다뤄본 기획자,
I want 다운로드한 엑셀이 평소 보던 기획 문서와 비슷한 모양이기를,
So that 별도 학습 없이 바로 알아보고 활용할 수 있다.

**Acceptance Criteria:**

**Given** 다운로드된 엑셀 파일
**When** 열어보면
**Then** 1~5 Depth 브레드크럼 컬럼 구성과 디바이스별(PC/모바일) 병행 표기 등 참고 자료([addendum.md §A])에서 확인한 업계 관행과 맞는 컬럼 구조로 되어 있다.

**Given** 다운로드된 파일
**When** Microsoft Excel 또는 Google Sheets로 열면
**Then** 병합 셀 깨짐이나 인코딩 오류 없이 정상적으로 열린다(NFR-4).

### Story 4.3: 메뉴 목록과 프로젝트 개요도 함께 내보내기

As a 산출물을 한 파일로 정리하고 싶은 사용자,
I want 화면 리스트뿐 아니라 메뉴 목록과 프로젝트 개요도 같은 엑셀 안에 포함되기를,
So that 파일 하나로 프로젝트 전체를 설명할 수 있다.

**Acceptance Criteria:**

**Given** 화면 리스트 다운로드
**When** 엑셀 파일을 열면
**Then** "화면 리스트" 시트 외에 "메뉴 목록" 시트와 "프로젝트 개요"(컨셉·전체일정) 시트가 별도로 포함되어 있다.
