- (version) Next.js 16.2.10 LTS (2026-07 기준 stable, App Router, Turbopack 기본 번들러, Node 20+ 요구) - 웹검증됨
- (decision) 패러다임: Hexagonal(Ports & Adapters). 근거: PRD FR-12(AI프롬프트 MVP=템플릿→Phase2=LLM 교체)와 FR-7(패턴라이브러리 확장)가 명시적으로 '나중에 구현을 통째로 바꿔도 호출부는 안 바뀌어야 한다'는 요구라 포트/어댑터 경계가 진짜 트레이드오프. 포트: ScreenGenerationEngine, PromptGenerator, ExcelExporter
- (decision) 스택: Next.js 16(App Router)+TypeScript, Tailwind+shadcn/ui(UX스파인 ASSUMPTION 승인), Drizzle ORM + Neon(서버리스 Postgres) - Prisma 대비 엣지친화적/스키마가 SQL에 가까워 AI코딩툴 생성에 유리해서 채택(대안: Prisma, DX는 더 좋으나 이번엔 Drizzle 선택). Better Auth 채택(자체호스팅, 벤더종속 없음, 추후 결제/멀티테넌시 확장 용이 - 대안: Clerk는 UI가 더 빠르지만 호스팅 종속). 엑셀 export: SheetJS(xlsx). 배포: Vercel(Next.js 네이티브)+Neon
- (decision) 데이터모델: User 1:N Project 1:N Menu 1:N Screen. Screen.pageId는 (project_id, page_id) 복합 유니크 - PRD상 프로젝트 스코프 고유성 반영. 메뉴 삭제시 Screen.status=quarantined로 격리(하드삭제 금지). ButtonAction은 target_screen_id(nullable)+is_broken 플래그로 댕글링 참조 표현
- (decision) 감사추적(NFR-7): Screen에 generation_source(auto|manual) + schedule_locked(bool) 필드. 사용자가 필드를 수정하면 해당 필드 그룹의 source가 manual로 전환, 재실행/재계산 로직이 이 플래그로 보호 여부 판단
- (decision) IA생성엔진(FR-7)은 코드 내 DomainPattern 규칙 테이블(키워드매칭→표준화면세트)로 MVP 구현, ScreenGenerationEngine 포트 뒤에 위치해 향후 DB기반 편집기나 ML기반으로 교체 가능
- (decision) AI프롬프트(FR-12): PromptGenerator 포트. MVP 어댑터=TemplatePromptGenerator(문자열 보간, 외부호출 없음), Phase2 어댑터=LLMPromptGenerator(Claude API 호출) - 설정으로 교체, 호출부 무변경
- (decision) 일정 재계산 보호(FR-3/FR-13): Screen.schedule_locked=true인 행은 전체일정 재계산 배치에서 제외. 범위이탈/역전 여부는 저장하지 않고 조회시점에 계산되는 파생 상태(computed status)로 처리
- (decision) 엑셀 export는 SheetJS로 서버(Next.js Route Handler/Server Action)에서 스트리밍 생성. 프로젝트당 화면 수 상한 가드 필요(대용량 시 타임아웃 방지) [ASSUMPTION: 구체적 상한값 미정]
- (decision) 배포 환경: Vercel(로컬/PR프리뷰/프로덕션 3단계, Vercel 표준 흐름) + Neon Postgres(브랜치 DB로 프리뷰 환경 대응 가능)
- (question) Drizzle vs Prisma, Better Auth vs Clerk는 Fast path assumption으로 결정 - 사용자 리뷰 시 재확인 필요 (개발 경험 선호에 따라 뒤집힐 수 있는 결정)
- (decision) 리뷰 반영(critical/high 전부): FR-20 프롬프트피드백 ERD 추가, SheetJS는 npm 아닌 cdn.sheetjs.com tarball로 설치(npm판 방치+취약점), AD-4를 UUID FK+target_page_id_snapshot으로 재정의(이름변경 경고와 깨진링크 분리), AD-8 신설(page_id 소급변경 금지), AD-9 신설(낙관적동시성 409), AD-7을 withProjectAuth 래퍼로 구체화(middleware.ts 배제, Server Action 기본), AD-5에 diff기반 source전환+단일 updateScreenFields 커맨드 명시, AD-1에 포트 최소계약(입출력 타입) 고정+어댑터의 Repository 직접호출 금지, Drizzle/Better Auth 버전 웹검증 후 고정(v1.0계열/1.6.23), 관측가능성/레이트리미팅/백업/계정삭제배치를 Deferred에 명시적으로 등재
