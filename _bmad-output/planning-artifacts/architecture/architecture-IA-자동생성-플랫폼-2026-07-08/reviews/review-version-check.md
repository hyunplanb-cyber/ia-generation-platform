# 기술 스택 최신성 검증 — IA 자동생성 플랫폼

## Overall verdict
스파인의 핵심 프레임워크 선택(Next.js 16.2.10, React 19.x, TypeScript 5.x, Tailwind 4.x, shadcn/ui, Drizzle, Better Auth, Neon, Vercel)은 2026-07 시점 실제로 존재하고 활발히 유지되는 조합이며, Better Auth + Drizzle + Neon + shadcn/ui 페어링은 오히려 2026년의 사실상 표준 스타터 조합으로 다수 튜토리얼/스타터 레포에서 검증됨. 유일하게 즉시 수정이 필요한 항목은 **SheetJS(xlsx) 표기** — npm 레지스트리의 `xlsx` 패키지는 사실상 방치되어 있고 심각한 보안 취약점이 다수 존재하므로, 설치 출처를 명시적으로 SheetJS 공식 CDN으로 지정해야 함.

### Findings

- **critical** SheetJS(xlsx) 설치 출처 — npm 공개 레지스트리의 `xlsx` 패키지는 최신 버전이 반영되지 않고 정체되어 있으며(레지스트리 최신 0.18.5, 실제 SheetJS 최신은 0.20.3+), 0.20.2 이전 ReDoS(정규식 서비스거부), 0.19.2 이전 프로토타입 오염(Prototype Pollution) 등 고위험(High) 취약점이 npm 패키지에 남아있고 수정판이 npm에 게시되지 않음. SheetJS 팀 스스로 npm 레지스트리 이탈을 공지하고 자사 CDN(`cdn.sheetjs.com`)을 "authoritative source"로 안내 중. 출처: [xlsx - npm](https://www.npmjs.com/package/xlsx), [GitLab Advisory Database — npm/xlsx](https://advisories.gitlab.com/pkg/npm/xlsx/), [SheetJS Installation 공식 문서](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/), [Why the move away from npm registry? (SheetJS GitHub Issue #2667)](https://github.com/SheetJS/sheetjs/issues/2667), [BleepingComputer — npm package with 1.4M weekly downloads ditches npmjs.com for own CDN](https://www.bleepingcomputer.com/news/software/npm-package-with-14m-weekly-downloads-ditches-npmjscom-for-own-cdn/). *Fix:* Stack 표의 "SheetJS (xlsx) | 최신 stable" 행을 "SheetJS (xlsx) — **반드시 `https://cdn.sheetjs.com/xlsx-<version>/xlsx-<version>.tgz` 형태로 설치**, 공개 npm 레지스트리의 `xlsx` 패키지명으로 직접 설치 금지"로 명시. `adapters/export/sheetjs/` 어댑터 구현 시 package.json에 CDN tarball URL을 dependency로 고정하고, CI에서 해당 의존성 출처를 검증하는 룰을 추가 권장.

- **low** ExcelJS 대안 검토 누락 — SheetJS의 npm 취약점 이력을 고려하면 서버리스(Vercel) 환경에서는 메모리 사용량이 낮고 능동적으로 유지보수되는 ExcelJS(주간 다운로드 약 190만)가 대안으로 종종 언급됨. 다만 스파인의 `addendum.md` 참고 엑셀 구조 분석에서 이미 SheetJS로 검증된 이력이 있고 포트/어댑터 구조(AD-1)상 `ExcelExporter` 교체가 쉬우므로 치명적이지 않음. 출처: [SheetJS vs ExcelJS vs node-xlsx 2026 비교](https://www.pkgpulse.com/guides/sheetjs-vs-exceljs-vs-node-xlsx-excel-files-node-2026), [ExcelJS 소개 (Medium)](https://medium.com/@manishasiram/exceljs-alternate-for-xlsx-package-fc1d36b2e743). *Fix:* Deferred 섹션에 "ExcelExporter 어댑터 교체 후보(ExcelJS)"를 한 줄 메모로 남겨 향후 스트리밍/메모리 이슈 발생 시 참조 가능하게 함. 필수 조치 아님.

- **low** Neon의 Databricks 인수 — Neon은 2025년 Databricks에 인수 완료(2026년 기준으로도 "Neon" 브랜드로 독립 운영 중, 컴퓨트 15~25%·스토리지 약 80% 가격 인하 등 개선 있음)되어 스파인의 "Neon (서버리스 Postgres)" 표기 자체는 여전히 유효함. 장기적으로 브랜드/API 변경 리스크는 낮지만 인지해둘 사실. 출처: [Databricks Agrees to Acquire Neon (공식 보도자료)](https://www.databricks.com/company/newsroom/press-releases/databricks-agrees-acquire-neon-help-developers-deliver-ai-systems), [Databricks and Neon (Databricks Blog)](https://www.databricks.com/blog/databricks-neon). *Fix:* 조치 불필요. 참고 사실로만 기록.

- **low** Stack 표의 `[ASSUMPTION]` 태그 정리 — Drizzle ORM과 Better Auth 행에 남아있는 `[ASSUMPTION — ... 검토됨]` 표기는 이번 검증으로 실제 근거가 확보되었으므로(아래 확인 사항 참조) ASSUMPTION 태그를 제거하고 근거 링크로 대체 가능. *Fix:* "Drizzle ORM | v1.0(2025 GA, 2026-07 기준 beta.22까지 후속 릴리스 진행 중) — Prisma/Kysely 대비 신규 프로젝트 채택 우위, 0 dependencies, Neon 네이티브 지원", "Better Auth | 1.6.x(2026-06 기준 1.6.23 stable, 1.7.0-rc.1 진행 중) — Next.js 13+/Drizzle adapter/Neon과의 조합이 2026년 사실상 표준 스타터 패턴"으로 갱신 권장.

### 확인 사항 (근거 요약, 조치 불필요)

1. **Drizzle ORM 존재/유지보수 여부** — 활발히 유지보수 중. v1.0이 2025년 GA, 2026-04 기준 v1.0.0-beta.22까지 후속 릴리스가 이어지고 있으며 Prisma/Kysely 대비 신규 프로젝트 채택률에서 앞서는 것으로 보고됨. 출처: [Drizzle ORM - Latest releases](https://orm.drizzle.team/docs/latest-releases), [Drizzle ORM v1 vs Prisma 6 vs Kysely 2026](https://www.pkgpulse.com/guides/drizzle-orm-v1-vs-prisma-6-vs-kysely-2026).
2. **Better Auth 존재/유지보수 여부 및 버전** — 활발히 유지보수 중, 2026-06-29 기준 stable 1.6.23, 2026-07-02에 1.7.0-rc.1 릴리스. GitHub Actions OIDC trusted publishing 등 보안 관행 양호. 출처: [better-auth - npm](https://www.npmjs.com/package/better-auth), [Better Auth 1.6 블로그](https://better-auth.com/blog/1-6), [Better Auth Security update: June 2026](https://better-auth.com/blog/security-update-june-2026).
3. **SheetJS 존재/유지보수 여부** — 프로젝트 자체(SheetJS Community/Pro Edition)는 활발히 유지보수 중(cdn.sheetjs.com 기준 최신 0.20.3+)이나, **npm 공개 레지스트리의 `xlsx` 패키지명은 사실상 방치**되어 있음. 위 critical 항목 참조.
4. **Better Auth × Next.js 16 App Router × Drizzle × Neon 궁합** — 2026년 시점 이 조합은 특이 사례가 아니라 다수의 스타터 템플릿(GitHub `nextjs_drizzle_better-auth`, `better-auth-starter` 등)과 튜토리얼에서 재현되는 사실상 표준 풀스택 인증 스타터 패턴으로 확인됨. Auth.js(NextAuth)나 Clerk가 이를 대체했다는 근거는 발견되지 않음 — 오히려 Better Auth가 Next.js 13+ 전용 설계와 Drizzle 어댑터 네이티브 지원으로 더 적은 보일러플레이트를 제공한다는 평가가 다수. 출처: [Full Stack Authentication in 2026 with Better Auth, Drizzle, Neon, Shadcn UI, and Next.js](https://dev.to/iampandit/full-stack-authentication-in-2026-with-better-auth-drizzle-neon-shadcn-ui-and-nextjs-32nb), [Drizzle ORM Adapter | Better Auth 공식 문서](https://better-auth.com/docs/adapters/drizzle), [GitHub - RvDstudio/nextjs_drizzle_better-auth](https://github.com/RvDstudio/nextjs_drizzle_better-auth).
5. **Next.js 16.x / Tailwind 4.x / shadcn/ui 주요 변경사항** — Next.js 16에서 `params`/`searchParams`가 완전히 Promise로 전환(동기 접근 제거), `next build`가 Turbopack 기본화(커스텀 webpack 설정 시 빌드 실패 주의), 16.2.10은 16.2.4 이후 빠졌던 `@next/swc-wasm-web` 재게시만 포함한 무변경 패치. Tailwind v4는 JS 설정 파일 대신 CSS `@theme` 방식, `@tailwind` 디렉티브 대신 `@import "tailwindcss"`, PostCSS 플러그인이 `@tailwindcss/postcss`로 교체, `tailwindcss-animate` 대신 `tw-animate-css` 사용. shadcn/ui는 이미 Tailwind v4 + React 19 완전 대응 완료. 신규 프로젝트로 시작하는 이번 스파인 기준으로는 이 변경사항들이 오히려 "이미 반영된 기본값"이라 리스크 없음. 출처: [Next.js 16 블로그](https://nextjs.org/blog/next-16), [Upgrading: Version 16 (Next.js 공식 문서)](https://nextjs.org/docs/app/guides/upgrading/version-16), [Release v16.2.10 · vercel/next.js](https://github.com/vercel/next.js/releases/tag/v16.2.10), [Tailwind v4 - shadcn/ui 공식 문서](https://ui.shadcn.com/docs/tailwind-v4), [Tailwind CSS Upgrade guide](https://tailwindcss.com/docs/upgrade-guide).
