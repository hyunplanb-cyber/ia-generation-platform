# IA 자동생성 플랫폼 — Experience Spine

## Foundation

데스크톱 우선 반응형 웹(태블릿/모바일은 조회 중심, 전체 편집 지원은 Phase 2) `[결정: 사용자 확정]`. shadcn/ui + Next.js + Tailwind 기반으로 가정한다 `[ASSUMPTION — 최종 확정은 bmad-architecture]`. `DESIGN.md`가 비주얼 아이덴티티를, 이 문서가 동작/행동을 정의한다. 계정당 다중 프로젝트, 프로젝트는 각각 독립된 작업공간(FR-1~2). 전문 기획자와 비전문가 창업자 두 세그먼트를 **하나의 UI로 통합**하고, 전문가용 세부 옵션(디바이스 분리 설정, 일정 가중치 등)은 "고급 설정" 접기/펼치기 패널 뒤에 숨긴다 `[결정: 사용자 확정]`.

## Information Architecture

| 화면(Surface) | 진입 경로 | 목적 |
|---|---|---|
| 로그인/가입 | 최초 진입, 세션 만료 | 인증 (FR-18) |
| 대시보드 (프로젝트 목록) | 로그인 직후 / GNB 로고 | 보유 프로젝트 카드 목록, 새 프로젝트 생성 (FR-2) |
| 프로젝트 설정 | 대시보드 "새 프로젝트" / 프로젝트 내 설정 탭 | 컨셉·설명·전체일정·디바이스 대응방식 입력 (FR-1, FR-3, FR-9) |
| 메뉴 관리 | 프로젝트 좌측 서브내비 "메뉴" | 메뉴 추가/수정/삭제/순서변경 (FR-4~6) |
| 화면 리스트 (핵심) | 메뉴 관리에서 [실행: IA 생성] 클릭 후 자동 이동 / 좌측 서브내비 "화면 리스트" | 전체 화면을 표 형태로 조회·편집 — 페이지ID/페이지명/기능정의/AI프롬프트/일정 (FR-7~13, FR-20) |
| 화면 상세 패널 | 화면 리스트 행 클릭 | 기능정의(버튼-액션 목록)·AI프롬프트 전체 텍스트를 넓게 편집하는 사이드패널 |
| 내보내기 | 화면 리스트 상단 "엑셀 다운로드" | .xlsx 생성/다운로드 (FR-14~16) |
| 계정 설정 | GNB 프로필 메뉴 | 프로필, 로그아웃, 계정 삭제 (FR-18) |
| 마케팅 랜딩 (비로그인) | 비로그인 방문 | 서비스 소개, 로그인/가입 유도. GNB: 로고·서비스소개·로그인/가입 CTA. Footer: 이용약관·개인정보처리방침·문의하기·© 표시 (FR-17) `[ASSUMPTION: 표준 구성. 실제 카피/추가 링크는 마케팅 콘텐츠 확정 시 갱신]` |

프로젝트 내부는 좌측 서브내비(설정/메뉴관리/화면리스트)로 이동하고, 전역 GNB(로고/대시보드/프로필)는 모든 화면 상단에 고정된다. 모달은 1단계까지만 허용(예: 화면 상세 패널 위에 "페이지ID 선택" 팝오버는 가능하나 그 위에 추가 모달은 없음).

→ 구성 참고: `.working/`에 초안 목업 예정. Spine이 항상 우선한다.

## Voice and Tone

브랜드 보이스는 `DESIGN.md.Brand & Style`을 따른다. 마이크로카피는 "전문가에게는 정확하게, 비전문가에게는 친절하게" 두 세그먼트를 하나의 톤으로 관통한다 — 어렵지 않은 실무 용어를 쓰되 느낌표·이모지로 과장하지 않는다.

| Do | Don't |
|---|---|
| "화면 12개를 생성했어요. 검토해 주세요." | "짜잔! 12개 화면이 완성됐어요! 🎉" |
| "이 페이지ID를 참조하는 화면이 3개 있어요. 그래도 삭제할까요?" | "정말 삭제하시겠습니까?" (근거 없는 단순 확인) |
| "깨진 링크" / "범위 이탈" | "오류 발생" (원인 불명확한 일반 에러 문구) |
| "메뉴가 삭제되어 화면이 보관함으로 옮겨졌어요." | "메뉴가 삭제되었습니다." (연쇄효과를 숨김) |
| "이미 가입된 이메일이에요. 로그인해 주세요." / "비밀번호가 일치하지 않아요." | "인증에 실패했습니다." (원인 불명확) |

## Component Patterns

행동 정의. 시각 스펙은 `DESIGN.md.Components` 참조.

| 컴포넌트 | 사용처 | 행동 규칙 |
|---|---|---|
| 화면 리스트 행 | 화면 리스트 | 셀은 **선택(포커스) 상태**와 **편집 상태**를 구분한다. 방향키로 셀을 선택 → 더블클릭 또는 `Enter`/`F2`로 편집 상태 진입(단문 필드: 페이지명 등). 편집 중 `Enter`는 저장 후 같은 열의 다음 행으로 이동, `Esc`는 편집 취소 후 선택 상태로 복귀. 기능정의/AI프롬프트 셀은 선택 상태에서 `Enter` 또는 클릭 시 화면 상세 패널을 연다(긴 텍스트는 인라인 편집 금지). 페이지ID 셀(`DESIGN.md.page-id-cell`)은 `{typography.code}` 적용, 클릭 시 복사. |
| 상태배지 (`DESIGN.md.status-badge`) | 화면 리스트 행 | "깨진 링크"(danger), "범위 이탈 일정"(warning), "일정 역전/겹침"(warning), "메뉴 삭제됨"(warning), "메뉴코드 변경(신/구 혼재)"(warning), "격리됨"(neutral), "자동생성"/"수정됨"(neutral) — 한 행에 여러 배지 동시 표시 가능, 최대 2개 초과 시 "+N" 축약. 최소 32×32px 히트영역("+N" 확장 클릭 포함). |
| 화면 상세 패널 | 화면 리스트 행 클릭/Enter | 우측에서 슬라이드인. `Esc`로 닫히며, 닫힘 시 포커스는 패널을 연 트리거 셀(행)로 복귀한다. 동일한 열림/닫힘/포커스복귀 규칙을 재실행·전체일정재계산 확인 다이얼로그, 페이지ID 선택기 팝오버에도 적용한다. |
| 페이지ID 선택기 (`DESIGN.md.page-id-selector`) | 화면 상세 패널의 버튼-액션 항목 | 자유 텍스트 입력 금지, 같은 프로젝트 내 페이지ID를 검색/자동완성하는 드롭다운만 허용(FR-11 오타 방지). WAI-ARIA Combobox 패턴을 따른다: 입력 필드 포커스/타이핑으로 목록 열림 → `↓`/`↑`로 옵션 이동(활성 옵션은 `page-id-selector.optionActiveBackground`) → `Enter`로 선택+목록 닫힘+입력 필드로 포커스 유지 → `Esc`로 목록만 닫고 입력 필드에 포커스 유지(선택 안 함). 대상이 삭제되면 선택기 값이 "깨진 링크" 상태로 표시. |
| [실행: IA 생성] 버튼 | 메뉴 관리 화면 상단 | 클릭 시 진행 모달(생성 중 애니메이션) → 완료 시 화면 리스트로 자동 이동 + 토스트("화면 N개 생성"). 처리 중에는 엑셀 다운로드 버튼 비활성화(FR-14). |
| 재실행 확인 다이얼로그 | [실행: IA 생성] 재클릭 시 | "기존에 직접 수정한 화면은 유지되고, 새로 추가된 메뉴에서만 화면이 생성됩니다"를 명시한 확인 다이얼로그 (FR-8 오해 방지). 닫힘(확인/취소/`Esc`) 시 포커스는 [실행: IA 생성] 버튼으로 복귀. |
| 전체 일정 재계산 확인 다이얼로그 | 프로젝트 설정에서 전체 일정 수정 후 저장 | "수동으로 조정한 화면 일정은 유지되고, 자동분배된 화면만 새 일정에 맞춰 재계산됩니다"를 명시한 확인 다이얼로그(FR-3). 재실행 확인 다이얼로그와 동일한 패턴(닫힘 시 저장 버튼으로 포커스 복귀). |
| 고급 설정 패널 (`DESIGN.md.advanced-settings-panel`) | 프로젝트 설정, 화면 상세 패널 | 접힌 상태가 기본. 디바이스 분리 여부, 일정 가중치 등 전문가용 옵션 포함. 펼침 상태는 세션 내 기억. 토글은 네이티브 `<button>` + `aria-expanded`(펼침 시 true)를 사용하고 `Space`/`Enter`로 조작 가능해야 한다. |
| AI프롬프트 피드백 (`DESIGN.md.feedback-icon-button`) | 화면 상세 패널 | 👍/👎 아이콘 버튼(FR-20), 각 32×32px 이상. 클릭 후 짧은 감사 토스트, 재클릭으로 취소 가능. |
| 프로젝트 카드 | 대시보드 | 파스텔 워시 순환 배정(`DESIGN.md.summary-card`), 화면 수·최근 수정일 표시. |
| 사이드바 네비 아이템 (`DESIGN.md.sidebar-nav-item-active`) | 프로젝트 내 전체 화면 | 설정/메뉴관리/화면리스트 3개 고정 항목. 현재 라우트와 일치하는 항목이 활성 스타일. 클릭 또는 `Enter`(포커스 시)로 라우팅. |

## State Patterns

| 상태 | 화면 | 처리 |
|---|---|---|
| 프로젝트 0개 (최초 진입) | 대시보드 | `display`: "첫 프로젝트를 만들어 보세요." 큰 "새 프로젝트 만들기" CTA 카드 하나만 표시(가입 직후 비전문가 창업자가 가장 먼저 보는 화면). |
| 메뉴 없음 (최초 진입) | 메뉴 관리 | `display-sm`: "첫 메뉴를 추가해 보세요." [실행: IA 생성] 버튼은 비활성화(메뉴 1개 이상부터 활성). |
| 메뉴코드 자동산출 실패 | 메뉴 관리 (메뉴 입력 행) | 코드 중복/영문 1글자/예약어(PC·MO) 충돌 시 해당 메뉴 행에 인라인 오류 + 수동 코드 입력 필드로 전환(FR-5). |
| IA 생성 중 | 화면 리스트 진입 전 | 진행 모달, 취소 불가(짧은 처리 시간 가정 `[ASSUMPTION]`). 완료 전 엑셀 다운로드 버튼 비활성화. |
| 화면 0개 (생성 실패/모든 메뉴 매칭 실패) | 화면 리스트 | 발생하지 않아야 함(FR-7 완료기준 — 메뉴당 최소 1개 보장). 만약 발생 시 오류 배너 + 재시도 버튼. |
| 깨진 링크 | 화면 리스트 행 / 화면 상세 패널 | danger 배지 + 상세 패널에서 "다시 연결" 또는 "항목 삭제" 유도. 자동 삭제 안 함(FR-11). |
| 범위 이탈 일정 | 화면 리스트 상단 | 해당 행들을 목록 최상단에 모아 warning 배지와 함께 노출, "일정 조정" 일괄 작업 진입점 제공(FR-13). |
| 일정 역전/겹침 | 화면 리스트 행 | 선행 화면 종료일 > 후행 화면 종료일인 행 쌍에 warning 배지("일정 역전"), 상세 패널에서 두 화면을 나란히 비교(FR-13). |
| 메뉴 삭제로 격리된 화면 | 화면 리스트 (별도 탭/필터) | "격리됨" 필터 탭에 모음. 사용자가 재배정하거나 최종 삭제 결정(FR-6). |
| 메뉴코드 변경으로 신/구 혼재 | 화면 리스트 상단 배너 | "일부 화면이 이전 메뉴코드를 사용 중입니다" warning 배너, 관련 행에 "메뉴코드 변경(신/구 혼재)" 배지(FR-6). |
| 디바이스 대응 방식 변경으로 신/구 혼재 | 화면 리스트 상단 배너 | "디바이스 대응 방식이 변경되어 화면 페이지ID 체계가 혼재합니다" warning 배너, 관련 행에 동일 계열 배지(FR-9). |
| 재생성 시 신규 화면 없음(모든 메뉴 이미 처리됨) | [실행: IA 생성] 클릭 후 | 토스트: "새로 추가된 메뉴가 없어 변경사항이 없습니다." |
| 화면 상세 패널 — 저장 중 | 화면 상세 패널 | 필드 우측에 작은 스피너, 저장 완료 시 체크 아이콘으로 전환 후 1초 뒤 사라짐. |
| 화면 상세 패널 — 빈 값 | 화면 상세 패널 (신규 생성 직후) | 기능정의/AI프롬프트가 비어 있을 일은 없어야 하나(FR-7 완료기준), 사용자가 내용을 모두 지운 경우 `display-sm` 대신 옅은 placeholder 텍스트로 안내. |
| 화면 상세 패널 — 글자수 초과 | 화면 상세 패널 | NFR-8 한도 근접 시 경고 카운터 표시, 한도 도달 시 추가 입력 차단. |
| 로그인/가입 실패 | 로그인/가입 | 이메일 중복, 비밀번호 오류 등은 필드 하단 인라인 오류로 표시(Voice and Tone 참조), 전역 토스트로 중복 안내하지 않음. |
| 세션 만료 (편집 중) | 전역 | 저장되지 않은 변경분을 로컬에 보존한 채 로그인 화면으로 이동, 재로그인 후 "이어서 편집하시겠어요?" 배너로 복구 제공. "저장 실패" 상태와 달리 재시도가 아닌 재인증이 트리거. |
| 저장 실패 | 전역 | 토스트(destructive, `aria-live="assertive"`): "저장하지 못했어요. 다시 시도해 주세요." 편집 내용은 유지, 재시도 버튼 제공. |
| 내보내기 실패 | 화면 리스트 (엑셀 다운로드) | 토스트(destructive): "다운로드에 실패했어요. 다시 시도해 주세요." 화면 데이터에는 영향 없음. |
| 계정 삭제 유예 중 | 로그인 시 배너 | "계정이 N일 후 삭제됩니다. 프로젝트를 내보내 두세요." + 엑셀 다운로드 바로가기(FR-18). |

## Interaction Primitives

- **셀 선택 → 편집 진입 → 저장/취소** — 방향키로 셀 선택(포커스), `Enter`/`F2`/더블클릭으로 편집 진입, 편집 중 `Enter`로 저장 후 아래 행 동일 열 이동, `Esc`로 취소 후 선택 상태 복귀(단문 필드만 해당).
- **행 선택 → 상세 패널** — 기능정의/AI프롬프트처럼 긴 텍스트나 구조화된 버튼-액션 목록 편집. `Esc`로 패널 닫힘, 포커스는 트리거 셀로 복귀.
- **표 키보드 내비게이션** — 방향키로 셀 이동, `Tab`으로 다음 편집 가능 셀 이동 `[ASSUMPTION: 수십~수백 행을 다루는 스프레드시트형 화면 특성상 필요]`.
- **페이지ID 선택기 조작** — WAI-ARIA Combobox 패턴(열기 → `↓`/`↑` 이동 → `Enter` 선택 → `Esc` 닫기, 포커스는 입력 필드 유지).
- **드래그 없음(MVP)** — 메뉴 순서 변경(FR-6)은 위/아래 화살표 버튼으로 대체, 드래그 정렬은 Phase 2 후보 `[ASSUMPTION]`.
- **일괄 작업** — 화면 리스트에서 여러 행 체크박스 선택 후 "일정 일괄 조정" 등 제공 `[ASSUMPTION, 상세는 Architecture 단계]`.

**금지 사항**: 상태를 색상만으로 표시, 페이지ID 자유 텍스트 입력(FR-11 위반), 생성 중 다운로드 허용.

## Accessibility Floor

행동 정의. 시각적 대비는 `DESIGN.md`(WCAG AA 목표) 참조.

- 상태배지는 색+텍스트 라벨을 항상 병행(색맹 사용자 고려).
- 화면 리스트 표는 키보드만으로 완전히 탐색·편집 가능해야 한다 — 방향키로 셀 선택, `Enter`/`F2`로 편집 진입(Interaction Primitives 참조. 더블클릭은 마우스 대안일 뿐 유일한 진입 수단이 아니다).
- 페이지ID 선택기(드롭다운)는 WAI-ARIA Combobox 패턴을 따르며, 스크린리더에서 검색어 입력 시 결과 개수를 `aria-live="polite"`로 안내.
- 사이드패널·다이얼로그·팝오버는 닫힘 시 트리거 요소로 포커스를 반환한다(Component Patterns 각 항목 참조).
- 고급 설정 토글은 네이티브 `<button>` + `aria-expanded`를 사용해 펼침 상태를 스크린리더에 노출한다.
- destructive 토스트(저장 실패 등 데이터 손실 위험 알림)는 `aria-live="assertive"`(또는 `role="alert"`)로 안내해 사용자가 놓치지 않게 한다. 일반 안내 토스트는 `polite`로 충분.
- 포커스 링은 `DESIGN.md`의 `primary` 컬러 기반, 표 셀 포커스 시에도 명확히 보여야 한다.
- 진행 모달(IA 생성 중)은 스크린리더에 "화면 생성 중, N% 완료" 형태로 진행 상태를 안내.
- 밀집한 표 행 안의 인터랙티브 요소(상태배지 확장, 피드백 아이콘, 일괄선택 체크박스)는 최소 24×24px 히트영역을 확보한다(WCAG 2.2 AA 2.5.8).

## Key Flows

### Flow 1 — 대량 화면을 빠르게 정리하는 에이전시 기획자 (민준, PM, 화요일 오후)

1. 민준은 클라이언트 이커머스 프로젝트를 새로 만들고, 컨셉과 8주 일정을 입력한다.
2. 메뉴 12개(회원/상품/장바구니/주문 등)를 빠르게 입력하고 [실행: IA 생성]을 누른다.
3. 진행 모달이 뜨고, 완료되자 화면 리스트로 이동 — 47개 화면이 표로 쭉 나열된다.
4. 그는 표를 훑으며 몇몇 페이지명을 더 구체적으로 수정하고, "장바구니 상품없음" 화면을 클릭해 상세 패널에서 버튼-액션 목록에 "계속 쇼핑하기 → HM1000" 항목을 추가한다. 드롭다운에서 HM1000을 검색해 고른다.
5. **클라이맥스**: 표로 돌아오니 방금 수정한 행에 "수정됨" 중립 배지가 자동으로 붙어 있다. 그는 나머지 46개 화면은 자동생성 그대로 두어도 될지 판단할 수 있다는 확신을 갖고, 상단 "엑셀 다운로드"를 눌러 클라이언트 보고용 산출물을 내려받는다.

실패 시: 저장 실패 → destructive 토스트, 편집 내용은 유지되어 재시도만 하면 됨.

### Flow 2 — 처음 서비스를 만드는 비전문가 창업자 (지현, 1인 창업, 늦은 밤)

1. 지현은 회원가입 후 첫 프로젝트를 만든다. 컨셉 칸에 "동네 반려동물 미용 예약 사이트"라고 쓰고, 전체 일정은 "이번 달 안"으로 잡는다.
2. 메뉴 입력 화면에서 무엇을 적어야 할지 막막해하지만, 예시 placeholder("예: 예약하기 — 원하는 날짜/시간에 미용 예약")를 보고 메뉴 4개를 채운다. 고급 설정은 건드리지 않는다(접힌 채로 둔다).
3. [실행: IA 생성]을 누르니 18개 화면이 생성된다. 화면기능정의와 AI프롬프트가 이미 채워져 있는 걸 보고 안도한다.
4. "예약하기 예약완료" 화면의 AI프롬프트를 읽어보고 👍를 누른다. 다른 화면 하나는 프롬프트가 어색해 보여 직접 한 문장을 덧붙인다.
5. **클라이맥스**: 엑셀을 다운로드해 그대로 Claude Code에 붙여넣는다. 화면이 자신이 상상했던 것과 크게 다르지 않게 만들어지는 걸 보고, 자신도 "기획"을 할 수 있었다는 걸 처음 실감한다.

실패 시: 메뉴를 1개도 안 채운 채 [실행: IA 생성]을 누르려 하면 버튼이 비활성화 상태이고, "메뉴를 1개 이상 추가해 주세요" 안내가 버튼 옆에 뜬다.

## Inspiration & Anti-patterns

- **Lifted from Notion**: 인라인 편집 후 blur 시 자동 저장, 별도 편집/보기 모드 토글 없음.
- **Lifted from Airtable/Google Sheets**: 표 셀 단위 편집, 방향키 내비게이션, 긴 텍스트는 확장 패널에서 편집.
- **Lifted from Linear**: 상태배지 어휘 체계(짧고 명확한 라벨), 깔끔한 좌측 서브내비.
- **Rejected — 마인드맵/캔버스형 IA 시각화**: 화면 수가 많아지면(수십~수백 개) 캔버스보다 표가 스캔·일괄편집에 유리. 시각적 사이트맵 뷰는 Phase 2 보조 뷰로 고려 가능하나 기본 뷰는 표.
- **Rejected — 실시간 협업 커서/프레즌스**: 실시간 공동편집은 명시적 비목표(PRD §2).
- **Rejected — 축하 애니메이션/게이미피케이션**: 이 제품은 업무 산출물 도구다. IA 생성 완료는 토스트 한 줄로 충분, 컨페티 없음.
