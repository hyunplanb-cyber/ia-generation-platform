# 가격 전략 리서치 및 제안

> 용어 설명: 이 문서에서 "구독형(subscription)"은 매달 자동으로 카드에서 청구되는 정기결제, "크레딧형(credit-based)"은 미리 충전한 포인트를 쓸 때마다 차감하는 방식(휴대폰 데이터 충전과 비슷), "프리미엄(freemium)"은 기본 기능은 무료로 열어두고 일부 기능만 유료로 잠그는 방식을 뜻합니다.

## 1. 왜 이 리서치가 필요한가

PRD §10에서 결제 모델은 미확정 상태로 남겨뒀습니다. 그런데 이 제품은 이미 알려진 리스크가 있습니다: **"프로젝트 킥오프 시점에 몰아서 쓰고, 그 이후엔 거의 안 쓰는" 사용 패턴**입니다. Notion이나 Slack처럼 매일 켜놓고 쓰는 도구가 아니라, "프로젝트 시작할 때 한 번 IA를 뽑고, 그 뒤로는 가끔 수정만 하다가 다음 프로젝트 때 다시 쓰는" 도구에 가깝습니다. 이런 사용 패턴에 월정액 구독을 그대로 적용하면, 사용자가 "이번 달만 결제하고 바로 해지"하는 행동이 반복되어 매출이 불안정해질 위험이 큽니다.

## 2. 인접 도구들은 어떻게 가격을 매기는가

### 2-1. IA/사이트맵/와이어프레임 도구 (직접 경쟁군)

| 도구 | 모델 | 가격대 | 비고 |
|---|---|---|---|
| Octopus.do | 프리미엄 + 좌석형 구독 | 무료(1프로젝트) → 월 $7~ | AI 사이트맵 생성 횟수를 무료 티어에서 제한(50회) |
| Relume | 프리미엄 + 좌석형 구독 | 월 $26~38(Starter) | 무료 플랜 없음, 낮은 진입장벽 위해 저가 Starter 운영 |
| Whimsical | 프리미엄 + 좌석형 구독 | 무료 → 월 $10~15/에디터 | AI 기능은 "크레딧"으로 별도 제한(월 20~1000건) — 구독 안에 크레딧을 얹은 하이브리드 |
| FlowMapp | 프리미엄 + 구독 | 무료 → 월 $8.25~ | 신흥국 대상 60% 할인(PPP) 적용 — 지역별 가격 차등 사례 |
| Uizard | 프리미엄 + AI 생성 횟수 제한 | 무료(월 3생성) → 월 $12~39 | "생성"만 크레딧 소모, 수동 편집은 무제한 — 우리 제품과 가장 유사한 과금 단위 |
| UXPilot.ai | 프리미엄 + 크레딧 | 무료(90크레딧) → 월 $12~29 | 초기 크레딧 소진 후 등급별 구독 |

**시사점**: 이 카테고리는 거의 전부 "프리미엄 + 구독"이지만, 실제로 돈을 내는 이유는 좌석 수가 아니라 "AI 생성 횟수" 제한입니다. 즉 구독 요금제 안에 사실상 크레딧형 과금이 숨어 있습니다.

### 2-2. 스펙/코드 생성 도구 (사용 패턴이 더 유사한 비교군)

| 도구 | 모델 | 가격대 | 비고 |
|---|---|---|---|
| v0.dev (Vercel) | 크레딧(토큰) 소모형, 구독은 크레딧 지급 수단 | 무료($5 크레딧) → 월 $20~ | 크레딧은 65일 후 소멸, 추가 구매 가능 |
| bolt.new | 토큰 소모형 | 무료(월 100만 토큰) → 월 $25~ | 프로젝트 복잡도에 비례해 토큰 소모 |
| lovable.dev | 크레딧 소모형 | 무료(일 5크레딧) → 월 $25(100크레딧) | 기능 1건당 크레딧 차감(단순 수정 0.5, 복잡 기능 1.2 등) |
| Specifys.ai | **완전 건별 판매(구독 아님)** | 스펙 1건 무료 → 추가 건당 $4.90 | **가장 가까운 비교 대상.** 프로젝트 시작 때 1회 쓰고 마는 도구라는 걸 인정하고, 아예 "건당 결제"를 기본 모델로 채택 |
| Gamma (프레젠테이션 생성) | 프리미엄 + 크레딧 | 무료(400크레딧, 1회성 지급) → 월 $8~ | 무료 크레딧이 "매달 리필"이 아니라 "가입 시 1회 지급"이라는 점이 중요 — 저빈도 사용자를 겨냥한 설계 |

**시사점**: "한 프로젝트당 한 번 쓰고 끝나는" 성격이 강한 도구일수록(Specifys.ai, v0, bolt, lovable, Gamma) 구독보다 **크레딧/건별 과금**으로 수렴하는 경향이 뚜렷합니다. 이 제품군이 본 플랫폼과 사용 패턴이 가장 비슷합니다.

## 3. 이 제품에 맞는 가격 모델 3안

**A. 순수 구독형 (월정액, 무제한)**
- 장점: 매출 예측이 쉽고 운영이 단순함.
- 단점: 이미 지적된 저빈도 사용 패턴과 정면으로 충돌 — "한 달 결제하고 바로 해지" 이탈이 구조적으로 발생. **비추천.**

**B. 크레딧형 (IA 생성 1회 = 크레딧 1개 소모, 충전식)**
- 장점: "쓴 만큼 낸다"는 인식이 명확해 저빈도 사용자에게 심리적 저항이 적음. Uizard/v0/lovable/Gamma가 검증한 모델.
- 단점: 크레딧 소진 시점을 예측하기 어려워 사용자가 "얼마나 사야 하나" 고민하게 됨(가격 설계 복잡도 증가).

**C. 프로젝트 단위 건별 결제 (Specifys.ai식 — 프로젝트 1개 = 결제 1건)**
- 장점: 이 제품의 핵심 산출물 단위(프로젝트)와 결제 단위가 정확히 일치해 가장 직관적. "한 번 쓰고 끝"이라는 사용 패턴을 억지로 구독에 끼워 맞추지 않음.
- 단점: 재방문(수정/재생성) 시 추가 가치를 어떻게 과금할지 별도 설계가 필요(예: 다운로드 재발급은 무료, 재생성은 유료 등 규칙 필요).

## 4. 추천안

**MVP 이후 첫 유료화 단계에서는 B(크레딧형)와 C(건별 결제)를 결합한 하이브리드**를 추천합니다: 가입 시 소액의 무료 크레딧을 1회 지급(Gamma 방식)하고, 이후에는 "프로젝트/IA 생성" 단위로 크레딧을 소모하는 충전식 크레딧 결제를 기본으로 합니다. 순수 월 구독(A안)은 지금 시점에서는 배제합니다.

이유: (1) PRD §5에 이미 "완료 후 엑셀 다운로드"를 노스스타 지표로 잡아뒀는데, 이는 본질적으로 "건별 완결 이벤트"를 가치 측정 단위로 본다는 뜻이므로 과금 단위도 이와 맞추는 것이 지표-가격 정합성이 높습니다. (2) 저빈도 사용 패턴에서 구독은 해지율만 높이고 신뢰를 깎습니다. (3) 크레딧형은 향후 Phase 2(LLM API 연동으로 원가 발생)로 전환될 때 원가 연동형 과금으로 자연스럽게 확장 가능합니다. 다만 PRD §6에서 결제 자체는 Phase 2 항목이므로, MVP 단계에서는 결제 연동 없이 "무료 사용"으로 가되, 계정/플랜 필드 구조(FR-19)만 이 모델을 염두에 두고 설계해두는 것을 제안합니다.

## 5. 무료 티어 경계 제안

핵심 가치(IA 생성)는 체험할 수 있어야 하되, "끝까지 써서 결과물을 가져가는" 완결 행동(노스스타 지표)에는 약한 장벽을 둡니다.

- **무료로 허용**: 프로젝트 1개, IA 생성 실행 무제한 횟수(초안 확인까지는 자유롭게), 화면 목록 화면 내 열람/편집.
- **유료로 잠금(또는 크레딧 소모)**: (1) 2번째 이후 프로젝트 생성, (2) 엑셀 다운로드(또는 워터마크/일부 컬럼 잠금 — 예: AI프롬프트 컬럼만 마스킹), (3) 화면 수 20개 초과 대형 프로젝트의 전체 다운로드.
- 근거: Octopus.do(무료 1프로젝트+제한 생성횟수), Uizard(무료 3생성), Gamma(무료 1회성 크레딧)의 공통 패턴은 "핵심 기능은 체험하게 하되 결과물 반출 또는 규모 확장에서 막는다"는 것입니다. 이 제품은 "다운로드 = 완결"이라는 지표 설계와도 맞아떨어지므로, 다운로드를 유료 경계로 삼는 것이 자연스럽습니다.

## 6. 한국 시장 참고사항 (가볍게 확인)

국내 프로슈머/소상공인·1인 창업자 대상 도구는 해외 카드 정기결제(자동 갱신)에 대한 심리적 저항이 상대적으로 크고, 토스페이먼츠·나이스페이·KG이니시스 등 국내 PG사를 통한 원화 결제, 그리고 "충전 후 사용" 방식(크레딧/캐시형)에 대한 친숙도가 높다는 것이 업계에서 통상적으로 언급되는 특징입니다(예: 국내 SaaS 구독 전문 플랫폼 Steppay도 일반결제/구독을 분리해 지원). 이번 리서치에서 이를 뒷받침하는 정량 데이터까지는 확보하지 못했으나, 방향성은 위 4~5절의 크레딧/건별 결제 추천과 일치합니다 — 정기 자동결제보다 "충전식 크레딧" 또는 "건별 결제"가 국내 타겟(전문 기획자 프리랜서, 비전문가 창업자)의 결제 저항을 낮출 가능성이 높습니다. 결제 연동 시점(Phase 2)에는 국내 PG사 지원 여부를 별도로 확인할 것을 제안합니다.
