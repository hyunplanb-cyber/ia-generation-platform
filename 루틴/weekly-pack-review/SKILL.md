## ⚠ «만드는 중»인 팩은 절대 보지 않는다 (2026-08-11 사장님 지적)

팩 하나를 만드는 데 **두 회차**가 걸리는데 너는 **매주** 돈다.
A 와 B 사이의 화요일에 만들다 만 팩을 보면 FAIL 이 쏟아지고, 마무리 루틴이 포장을 막는다.

**그래서 폴더가 갈라져 있다. 폴더가 곧 표시다.**

| 자리 | |
|---|---|
| `판매용_템플릿/_판매팩/` | **네가 보는 곳.** 다 된 것만 있다 |
| `판매용_템플릿/_만드는중/` | **열지 마라.** 만들고 있는 것이다 |

`_만드는중/` 에 있는 것은 **세지도 말고, 흠으로 적지도 마라.**
보고에 「만드는 중인 업종이 있습니다 — <이름>」 한 줄만 적는다.

### 예시 사진 묶음 (F 항목, 2026-08-11 추가)

디럭스·프리미엄에만 있다. `검수항목.md` 의 **F1~F6** 을 건다.

```
npx tsx check-zip.mts <업종키>-<등급>       F1·F2·F3 을 잰다
```

- **F1~F3 은 `check-zip` 이 잰다.** 손님이 받는 zip 을 열어 보는 검사라 여기가 제일 세다.
  「태그는 있는데 webp 가 없다」로 8월 10일에 한 번 팔릴 뻔했다.
- **F4 — 사진이 하나도 안 깔린 팩을 조심한다.** 자리표는 있는데 `data-예시` 가 0곳이면
  넣기가 조용히 실패한 것이다. 여행 팩은 자리표 이름이 `data-cap` 에 있어 234곳을
  통째로 놓쳤었다. **자리표 수와 사진 수를 나란히 세어 본다** —
  둘의 차이는 지도·차트 수와 같아야 한다.
- **F6 은 사람이 봐야 한다.** 히어로가 있는 화면을 찍어서 연다. 어두운 사진 한 장이
  밝은 화면에서 구멍처럼 보이는 것은 검사기가 못 잰다.

**사진이 빠졌으면 이 자리에서 다시 끼운다** — 사진 넣기는 팩 고치기가 아니라
**빠진 재료 채우기**라, 화요일에 해도 되는 일이다.

```
npx tsx 이미지-끼우기.mts <팩폴더>
```

⚠ **끼웠어도 zip 은 굽지 마라.** 「절대 지킬 것」 그대로다 — 포장은 마무리 루틴 몫이다.
대신 **CSV 에 「사진 다시 끼움」이라고 적는다.** 마무리가 그걸 보고 zip 을 다시 굽는다.
지금 `check-zip` 을 돌리면 **옛 zip** 을 보고 통과시킨다. 사진이 없는 채로 「성합니다」가 나온다.

⚠ **`build/generate.mjs` 를 돌렸다면 사진이 다 날아갔다.** 완성화면 pages 는 생성물이다.
생성기를 돌렸으면 끼우기를 반드시 다시 돌린다.

### ⭐ 한쪽을 고쳤으면 «다른 등급»도 본다 (2026-08-18 신설)

**한 업종에는 완성화면이 두 벌 있다** — 디럭스(2뎁스)와 프리미엄(3뎁스).
**빌더·CSS·app.js 가 각각 따로다.** 한쪽을 고쳐도 다른 쪽은 그대로 남는다.

2026-08-18 에 실제로 그랬다. 인테리어 디럭스의 견적 마법사를 6단계로 고치고
스펙(`template-data-interior.ts`)까지 고쳤는데, **프리미엄 화면은 3단계에 얼어붙은
채 그대로였다.** 스펙을 고쳐도 완성화면 두 벌이 저절로 따라오지 않는다 —
완성화면은 사람이 만든 것이고 생성기는 제 빌더를 볼 뿐이다.

**그래서 고친 것마다 짝을 확인한다.**

| 고친 곳 | 같이 볼 곳 |
|---|---|
| `<업종>_디럭스/완성화면` | `<업종>_프리미엄/완성화면` |
| `template-data-<업종>.ts` (스펙) | **완성화면 두 벌 다** — 스펙만 고치면 화면은 안 바뀐다 |

⚠ **그대로 복사하지 마라. 두 벌은 어휘가 다르다.** 2026-08-18 에 디럭스 손잡이를
프리미엄에 그대로 옮겼다가 네 군데가 어긋났다 —

- 「포함」이 디럭스는 `.toggle` 버튼, 프리미엄은 `checkbox` → 합계가 0원이 됐다
- 폼 칸이 디럭스는 `.sel`, 프리미엄은 `.input` → 달력 `.sel` 과 부딪치는 것도 한쪽뿐
- `ph()` 인자가 디럭스는 `ph([이름, 가로, 세로], {})`, 프리미엄은 `ph(이름, 크기, 씨앗)`
  → `class="ph [object Object]"` 가 박혀 사진 칸이 납작해졌다
- 「(주말 제외)」 같은 글이 한쪽 화면에만 이미 있어 두 번 찍혔다

**옮긴 뒤에는 반드시 눌러서 재 본다.** `check-사진` 도 `check-반응` 도 이 넷 중
셋을 못 잡았다 — 캡처를 눈으로 보고서야 알았다.

### ⚠ 자리가 «둘»이다. 헷갈리지 마라 (2026-08-18 에 실제로 헷갈렸다)

안 갈 뻔했다. 파일 하나 자리가 틀려서 그렇게 된다.

**쓰고 나서 `ls 검수/` 로 눈으로 확인한다.** `<날짜>_A.csv` 와 `<날짜>_A.done`
두 개가 거기 보여야 끝난 것이다. 캡처 폴더에만 있으면 안 끝난 것이다.

### 6-1. 고친 화면을 목록으로

`판매용_템플릿/_마케팅/검수/<날짜>_A/` 안에 —
고친 화면마다 **전·후 캡처 두 장**과 `요약.md`(화면ID · 무엇이 틀렸나 · 무엇으로 고쳤나).
⚠ **여기에는 캡처와 요약만 넣는다. CSV·done 은 여기가 아니다.**

### 6-2. 내 몫 CSV

**저장소 뿌리의** `검수/<날짜>_A.csv` 에 쓴다 — `판매용_템플릿/` 아래가 아니다.
**`검수기록.csv` 를 직접 건드리지 마라** —
B가 같은 시각에 쓰고 있으면 서로 덮어쓴다. 합치는 것은 마무리 루틴이 한다.

칸: `날짜,업종,묶음,항목번호,무엇이틀렸나,어떻게고쳤나,상태,근거파일`
`상태` = `고침` · `못고침` · `사람확인필요` · `이상없음`

### 6-3. 끝났다는 표시

마지막에 **저장소 뿌리의** `검수/<날짜>_A.done` 을 만든다.
마무리 루틴이 이 파일을 보고 「A가 끝났다」를 안다.
**중간에 실패했으면 이 파일을 만들지 마라.** 그래야 마무리가 반쪽짜리를 올리지 않는다.

```bash
ls 검수/          # ← 마지막에 반드시 이걸로 눈으로 본다
```

## 7단계 — 보고

**「했다」가 아니라 「무엇이 나왔나」.**
본 업종 · 찾은 것 몇 건 · 고친 것 몇 건 · **못 고친 것과 그 까닭** ·
사이트 쪽 문제(고치지 않고 적기) · ⬜ 를 ✅ 로 바꾼 것이 있으면 무엇인지.

## 물어보지 않는다

중간에 승인을 구하지 않고 끝까지 돈다. 위 「절대 지킬 것」만 지킨다.
