## 하는 일

### 1단계 — 새 지시가 «무엇을 요구하는지» 옮겨 적는다

`새지시` 의 파일을 열어 **바뀐 부분을 읽고**, 팩에서 확인할 것으로 바꿔 적는다.

예시:

| 새 지시 | 팩에서 확인할 것 |
| --- | --- |
| `lib/design-presets.ts` 에 「`[hidden]` 은 `!important` 로」 | 각 팩 `base.css` 에 그 줄이 있는가 · 거르기가 실제로 목록을 줄이는가 |
| `lib/export/spec-pack.ts` 7절 추가 | 각 팩 `07_AI빌드_스펙팩.md` 에 그 절이 있는가 |
| `검수항목.md` 에 항목 추가 | 그 항목을 네 몫 업종에 건다 |

⚠ **글자가 있는지만 보지 마라.** 규칙이 들어갔어도 **화면에서 그대로 도는지**는 다른 일이다.
2026-08-19 에 `overflow: auto hidden` 이 규칙에는 있었는데 예시가 `overflow-x: auto` 라
14개 팩 74곳이 전부 옛 방식이었다. **규칙과 예시가 싸우면 만드는 쪽은 예시를 따른다.**

### 2단계 — 네 몫 업종에 걸어 본다 (검수공통 1절 차례대로)

업종 하나가 4등급이다. 등급끼리 파일이 같은 것이 많으니 **묶음으로 본다.**

| 묶음 | 무엇 | 누가 쓰나 |
| --- | --- | --- |
| ① 2뎁스 재료 | 01~05 · 07 스펙팩 | 스탠다드 ＋ 디럭스 |
| ② 3뎁스 재료 | 위의 3뎁스판 | 플러스 ＋ 프리미엄 |
| ③ 디자인프리셋 | 가이드 3 + 레이아웃 2 (md·json 짝) | 4등급 전부 |
| ④ 완성화면(2뎁스) | html · css · js | 디럭스 |
| ⑤ 완성화면(3뎁스) | 〃 | 프리미엄 |

**기계 먼저** — `팩검사.mjs` → 검사기들 → **그다음 눌러 본다.**

⭐ **완성화면(④⑤)에 걸리는 지시라면 반드시 눌러 본다.**
CSS·JS 규칙은 파일에 글자가 있어도 **화면에서 안 도는 일**이 잦다.
새 지시가 걸린 화면을 **묶음마다 한 장씩** 열어 실제로 눌러 확인한다.

### ⭐ 07 스펙팩이 뿌리를 따라왔는가 — 빠뜨리기 쉽다

판매팩의 `07_AI빌드_스펙팩.md` 는 **`lib/export/spec-pack.ts` 로 구워 둔 파일**이다.
코드를 고쳐도 **구워진 파일은 저절로 안 따라온다.**


⚠ **글을 믿지 않는다.** 색·레이아웃 이름은 `완성화면/assets/css/base.css` 의 `--primary` 를

### 3단계 — 안 반영된 것을 고친다

검수공통 2절을 따른다. 특히 **한쪽 등급을 고쳤으면 다른 등급도 본다** —
스탠다드와 디럭스, 플러스와 프리미엄은 핵심 파일이 같다.

지시가 **뿌리에서 온 것이면** 뿌리도 확인한다.
`template-data-<업종>.ts` 가 안 고쳐졌으면 손님 화면도 똑같이 죽는다.
스펙팩 뿌리를 고쳤으면 **CSV 에 「스펙팩 고침」** 이라고 적는다 — 마무리가 다시 굽는다.

#### ⭐⭐ 흠이 나오면 «반드시 브라우저로 그 화면을 열어 본다» (2026-08-21)

**검사기가 짚었다고 팩이 아픈 것이 아니다.** 그날 첫 판 **120건 가운데 절반쯤이
검사기의 헛짚음**이었다. 열어 보지 않고 고치면 **잘 만든 자리를 망가뜨린다.**

| 검사기가 한 말 | 열어 보니 |
| --- | --- |
| 「align-items 를 안 줘서 늘어났습니다」 | `flex:1 1 0%` — 한 줄을 반씩 나눠 쓰라고 **일부러** 적어 둔 것 |
| 「덩어리가 0px 로 맞붙었습니다」 | 안여백 28px 이 있어 글은 28px 아래에서 시작 (40쪽 헛짚음) |
| 「썸네일 키가 607·118px 로 제각각」 | 상품 갤러리의 「큰 것 하나 + 작은 것 넷」 — 층이 다른 것 |
| 「탭이 제 화면을 가리킵니다」 | 지금 켜진 탭 — 제 모습 |

**고칠 것이 팩일 수도 있고 검사기일 수도 있다.** 검사기가 틀렸으면
`check-눈으로.mts` 를 고치고 **왜 틀렸는지 주석으로 남긴다.**
