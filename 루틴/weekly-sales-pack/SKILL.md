## 할 일 — «두 회차에 한 업종을 다 끝내고 판다»

⚠ **작은 칸을 하나씩 하지 않는다.** 예전 규칙이 그랬는데, 그러면 한 업종을 파는 데
여덟 주가 걸린다. 2026-08-10 에 사장님이 바로잡았다 —
**「2주에 한 업종 4등급이 완성되어 홈페이지에 배포되는 것」.**

매주 돌되 **두 번이 한 짝**이다. 지시서 「한 회차에 무엇을 하나」 절에 A·B 가 적혀 있다.

| 회차 | 무엇을 | 끝났을 때 |
|---|---|---|
| **A** | 업종 고르기 → 재료 → 프리셋 → 배선 → 굽기 → **디럭스 완성화면** | 4등급 문서 + 디럭스 화면 |
| **B** | **프리미엄 완성화면** → 검사 → 눌러 보기 → 캡처·영상 → 진열·값 → **머지·배포** | **홈페이지에서 팔린다** |

**시작할 때 먼저 정한다 — 이번이 A 인가 B 인가.**
지시서 「지금 어디까지 왔나」에서 `[ ]` 가 남은 업종을 보고 판단한다.
A 가 `[~]` 로 남아 있으면 **A 를 마저 끝내는 것이 이번 회차**다.

한 회차 안에서는 **끝까지 간다.** 중간에 멈추지 않는다.
정말 시간이 모자라면 거기까지 하고 `[~]` 로 표시한 뒤 어디까지 했는지 적는다.
**다만 대충 만들어 채우지는 않는다** — 검사기가 어차피 잡고, 파는 물건이다.

## 배포는 B 회차가 한다 (2026-08-10 사장님 결정)

전에는 「main 에 밀지 않는다, 진열은 사람이 한다」였다. **바뀌었다.**
B 회차는 `main` 에 머지하고 밀어 **실서버에 배포**하고, **실서버를 눈으로 확인**한다.

**그래서 브레이크가 둘뿐이다 — 검사기 4개 FAIL 0, 그리고 `check-zip` FAIL 0.**
FAIL 이 남았으면 **배포하지 않고 브랜치에 둔 채 보고한다.**
「거의 다 됐으니 올리자」는 없다. 사람이 안 보는 물건이 팔리는 것이 가장 나쁘다.

```bash
npx tsx package-template.mts --내보내기 <업종키>   # «만드는 중» → «다 된 것» 으로 옮기고
npx tsx package-template.mts --zip                # 판매 zip 을 다시 굽고
npx tsx check-zip.mts                             # 손님이 받는 그 파일을 열어 본다
```

## 만드는 중인 팩은 «다른 폴더»에 둔다 (2026-08-11 사장님 지적)

팩 하나를 만드는 데 **두 회차**가 걸리는데, **검수 루틴은 매주 화요일**에 돈다.
그러면 A 와 B 사이의 화요일에 **만들다 만 팩이 검수에 걸려** FAIL 이 쏟아진다.

**그래서 폴더를 가른다. 폴더가 곧 표시다.**

| 자리 | 누가 보나 |
|---|---|
| `판매용_템플릿/_판매팩/` | 검수 · zip · 진열 — **다 된 것만** |
| `판매용_템플릿/_만드는중/` | **아무도 안 본다.** 만드는 동안 여기 둔다 |

- **A 회차 끝** — `npx tsx package-template.mts --만드는중 <업종키>` 로 «만드는중» 에 만든다
- **B 회차 시작** — 거기서 이어서 프리미엄 화면을 만든다
  (`팩재료-캡처영상.mts` · `팩재료-앱스토어.mts` 는 두 자리를 다 찾으니 그대로 쓰면 된다)
- **B 회차, 검사 다 통과한 뒤** — `--내보내기 <업종키>` 로 «다 된 것» 으로 옮기고 zip 을 굽는다

⚠ **검사가 남았는데 먼저 내보내지 마라.** 내보내는 순간 화요일 검수가 그것을 본다.

⚠ **`check-zip` 을 건너뛰지 않는다.** 앞의 검사기 넷은 만드는 «재료»만 본다 —
스펙·가이드·화면. **담다가 빠진 것은 이것만 잡는다.**
2026-08-10 에 뷰티샵 디럭스가 `완성화면/index.html` 없이 엿새를 팔렸는데
검사기 넷이 다 통과시키고 있었다. 화면 49장이 있어도 들어갈 문이 없으면 못 쓴다.

배포 뒤에는 팩 목록 수·`/packages/<키>` 응답·갈래 숫자를 **실제로 열어 보고** 보고에 적는다.
확인 못 했으면 배포는 끝난 것이 아니다.

## 업종은 «조사해서» 고른다 — 사람에게 묻지 않는다

이건 자동화다. 「무엇을 만들까요」를 사용자에게 묻지 않는다.
지시서의 큐가 비었거나 다음 업종이 안 정해져 있으면, **직접 조사해서 정한다.**
지시서의 「업종은 조사해서 고른다」 절에 네 관문이 있다.

① 지금 뜨는 업종·서비스를 웹 검색으로 조사한다 (시장성). 근거 URL 을 지시서에 적는다.
② 주제나 업종이 한 문장으로 말해지는가.
③ **우리 손님이 실제로 적어 본 말을 본다** — 이게 가장 가까운 수요다.
   `npx tsx 조사-생성키워드.mts` 를 돌린다. 우리 앱에 들어와 컨셉을 적었는데
   우리가 못 만들어 준 것들이 나온다. 「인테리어」처럼.
   표본이 적으면 스크립트가 「쓸 수 없습니다」라고 스스로 말한다. 그때는 ①만으로 고른다.
④ 카페24·아임웹으로 «안 되는가». 이게 가장 자주 걸린다. 실제로 되는지 찾아본다.

③에 많이 나왔다고 그대로 만들지 않는다. **네 관문을 다 지나야 한다.**

## 완성화면을 만들었으면 «예시 사진»을 끼운다 (2026-08-11 사장님 결정)

디럭스·프리미엄을 만들었으면 **검사보다 «먼저»** 이것을 한다. 순서가 중요하다 —
사진이 들어간 뒤에 검사하고 캡처해야 손님이 볼 화면을 그대로 재고 그대로 찍는다.

```
npx tsx 이미지-끼우기.mts <팩폴더>        예) 여행_디럭스
```

**왜 하나.** 회색 네모는 아무리 뼈대가 좋아도 눈이 「아직 안 만들어진 것」으로 읽는다.
사진이 들어가면 같은 화면이 「다 만들어진 것」이 된다. 우리가 파는 것은 «완성돼 보이는
화면»이다. 사진마다 「예시 이미지 · 바꿔 넣으세요」가 박혀 있어서 내용이 딱 맞지
않아도 손해가 없다 — 사진의 일은 진짜인 척하는 것이 아니라 **자리가 어떻게 생겼는지
보여 주는 것**이다.

- 사진은 `판매용_템플릿/_이미지/<업종>/` 에 있다. 없으면 **거기서 멈추고 보고한다.**
  아무 사진이나 갖다 쓰지 마라. 라이선스가 분명한 것만 쓴다(픽사베이·언스플래시).
  게티는 유료다. 새로 받은 원본은 `_원본/<업종>/` 에 두고
  `npx tsx 이미지-예시만들기.mts <업종>` 으로 워터마크를 박는다.
- 어느 사진이 어느 역할인지는 `_이미지/<업종>/배치.csv` 가 정한다(매장·인물·결과·시술·후기).
  없으면 스크립트가 전부 「시술」로 놓고 만들어 준다 — **그대로 두지 말고 사진을 눈으로
  보고 고친다.** 대조표(contact sheet)를 만들어 Read 로 열어 보면 빠르다.
- 팩 이름과 사진 폴더 이름이 다를 수 있다. 공동구매는 `제품` 폴더를 쓴다
  (`이미지-끼우기.mts` 의 `사진폴더별명`).
- 끼우면 `완성화면/사진바꾸기.csv` 가 같이 나온다. 손님이 사진을 바꿀 때 보는 표다.
- 마음에 안 들면 `--빼기`. 자리표는 안 건드리고 얹기만 했으니 회색 네모로 그대로 돌아온다.

⚠ **`build/generate.mjs` 를 다시 돌리면 사진이 통째로 날아간다.** 완성화면 pages 는
생성물이라 다시 구우면 덮어써진다. 2026-08-11 에 이걸 몰라서 192장을 잃었다.
**생성기를 돌렸으면 끼우기를 다시 돌린다.**

⚠ **끼운 뒤 반드시 이것을 돌린다.**

```
npx tsx check-사진.mts <팩폴더>
```

실제로 그려서 **「사진이 제 칸 안에 있나」**를 잰다.
2026-08-11 에 매칭 팩만 `.ph` 에 `position:relative` 가 없어서 **64px 프로필 사진이
페이지를 통째로 덮었다.** 히어로가 아래 카드로 흘러내리고, 고수 목록은 빈 네모가 되고,
분야 목록은 데스크톱에서 통째로 안 보였다. 증상은 넷인데 뿌리는 하나였다.
**`check-design` 도 `check-zip` 도 못 잡았다** — 둘 다 «글자»를 보지 «그려진 자리»를 안 본다.

⚠ **손님이 «직접 올릴» 자리(짐 사진·첨부 사진·작업 사진)에 엉뚱한 사진을 넣지 않는다.**
맞는 사진이 없으면 `_이미지/<업종>/배치.csv` 에 `(비움),시술` 처럼 적어 **자리표로 둔다.**
자리표는 「이미지 영역 (짐 사진 · 권장 1200×900)」이라고 **맞는 말**을 하는데,
엉뚱한 사진은 **틀린 말**을 한다. **빈 것보다 틀린 것이 나쁘다.**

⚠ **지도·차트 자리에는 사진이 들어가면 안 된다.** 스크립트가 `ph-map` 클래스와
「지도·차트·그래프·추이」라는 말을 보고 건너뛴다. 여섯 팩에서 35곳이 그랬다.
끼운 뒤 채운 수가 `자리표 수 - 지도·차트 수` 와 맞는지 본다.

   12개월 할부로 결제했는데 완료 화면은 「일시불」이었다. **눈으로는 전부 멀쩡했다.**
   열어 보는 것과 눌러 보는 것은 다른 일이다.

   `.claude/launch.json` 의 **팩전체**(`node _작업/팩서버.mjs 4200`)를 띄우고
   `http://localhost:4200/<팩이름>/완성화면/` 에서 **주소창 대신 화면 안의 링크를 눌러** 다닌다.
   주소로 건너뛰면 화면이 서로 이어지는지가 안 보인다.

   **세 가지를 본다.**

   | 무엇 | 어떻게 |
   | --- | --- |
   | **화면연결·레이아웃·UI** | 눈으로 직접 본다. 무너진 곳·겹친 곳·잘린 글·화면 밖으로 나간 것. 화면 목록에서 시작해 묶음마다 대표 화면을 연다 |
   | **UX** | **직접 눌러 본다** — 뒤로가기 · 버튼 · 탭 · 필터 · 썸네일 · 배너 · 쪽 번호 · 정렬. 누르면 화면이 바뀌거나, 값이 바뀌거나, 안내가 떠야 한다 |
   | **데이터 연동** | 같은 값이 여러 화면에 나오면 **서로 맞는지** 본다. 앞 화면에서 고른 것이 뒤 화면에 그대로 넘어가는지, 합계가 항목의 합과 맞는지 |

   **먼저 기계에 맡긴다** — `node _작업/팩검사.mjs <팩이름>`
   끊어진 링크 · 없는 그림 · 외톨이 쪽 · 요일이 달력과 맞는지 · 프리셋 이름이 실제 색과 맞는지 ·
   두 등급이 같은 레이아웃인지를 센다. **여기서 걸리는 것이 0이 된 뒤에 눌러 본다.**
   사람 눈으로 요일을 세지 마라 — 2026-08-19 에 49건이 그렇게 숨어 있었다.

   **자주 나오는 자리** (LMS 두 팩에서 실제로 나온 것들)
   - 거르는 단추가 **켜짐 표시만 바뀌고 목록은 그대로** — 눌러서 개수가 실제로 줄어야 한다
   - 같은 무리의 단추가 **동시에 켜져 있음** — 「디자인」과 「전체 보기」가 같이 켜지면 안 된다
   - 걸러서 2개가 남았는데 **쪽 번호는 1~5 그대로**
   - 카드 위 찜 하트가 **사진에 덮여** 안 눌림 (`document.elementFromPoint` 로 그 자리 맨 위를 확인)
   - 앞 화면에서 고른 값(할부·수량·옵션)이 **다음 화면으로 안 넘어감**
   - 같은 값이 화면마다 다름 — 진도가 한 곳은 67%, 다른 곳은 40%
   - 「이번 주」·「D-3」 같은 말이 **실제 날짜와 안 맞음**
   - 비로그인 화면인데 **헤더는 로그인 상태**

   **찾았으면 그 자리에서 고친다.** 기록만 남기고 넘어가지 않는다.
   고친 뒤에는 검사기 4개와 `팩검사.mjs` 를 다시 돌리고, 고친 화면을 다시 눌러 본다.

   **숫자로 남긴다** — 「눌러 본 화면 N개 · 안 눌리는 단추 0개 · 안 걸러지는 필터 0개 ·
   뒤로가기 어긋남 0개 · 화면끼리 안 맞는 숫자 0개 · 고친 것 N건」.
   숫자를 못 적으면 아직 확인한 것이 아니다.

   ⛔ **숫자 하나를 고치면 그 숫자로 계산되는 값을 «전부» 따라가라.**
   2026-08-19 에 차시 수를 30에서 18로 고치면서 진도·남은 차시를 안 고쳐서,
   같은 강의가 화면마다 67% 와 40% 로 갈렸다. 반쪽만 고치면 안 고친 것보다 나쁘다.

3. **캡처·영상 재료를 뽑는다. 건너뛰지 않는다.**

   ```
   npx tsx 팩재료-캡처영상.mts <업종키>      예) rental
   ```

   `build-all.mts` 6번에 들어 있어서 `npx tsx build-all.mts <업종키>` 로 구우면 저절로 돈다.
   업종 없이 전체를 구우면 **안 뽑히고 「건너뜁니다」라고 나온다** — 그때는 위 명령을 따로 돌린다.

   나오는 것: 캡처 PNG(가로·세로) · mp4 두 벌(16x9 · 4x5) · `00_자동넘김.html`.
   자세한 것은 지시서의 「화면을 만드는 김에 캡처와 영상 재료를 같이 뽑는다」 절에 있다.

   **여기까지가 네 몫이다 — 릴스 폴더에 «재료»를 넣어 두는 것.**
   자막·고양이·영상틀·길이 맞추기·유튜브 올리기는 **SNS 루틴**(`weekly-sns-content`)이 한다.
   편집을 시작하지 마라. 두 루틴이 같은 영상을 두 번 만들게 된다.
   4:5 가 폰에서 글자가 작은 것도 흠이 아니라 재료의 성질이다 — 확대 컷은 저쪽이 얹는다.

   ⚠ **뽑은 캡처를 반드시 열어 본다.** 이미지를 Read 로 열어 눈으로 확인한다.
   2026-08-10 에 여기서 렌탈 홈 화면의 결함 두 개를 찾았다 — 검사기 넷이 다 통과시킨 화면이었다.
   검사기들은 「어디에 그려졌나」를 재지 않는다. 실제로 그려 보는 것은 캡처뿐이다.
   **홍보물을 만드는 일이 곧 마지막 검사다.** 안 열어 보면 결함을 홍보하게 된다.
   이상한 것을 찾으면 고치고, 고쳤으면 검사기 4개를 다시 돌리고 재료도 다시 뽑는다.

## ⭐ 팩을 다 만들면 «두 갈래 검수»를 확인한다 (2026-08-21 사장님 지시)

### ① 스펙팩에 두 갈래 지시문이 실렸는지 — 모든 등급

```bash
grep -c "검수는 «두 갈래»입니다" 판매용_템플릿/_판매팩/<팩>/07_AI빌드_스펙팩.md          # 1
grep -c "기계가 보는 검수 — 파일만 보고 재기" 판매용_템플릿/_판매팩/<팩>/07_AI빌드_스펙팩.md  # 1
```

⛔ **0 이면 스펙팩이 묵은 것이다.** 코드를 고쳐도 «찍혀 있는 파일»은 안 바뀐다.
`build-template.mts` · `build-template-deep.mts` 를 다시 돌리고 **zip 까지 다시 굽는다**(B9).

⛔⛔ **다시 굽기 전에 `build-all.mts` 의 업종 목록부터 본다** (2026-08-21).
그 배열에 **인테리어가 빠져 있었다.** 팩은 일곱인데 여섯만 적혀 있어서, 아무리 다시
구워도 인테리어 네 등급은 **옛것 그대로**였다 — **아무 소리도 안 났다.**
스펙팩 28칸 중 24칸에만 새 글이 실려서야 들통났다.

```bash
grep -n "const 업종들" build-all.mts     # 일곱 업종이 다 있나 — 없으면 넣는다

# 다시 구운 뒤 — 이번에 넣은 글의 한 조각으로 «센다»
grep -rl "<넣은 글 한 조각>" 판매용_템플릿/_판매팩/*/07_AI빌드_스펙팩.md | wc -l   # 28 이어야 한다
```

⛔ 「됐다」로 끝내지 않는다. **숫자를 보지 않으면 모른다.**

### ③ 포장 전에 «우리 점검용 파일이 섞였는지» 본다 (2026-08-21)

```bash
node _작업/팩검사.mjs <팩>     # 끊어진 링크 · 없는 그림 · 빈 링크 · 외톨이
npx tsx check-zip.mts         # 우리 것이 섞여 나갔는지 (B4)
```

⛔ **2026-08-21 에 실제로 겪었다.** 우리가 화면을 훑어보려고 만든 `build/qa.html` 이
**네 팩(뷰티샵 둘·여행 둘)의 zip 에 그대로 들어가 팔리고 있었다.**
손님 것이 아닌데 손님이 받았다. `check-zip` 이 이제 잡는다.

⚠ **빈 링크는 «갈래마다 다르게» 고친다.** 쪽 번호 · 이미 꺼진 버튼 · 끌어 옮기는 줄 ·
갈 화면이 없는 것이 섞여 있다. 검수공통 2절 「고칠 때」를 그대로 따른다.
고친 뒤 **태그 짝(`<a>`·`<button>`·`<span>`)을 세서 어긋난 화면 0장**을 확인한다.

### ② 디럭스·프리미엄은 «화면을 완성한 뒤» 두 갈래를 다 검수한다

완성화면(HTML)이 들어가는 등급은 **디럭스·프리미엄** 둘이다.
스탠다드·플러스는 문서만 나가므로 ②만 본다.

| 갈래 | 무엇으로 | 언제 |
|---|---|---|
| **① 사람처럼 보는 검수** — 15개 | `npx tsx check-눈으로.mts <팩> --전부` | 화면을 다 만들고, 예시 사진을 끼운 «뒤» |
| **② 기계가 보는 검수** — 27개 | `node _작업/팩검사.mjs <팩>` · `check-zip` · `check-zip날짜` · `check-겉표지` | 포장하기 직전 |

⛔ **한 갈래만 하면 반드시 새어 나간다.**
보기에 멀쩡한데 링크가 죽어 있거나, 파일은 다 맞는데 화면이 무너져 있다.

### ⭐⭐ 흠이 나오면 «반드시 브라우저로 그 화면을 열어 본다» (2026-08-21)

**검사기가 짚었다고 팩이 아픈 것이 아니다.** 그날 첫 판 **120건 가운데 절반쯤이
검사기의 헛짚음**이었다. 열어 보지 않고 고치면 **잘 만든 자리를 망가뜨린다.**

| 검사기가 한 말 | 열어 보니 |
| --- | --- |
| 「align-items 를 안 줘서 늘어났습니다」 | `flex:1 1 0%` — 한 줄을 반씩 나눠 쓰라고 **일부러** 적어 둔 것 |
| 「덩어리가 0px 로 맞붙었습니다」 | 안여백 28px 이 있어 글은 28px 아래에서 시작 (40쪽 헛짚음) |
| 「썸네일 키가 607·118px 로 제각각」 | 상품 갤러리의 「큰 것 하나 + 작은 것 넷」 — 층이 다른 것 |

**고칠 것이 팩일 수도 있고 검사기일 수도 있다.** 검사기가 틀렸으면
`check-눈으로.mts` 를 고치고 **왜 틀렸는지 주석으로 남긴다.**

### ⛔ 공통 CSS 를 고칠 때 — 없는 변수를 쓰면 «그 줄이 통째로 버려진다» (2026-08-21)

팩이 두 세대라 같은 뜻의 값이 이름이 다르다 — 섹션 사이는 `--sec-gap`(새) / `--sp-sec`(옛),
덩어리 사이는 `--sp-block`(있는 팩만) / 없으면 `--s4`.
한쪽만 적었더니 옛 팩 다섯 벌에서 **아무 소리 없이** 안 먹었다.
CSS 는 없는 변수를 만나면 경고가 아니라 **그 줄을 버린다.**
반드시 겹쳐 쓴다 — `var(새, var(옛, 기본값))`.

⚠ **`check-눈으로` 는 사진을 끼운 뒤에 돌린다.** 자리표만 있을 때 재면
썸네일 크기(H10)·배지 위치(H15)가 실제와 다르게 나온다.
